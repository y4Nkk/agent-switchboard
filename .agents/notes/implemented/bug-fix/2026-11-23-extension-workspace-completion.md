# Agent Note: 扩展工作区返回与更新确认

Status: implemented

## Problem

仓库管理退出沿用了仓库读写禁用条件。分类更新检查的结果只出现在对应行，MCP 更新可能被搜索隐藏。目录版本关联复用了连接部署流程，当前定义与部署修订也共用同一个修订号。市场保存后原配置按钮消失，子页缺少返回焦点。

## Decision

仓库管理以正在提交的仓库写入限制返回，读取状态只约束依赖列表的操作。库工具栏根据当前修订的 MCP 检查结果提供汇总和逐项入口，用户进入条目时保留现有筛选。目录版本关联只提交来源元信息。扩展库在保存定义时根据 MCP 名称与连接推导配置最近变化的修订号，仅当它早于定义修订时保存 `mcpConfigRevision`。部署状态比较原生条目和基线，并接受配置最近变化到当前定义之间的已部署修订。子页优先把焦点还给发起控件，市场保存后发起按钮消失时返回「市场」控件。

## Alternatives considered

让关联继续走部署计划可以沿用现有版本指示，但会纳入已保存的待部署配置。批量抬升绑定的已部署修订可以维持结果显示，却会改写部署历史事实并引入多文件提交。

清空当前搜索可以显示隐藏的更新项，但会打断在库内进行的查找，也无法直接定位多个待处理条目。

## Consequences

仓库读取失败后可以切换来源。对客户端的原生配置改动仍按基线识别，目录记录更新保留原部署记录，滞后的部署仍提示待应用。定义修订继续用于编辑并发检查和候选复核。
