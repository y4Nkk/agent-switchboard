# Agent Note: 供应商行操作统一按悬浮显示

Status: implemented

## Problem

供应商列表通过输入能力媒体查询决定是否隐藏按钮，设备报告的触摸、悬浮或指针精度会让空闲行整表常显。仅删除粗指针排除条件仍保留了这条常显路径，没有满足用户明确要求的“按钮是鼠标悬浮时才显示”。此外，`:focus-within` 会让鼠标点击后的焦点继续保持操作可见，移开鼠标也不收起。

## Decision

`base/provider-list.css` 直接根据行的实际交互控制 `.asb-row-action`：空闲时隐藏，悬浮当前行时显示；键盘可见焦点或已有拖动状态保留操作可达。键盘例外使用 `:has(:focus-visible)`，普通鼠标按钮焦点不再使操作常驻。删除整个输入能力媒体查询，不保留触摸常显、主指针分支、兼容选择器、开关或事件监听。

Codex 和 Claude 的官方与第三方档案共用 `ProviderRowShell`。排序手柄、动作轨和 `UsageSummaryView` 的刷新按钮继续显式声明 `.asb-row-action`，共享一处显隐规则，不匹配摘要内部结构。保留布局占位、Tab 顺序、节点级透明度过渡、手柄按压反馈和减少动态效果偏好。名称、模型、地址、已应用、用量与错误始终显示，详情面板内操作不受影响。

## Alternatives considered

- 按输入能力常显或收起：最强理由是纯触摸设备可以直接发现按钮，混合设备也可按主指针减少噪声；但无论检测任一粗指针还是只检测主指针，都使环境报告决定按钮常显，与用户指定的统一悬浮行为冲突，因此删除整条能力分支。
- 保留 `:focus-within`：最强理由是任何焦点都能保持按钮可达，选择器简单；但鼠标点击也会留下焦点，导致移开鼠标后按钮仍显示，因此使用原生 `:focus-visible` 保留键盘操作。
- 隐藏时移除布局与焦点：最强理由是回收按钮占位；但模型与地址会在悬浮时移动，Tab 也无法进入操作，因此只改变透明度与指针命中。

## Verification

- 静态核对 `base/provider-list.css`：唯一隐藏选择器无媒体查询，例外只有 `:hover`、`:has(:focus-visible)` 和 `.is-dragging`，不再由 `:focus-within` 保持操作可见。
- 源码核对 `ProviderRowShell`、`ProviderList`、`CodexProviderRows` 和 `UsageSummaryView`：两个客户端继续共用显式动作标记，未新增状态、监听、依赖或第二套按钮，模型与地址布局保留。
- 设计与笔记归属同步，临时主指针方案无残留。笔记结构和差异检查仅提供静态证据，不等同于桌面交互验收。

## Consequences

按钮显隐由当前行交互直接决定，环境能力报告不再让全列表常显；鼠标点击后的普通按钮焦点也不锁住显示。保留占位避免模型与地址跳动，保留可见键盘焦点与拖动保证已有操作可达。代价是按钮需要悬浮才可发现，触摸端也不再有默认常显的特殊待遇，需由平台原生交互显现当前行；本次不承诺未经验收的触摸模拟悬浮行为。只有用户明确改变触摸交互范围时才重访，不预留兼容层。按项目限制未运行编译、类型检查或自动化测试，真实桌面交互需人工验收。
