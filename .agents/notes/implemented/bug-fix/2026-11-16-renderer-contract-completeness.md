# Agent Note: 前后端显示契约完整性与页面故障隔离

Status: implemented

## Problem

运行日志的合法 `sessionRangeProcessed` 事件遗漏于前端类型和标签映射，TypeScript 仍然自洽，直到真实事件进入日志首屏才触发渲染异常。Claude 子代理缓存时长选项也缺少双语词条；请求诊断的 `retryAfter` 已由后端返回，但没有进入前端类型与详情。整个 AppWorkspace 共用一个不可重置的错误边界，使一个页面的渲染错误阻断其他页面。

## Decision

运行日志动作与级别的前端类型从实际显示映射推导，页面、筛选和记录级别共用这份映射，删除手写重复联合类型与级别清单。补齐子代理缓存时长词条和请求诊断的可空 `retryAfter`；详情按上游原始 Retry-After 值展示，不推测秒数、截止时间或自动重试。

Rust 单元测试从 Serde 的当前枚举元信息读取并重新序列化运行日志动作与级别，调用真实设置目录投影取得所有标签、分组、选项与路径文案，并序列化真实请求诊断。测试通过标准输入交给 Node 消费真实前端映射、文案和类型约束的诊断夹具，严格比较当前值、完整字段与无参数双语词条。共用 CI 的 Rust 测试自动执行这条链，tsconfig 同时纳入消费脚本和诊断夹具；不维护手写 Rust 枚举副本、不解析 Rust 源码、不提交生成快照或新增运行时 IPC。

页面错误边界分别属于七个工作区、设置分区、诊断页签及用量分区。切出故障页面后重新进入或显式点击重试时只重建失败子树，健康边界不变更子树身份。页面持有的未保存编辑可能丢失，其他页面的状态继续由原组件持有；原生任务与全局操作继续由原所有者持有。删除原全工作区错误边界与强制 WebView 重载动作，不引入全局草稿仓库、自动重复重试或异常原文持久化。

## Alternatives considered

- 只补缺失的两行映射和词条改动最少；但前端联合类型与映射同时遗漏时仍会再次通过编译，因此需要对照 Rust 实际当前契约。
- 用正则扫描 Rust 源码无需编译、适合定位问题；但宏、Serde 重命名及 DTO 投影会使源码拼写与实际返回值不同，因此不作为持续门禁。
- 把全部 IPC 切换为新的代码生成或运行时校验框架可覆盖更多接口；但超出已确认缺陷的边界并增加依赖与第二套生产格式，不采用。
- 仅在导航变化时重置一个全局边界最易实现；但任何子页报错仍会卸载所有健康页面，因此使用局部边界，保留原挂载与导航所有者。

## Regression coverage

- `commands/client_settings/frontend_contract_tests.rs` 将真实原生值传给 `tests/frontend-contract-consumer.ts`：遗漏或多出日志动作、级别、筛选值，丢失目录双语标签或改变诊断字段均使断言失败。
- `tests/fixtures/provider-diagnostic.ts` 受前端类型约束；与真实 Rust 序列化对象逐字段、逐值比较，不把自行构造的前端类型当作后端证据。
- `scripts/test-page-recovery-ui.mjs` 与隔离夹具使用真实 React、PageErrorBoundary 及 ProviderDiagnosticDetails：覆盖隐藏页报错、顶层及嵌套导航、持续故障重试、显式成功重试、重新进入恢复和健康草稿保留，并核对文档身份未重载。
- 同一浏览器脚本覆盖 Retry-After 的秒数、零、HTTP 日期、缺失与双语标签；原生命令和外部网络请求被禁止。脚本沿用既有 ASB_PLAYWRIGHT_MODULE 浏览器工具选择机制，结果写入独立 `.tmp/page-recovery-*` 目录，仅在用户要求时手动执行。

## Consequences

前端日志类型与显示值不再各自维护，设置目录的真实产出进入持续检查，故障页面也不会卸载健康兄弟子树。代价是跨语言测试需要同一环境有 Cargo 与 Node，共用 CI 通过 ASB_TEST_NODE 提供精确路径；当前检查覆盖日志、设置目录及请求诊断，不声称替代所有 IPC 的契约检查。错误边界只能隔离后代的渲染生命周期错误，事件与异步失败继续由原有命令和读取状态处理；失败子树内已经丢失的本地草稿不能自动恢复。
