# Agent Note: 供应商诊断的档案解析与修复写入边界

Status: implemented

## Problem

供应商诊断的联网请求只查通用档案，遗漏 Codex 专用档案。修复复用完整切换投影，把存储中的公共设置与片段重新写入真实客户端。路由诊断先要求写入投影成功，网关停止或恢复阻塞时无法报告监听、端口和路由事实，未激活档案也被误报。

## Decision

配置存储提供一个类型化已保存档案解析入口，区分 Codex 专用档案和通用档案，保留原始文件修订。诊断、切换计划、活动状态和联网请求消费这个入口，存储错误不能降级成另一种格式的查找。Codex 请求默认模型按档案现有模型映射解析到上游名称。xAI 请求复用现有账号解析与刷新，准备修订包含账号身份；同账号刷新读取新凭据，改绑账号拒绝旧准备。供应商核心契约拥有固定 xAI 上游地址，诊断、请求与网关共用，删除原网关私有地址解析。

SwitchPlan 显式拥有写入范围。供应商修复只投影 Provider 所有的目录字段、认证、模型目录及供应商片段；Client 所有的标量、公共片段和未声明配置保留实时值。预览与执行消费同一范围，禁止过滤显示差异来掩盖实际写入。Claude 供应商片段不能覆盖实时公共片段声明的叶子。Codex 渲染的 set_path 更新已存在的受管标量时就地替换值、保留键的 decor（2026-10-13 本地 CI 修复），实时文件里受管键上方的注释在切换与修复渲染中不再丢失。

路由检查先判断是否激活，再从档案要求、当前客户端入口和 GatewayObservation 判断直连或网关状态，独立于写入计划。状态模块在地址脱敏前提取网关端口，内部字段不进入序列化；网关就绪还要求客户端入口、实际监听与配置端口一致。官方 Codex 接管通过已有活动路由回放状态，不再当作第三方专用档案读取，也不为状态回放刷新账号或要求监听成功。配置检查仍报告不能生成修复计划的具体原因。沿用确认、备份、快照冲突拒绝与撤回执行器，不创建第二条真实配置写入路径。

诊断报告由共享 Table 展示检查项、状态、结论与处理建议，状态保留文字和语义颜色；窄窗口只在报告区域横向滚动，长结论完整换行。修复与撤回继续消费唯一 DiffView，DiffView 内部使用共享 Table 对齐配置项、变更前和变更后，切换、备份、客户端配置与扩展的直接消费者同步使用这一结构。差异值在所属列内换行，不引入横向滚动；无变更时不显示空表头。单次连接结果、说明、表单和配置原文保留原有语义，不为表格布局复制业务状态。

## Related decisions

[当前客户端配置契约](../feature/2026-10-12-current-client-configuration-contract.md)部分重叠：目录与片段所有权继续有效，本篇补充供应商修复的范围限制。其他命中的[供应商存储修复](../feature/2026-09-23-provider-store-repair.md)面向应用存储损坏，目标无关，保持原决策；没有需要取代或归档的同主题笔记。

[跨供应商路由一致性](2026-10-23-cross-provider-route-consistency.md)补充活动故障转移候选的保存与恢复、会话工具历史隔离及 HTTP/WebSocket 共享响应还原；本篇的诊断与真实配置写入边界保持有效。

## Alternatives considered

- 前端把已保存 Codex 档案转换成草稿请求，可以复用现有接口；但失去文件修订约束并扩大凭据流转，拒绝。
- 完整切换后过滤预览中的公共设置，改动较少；但实际执行仍修改公共值，无法兑现修复边界，拒绝。
- 仅把未激活判断移到投影前，可以消除一类误报；但网关故障仍遮蔽结构化事实，拒绝。
- 只为诊断弹窗制作差异表格可以缩小界面影响；但修复、撤回和其他写入预览会出现两个差异渲染契约，因此改由既有 DiffView 统一消费 Table。
- 将所有事实和表单都改成表格能保持表面一致；但单次请求状态与编辑控件不属于逐项对照数据，因此仅把检查记录和键级差异接入表格。

## Regression coverage

- 已保存 Codex 直连与网关档案可准备请求，默认模型映射正确，档案变化后拒绝旧请求。
- Codex 与 Claude 修复只产生供应商差异，保留实时公共标量、公共片段和无关内容；片段所有权冲突明确拒绝。
- 未激活档案无活动路由为正常未知状态；网关停止、端口冲突和恢复阻塞保留具体事实。
- 回归测试源代码覆盖专用档案与官方档案区分、档案修订及账号身份变化、两端供应商写入范围、公共片段缺失叶子和声明冲突、备份撤回、外部修改拒绝、网关故障与脱敏后的端口事实。

## Consequences

修复范围从核心计划贯穿预览与执行，公共设置无需复制或写后补偿；损坏的档案和冲突的所有权声明仍明确失败。Codex 退役的客户端设置清理归到客户端覆盖层，供应商修复和端口改写不再隐式清理该字段；完整公共设置应用仍删除退役键并在预览中列出。没有增加持久格式、兼容读取、过渡开关或第二条写入路径。

检查记录与键级差异共用全局表格的表头、间距和边框契约，删除旧诊断网格及逐项差异卡片样式。三列差异表在窄内容区有更多换行，换来稳定的前后列对齐；移除仍明确显示文字，不依赖红绿色。客户端恢复预览同步删除旧列表布局覆盖，采用同一表格。

备份历史的吸顶表头规则只匹配历史主表的表头，展开的差异表保持正常流，避免覆盖历史列头。

本次运行笔记结构校验、差异空白检查、冲突标记与受影响源文件长度核对。依项目规则未运行编译、类型检查或自动化测试，回归测试仅补充源代码；真实客户端和联网请求未验收。所有写入测试使用隔离临时目录，本次实现不修改真实客户端配置、凭据或共享业务数据。
