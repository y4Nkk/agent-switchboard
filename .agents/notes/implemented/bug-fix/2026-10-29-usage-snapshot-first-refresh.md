# Agent Note: 消耗统计先读快照与合并刷新

Status: implemented

## Problem

消费统计把读取汇总缓存放在来源发现之后，进入页面仍需等待本地扫描。每次切换日期范围都会强制扫描，尽管后端已经同时生成四个范围。首次加载只有大面积骨架，无法区分读取快照和重新统计；活动来源变化时，本次已验证结果没有保存为下次可展示的快照。

## Decision

保留现有读取索引和调用事实所有权，将命令拆为无扫描的快照读取及显式刷新，删除旧的单范围请求与 forceRefresh 契约。响应一次交付四个范围，前端按当前范围选择；日期切换不启动读取。页面先读取同一来源键下的上次汇总，然后后台刷新，刷新失败保留已显示结果并重试。

后端启动或加入唯一刷新任务，前端通过短请求观察进度和终态；快照读取不等待任务完成。来源变化只更新受影响调用和小计，未变化来源不解码历史调用。所有已核实的汇总保存为上次结果，来源变化只缩短下次刷新期限，不伪装为已经覆盖随后追加的记录。首次无快照显示统计说明，真实阶段和工作量由局部组件呈现，计时不使模型图表每秒重绘；任务和增量结构由[按调用增量计量](../architecture/2026-11-04-incremental-usage-ledger.md)拥有。

## Related decisions

- [按调用增量计量与真实刷新进度](../architecture/2026-11-04-incremental-usage-ledger.md)：部分取代；移除长请求门禁、整块用量状态和仅计时反馈，接管当前任务、模式升级和真实进度。本篇的快照先显及四范围选择继续成立。
- [会话读取索引](../../implemented/architecture/2026-10-22-incremental-session-read-index.md)：部分重叠；本篇接管消费页加载、范围选择和刷新合并，保留该篇的来源索引、真实调用、完整前缀验证和日期规则。
- [完整本地会话与用量](../../implemented/architecture/2026-10-16-complete-local-session-usage.md)：部分重叠；来源覆盖、统计口径和隐藏页不调度新读取仍成立。
- [本地资源边界](../../implemented/architecture/2026-10-14-bounded-local-resources.md)：部分重叠；页面不再将范围切换排入读取队列，其他领域的队列和有界传输不变。
- 供应商额度、资源占用与托盘笔记：无关，读取及采样策略不变。

## Alternatives considered

- 只增加超时或等待文字可以最快改善反馈，但重复来源扫描及缓存被扫描阻塞仍存在，因此同时改动读取所有权。
- 在前端为四个范围分别缓存可以减少切换后的空白，但产生四份查询生命周期，仍然重复执行后端已经一起算出的工作，因此一次交付同批四个范围。
- 用文件大小或抽样摘要取代完整前缀验证能够减少字节读取，但无法证明旧调用未被改写，因此保留正确性检查，通过快照先显和合并重复扫描改善等待。

## Consequences

快照读取不调用来源发现；范围切换不发出统计请求；有缓存时刷新中和失败后仍展示匹配范围的结果；无缓存时呈现统计说明、真实阶段和进度。并发刷新共用任务，来源变化仍保存本次已验证快照并安排短期刷新。删除旧 get_model_usage_report 命令、ModelUsageRequest 单范围请求、消费页刷新队列与空白骨架；原子替换所有直接调用方，不保留旧 API 或双读路径。现行读取索引通过一次事务升级将有效快照转入 usage_snapshot，退出原 usage-reports 项。

首次索引与变化文件的完整前缀校验仍然有 I/O 成本。上次快照可能属于前一日，保留其生成时间及上次汇总标记。前端持有整批四范围结果，后端仅保留当前或最后一个任务及其来源键，不积累历史任务。隐藏页不再观察和调度新读取，正在运行的扫描完成并落盘。
