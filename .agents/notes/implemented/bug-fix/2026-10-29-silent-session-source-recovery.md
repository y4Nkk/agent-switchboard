# Agent Note: Codex 与 Claude 会话来源静默恢复

Status: implemented

## Problem

Codex 当前归档使用 `.jsonl.zst`。发现器只收集普通 JSONL，登记路径的身份检查又直接解析压缩字节，将不可读、缺少身份和真实身份冲突合并报告。派生索引可能保留错误的空身份。Claude workflow 依赖全局通知中的手动转换入口；两端来源警示又在会话与用量页重复进入全局消息。用户要求自动静默恢复，保留现有架构。

## Decision

- 原始会话及 Codex 原生库保持只读。共享记录读取器唯一拥有普通 JSONL 与 Zstandard 解码；所有记录偏移均指解压后的逻辑字节，源修订和摘要仍对应物理文件。
- 发现、身份、消息位置、正文、搜索、复制、收藏、导出和用量读取使用同一当前格式。压缩归档流式读取，消息批次复用同一顺序游标；不持久化第二份解压全文。普通活动文件保留原有追加校验，压缩文件变化后按完整快照重建。
- 已知旧派生索引升级后自动重建；单条缓存无法反序列化时删除该派生项并重算。读取期间发生变化时只作一次有界重读，取消立即传播；真正的源损坏保留完整诊断，不伪造成功。
- Claude workflow 在后台扫描中按来源修订自动生成完整的应用副本，复用现有转换格式与原子发布，删除旧手动转换命令和前端生命周期。失败保留此前完整副本，下次源修订更新或重新扫描时重试。
- 自动整理复用 Claude 保留库的删除标记；明确删除的 workflow 副本不能被后台重新生成。副本删除与其标记由同一保留库写入门禁拥有，不修改原始 workflow。
- Codex、Claude 的来源问题与用量覆盖诊断进入运行日志及相关读取结果，不再发布全局来源消息；删除无人使用的来源通知 Provider、确认状态和转换通知入口。用户主动操作的错误与全局设置、事务反馈继续由原所有者处理。

## Alternatives considered

- 仅删除全局警示最小且立即减少打扰，但压缩归档和用量仍漏读，因此需要先补齐读取及恢复链路。
- 长期保存完整解压副本可直接随机定位，但为大量归档复制 GB 级正文，违背既有存储边界，因此只保留位置与计量派生结果，批量读取复用解码游标。
- 保留手动转换按钮可以沿用所有交互，但自动恢复仍依赖用户进入指定页面，因此转换归后台来源扫描所有者，删除原前端入口。

## Regression coverage

- 隔离夹具覆盖两种编码的身份、消息位置、分页、搜索、导出及真实用量等价；普通追加、压缩替换、损坏记录、缓存失效和重复副本均保持当前语义。
- Claude workflow 首次扫描、重复扫描、来源更新及失败保留旧副本均自动完成，不发布全局消息，不写原件。
- 原有全局来源发布、手动转换命令及无人消费的状态、词条与测试引用全部移除。保留明确的本地错误及运行日志。
- 按当前 AGENTS.md 不执行编译与自动化测试；添加回归夹具并进行静态引用、差异和笔记结构校验。

## Consequences

标准 Zstandard 不能直接按解压偏移随机定位，单条读取仍有从流首跳过的成本；分页及连续访问必须复用游标。真正损坏或不可访问的原件不能通过缓存修复，须保留原件并记录原因。未知数据库结构必须保留，不能把未知材料当作已知缓存自动清空。

前端按 React 质量技能复核 Hook 顺序、移除状态后的直接消费者、通知清空焦点、空态及异步任务取消；未新增确认状态、浏览器持久化或额外消息副本。原始文件和业务库没有在开发过程中执行写入，现有安装包尚未包含本次修复。
