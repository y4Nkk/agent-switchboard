# Agent Note: Claude 账号切换后的会话可见性与保留边界

Status: implemented

## Problem

用户要求 Claude Code 换账号后仍可看见并继续以前的会话，达到目前 Codex 会话保留的使用效果。用户不能确认消失发生在终端、VS Code、Claude 桌面端还是 Switchboard。把任一客户端列表的消失直接当成会话文件被删除，会导致修改错误的所有者；只修列表也不能阻止原始正文随后被清理。

## Baseline evidence (2026-10-22)

- `commands/switching/plan.rs`、`asb-switch/src/executor/switch.rs` 的 Claude 投影写入当前 `settings.json`；切换后的 `claude_integration` 仅同步插件标记。官方登录在 `official_login/claude_credentials.rs` 合并替换凭据对象。当前链路没有会话目录删除或按账号搬迁操作。
- `session_manager.rs::session_roots` 仅使用当前进程解析的 Claude 配置目录下 `projects/`。`sources.rs` 按客户端和会话身份汇合来源；`search/filters.rs` 不按账号或供应商过滤。会话与用量共用原生来源。更换 `CLAUDE_CONFIG_DIR` 会改变整个来源集合，旧目录不会被记住。
- `session_manager.rs::resume_session` 在来源保存的项目目录启动 `claude --resume <id>`；没有把旧账号凭据带入恢复命令。恢复仍依赖启动环境能找到该会话，当前实现不携带独立的会话来源目录。
- 配置及认证备份不包含 Claude 会话正文。会话读取直接依赖原生文件；收藏只保存用户明确选中的消息，workflow 转换只保存对应事件，两者都不能冒充完整会话保留。
- Codex 的当前阅读链路还读取客户端原生登记库及历史正文库；Claude 没有对应的应用持久正文副本。因此两者的保留基础不同，不能从 Codex 会话仍可读推断 Claude 原文件可以安全删除。

2026-10-22 的本机只读盘点：默认 Claude 项目目录有 221 个 JSONL 文件，其中 68 个主会话、148 个普通子代理记录、5 个 workflow journal。68 个主会话均能找到会话身份且没有重复主会话 ID；5 个 journal 没有 sessionId，与现有显式转换契约一致。主会话最新文件时间为 2026-09-16，68 份都早于本次盘点日的 30 天边界。这里只核对来源、身份和文件元数据，没有运行生产解析器或真实恢复，不能把盘点说成 UI 验收或实际清理资格证明。

当前进程、用户、机器三个环境范围均未设置 `CLAUDE_CONFIG_DIR` 或 `CLAUDE_CODE_SKIP_PROMPT_HISTORY`；原生设置及现有 4 份 Claude 档案、2 份客户端设置中未发现历史目录覆盖或显式保留策略。默认项目目录没有链接目录。安装的 VS Code 扩展为 2.1.306，其设置未显式覆盖自动归档、进程包装器或扩展环境变量。当前没有正在运行的 Claude / VS Code 进程，也没有足以对应用户那次账号切换的前后快照；尚不能认定用户此次现象的唯一根因。

## Native contracts

- [Claude 官方认证文档](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)明确：独立的 `CLAUDE_CONFIG_DIR` 同时隔离设置、历史和登录。账号目录切换后的空列表可以是来源切换，并不证明原文件被删除。
- [Claude 会话文档](https://code.claude.com/docs/en/sessions#where-transcripts-are-stored)说明正文存于项目 JSONL，并支持按会话 ID 或完整 transcript 路径恢复。
- [原生保留规则](https://code.claude.com/docs/en/claude-directory#cleaned-up-automatically)规定终端记录默认 30 天；`cleanupPeriodDays` 最小为 1，0 无效。本机 2.1.306 扩展附带的官方 schema 同样要求正整数，不能用写入 0 来承诺永久保留。新版本桌面端正文有独立保留规则，不能一概套用终端的 30 天。
- [VS Code 历史文档](https://code.claude.com/docs/en/vs-code#resume-past-conversations)说明无活动会话默认 14 天进入 Archived sessions。归档改变列表可见性，不等于正文删除。
- Claude 桌面端有独立列表；官方仓库的[跨账号会话不可见报告](https://github.com/anthropics/claude-code/issues/48511)与用户描述相似，但这是其他用户的报告，不能当成本机复现。不得仅凭该报告改写本机桌面端的账号 / 组织索引。

## Decision

历史属于本机项目，认证只决定后续请求使用哪个账号。`session_manager/history` 在现有 `state/sessions/claude.sqlite3` 单独拥有 Claude 来源目录、原始记录、版本、附件、恢复文件登记与删除标记。主会话、普通子代理经过同一原生解析器进入保留库；列表、正文、搜索、收藏、复制、导出和用量读取保存的当前契约。原生目录仅是采集入口，删除单一活动目录的 Claude 原文直读路径及仅传 ID 的恢复路径，不保留第二套正文回退。

来源默认接入本机 `.claude` 和当前配置目录，用户通过系统目录选择器接入其他旧目录。登记在库内，切换配置目录不会忘掉旧来源；停止读取不删除已保存内容。来源窗口展示目录状态与具体采集问题，详情展示保存时间、原件可用性和保留异常。后端拒绝把应用状态目录注册成用户来源，不扫描整个主目录猜账号。

保存由应用生命周期拥有：启动、每 10 秒、已确认的 Claude 配置投影 / 官方重新登录写入前以及正常退出时运行。单个来源在一个 SQLite 事务内逐行保存原始字节，校验来源前后时间、长度、全文摘要与附件集合；未写完、超限或变化中的来源回滚该次保存并报告问题。未变化来源跳过；追加先验证已保存字节前缀，只插入新增行；原地重写或已保存附件改写时新增版本，保留旧完整版本。相同原路径被替换为不同会话身份时不覆盖旧会话。读取仍可使用已成功保存的材料，库结构 / 写入事务错误不能伪装成切换前保存成功。

附件按 SHA-256 去重，以 1 MiB 块写入同一库，和正文原子发布。内嵌图片留在原始记录中；本机图片与会话附属目录保留完整字节。已经缺失的图片保留正文并明确报告缺口，先前保存的图片不因原图消失而丢弃。普通读取不访问原图片路径；消息解码后将外部图片引用绑定到该来源版本，按需解析为图片字节，不能跨版本按相同文件名猜测图片。单条原始记录仍受 32 MiB 边界约束，不把全历史正文常驻内存。新库仅接受当前模式，异常或未知结构保留原库并报错，不重建覆盖。

恢复只在用户点击时生成带可用附件的原生 transcript，用当前认证在原项目启动 `claude --resume <完整路径>`；不复制账号设置或凭据，不改写桌面端私有账号索引。恢复目录先登记再原子发布，失败暂存目录在下一次保存时清理；已发布目录继续纳入采集，无论客户端向原目录还是恢复文件追加，都有后续保存入口。消息使用原生 UUID 保持跨恢复身份，原文摘要继续校验实际内容；无 UUID 的记录按完整记录与出现次数去重。相互冲突的附件拒绝猜测覆盖，并给出具体错误。

删除通过同一保留库所有者解析原路径，校验来源目录与会话身份后删除可访问原件、附属目录、保存的所有版本 / 附件和已登记恢复目录；逻辑会话及普通子代理写入删除标记，离线旧副本再出现也不重新导入。失败不报告删除成功，库内材料保留以便重试。独立收藏和 workflow 转换副本遵守各自明确删除边界。原客户端的年龄清理、VS Code 归档和桌面端账号列表仍由各自客户端拥有，不通过改写这些设置来冒充正文保留。

## Related decisions

- [搜索取消、真实进度与全局警示](2026-10-23-session-search-lifecycle.md)：搜索取消进入保留同步的记录和附件分块边界；取消只回滚当前未发布文件，目录原件可用性在完成整目录扫描后原子发布，避免取消导致未检查的历史被误记为不可用。保留模式、完整快照及恢复身份继续由本篇拥有。

- [完整本地会话与用量](../architecture/2026-10-16-complete-local-session-usage.md)：部分重叠；保留逻辑身份、共享读取器、真实消费去重及原生数据库只读约束。本篇接管 Claude 来源跨账号稳定性和完整正文保留，不推翻共享读取契约。
- [会话读取索引与增量真实用量](../architecture/2026-10-22-incremental-session-read-index.md)：部分重叠；保留库交付按修订校验的原始字节范围，消息位置、搜索命中和计量状态由派生索引拥有，不另设 Claude 原件直读路径。
- [本地资源边界](../architecture/2026-10-14-bounded-local-resources.md)：部分重叠；继续逐记录有界读取、分页传输及显式维护，持久保留不能引入全量正文常驻内存。
- [workflow 转换](../feature/2026-10-20-session-warning-conversion.md)：相邻但独立；journal 仍是执行事件，不能为覆盖数量虚构 sessionId，也不拿 workflow 副本代替主会话。恢复目录的 journal 也由同一显式转换入口解析。
- 检索 proposed 与 implemented 的会话保留、Claude 历史、账号目录及保留策略；未发现需要废弃的同主题提案。其他会话布局及客户端配置笔记维持原职责，未改写既有决定。

## Alternatives considered

- 仅延长 `cleanupPeriodDays` 最少改动、原客户端直接受益；但无法合并账号目录或桌面端列表，也不能恢复已经删除的原文，故不能单独满足完整保留目标。
- 只记住旧目录可直接复用现有解析器，不复制正文；但原文件一旦被清理仍失去会话，因此适合来源发现，不能承担持久保留承诺。
- 给每个账号复制一套历史或改写桌面端账号索引，可以让某个原客户端列表立即出现旧记录；但会复制增长、分叉同一会话，且把会话归属、删除及认证混在一起，不作为通用方案。
- 切换时才备份全部会话，触发点明确、无需后台同步；但覆盖不了客户端自行清理、外部账号切换或尚未再切换的新增内容，因此不能作为完整保留的唯一入口。
- 仅原子替换最新完整快照可节省存储，也易于证明当前一致性；但客户端重写、截断或压缩原日志会同步丢掉早先已保留内容，因此按完整旧字节前缀区分追加与新版本，重写时保留旧版本。

## Testing

- 新增隔离夹具覆盖：原件消失后正文 / 图片 / 消息身份；图片原文件改写后保留旧附件；未完成追加保留旧快照后恢复；末条完整 JSON 后补换行的字节连续性与用量；两个账号目录的逻辑去重与收据去重；日志重写保留早期内容；删除标记阻止离线副本复活；恢复主会话 / 子代理 / 工具输出而不复制凭据；恢复文件新追加继续保存且删除清理；损坏数据库保留原字节。
- 用户明确授权一轮沙箱黑盒、白盒及单元测试。测试进程重定向用户目录、应用目录、Codex / Claude / SQLite 目录和临时目录，并移除真实模型调用环境变量；编译缓存保留在既有构建目录。公开服务入口黑盒使用独立子进程，跨进程验证目录切换、原件消失、搜索 / 阅读 / 图片 / 复制 / 导出 / 收藏、删除和离线来源重现。恢复材料和失败事务由内部隔离夹具验证，不启动真实客户端或使用真实账号。
- 已执行并通过 113 个不同用例：保留库单元 10、会话白盒回归 74、公开接口跨进程黑盒 2、真实用量及缓存回归 18、前端语言 / 读取调度 9；TypeScript 类型检查通过，Rust 库测试完成编译并执行。黑盒父用例实际调用四个独立子进程阶段，单独的驱动函数按设计不作为普通用例直接运行；各阶段均核对假凭据保持不变。本轮未发现功能失败，清理两处未使用导入。真实 Claude CLI 恢复、OAuth 登录及原生桌面交互未验收。

## Consequences

原件被清理或账号目录变化不再直接移除已保存会话，恢复继续使用当前认证。正文和附件长期保留增加磁盘占用，也保留原文已有敏感内容；容量计入已有存储界面，显式删除回收库内记录及恢复目录。SQLite 空闲页可能等待数据库复用，删除不承诺立即缩小文件或物理安全擦除。应用关闭期间没有后台保留进程，首次接入前已被删除、两次观察间写入又被清理、客户端尚未写出的内存内容均不能承诺已保存。原生格式、并发分支与恢复行为仍需真实客户端验证，冲突不静默猜测。此能力属于 Switchboard 本机会话库，不等于 Claude 桌面端跨账号列表同步或云端历史同步。
