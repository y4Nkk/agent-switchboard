# Agent Note: 会话搜索取消、真实进度与全局警示

Status: implemented

## Problem

清空搜索栏只更新 draft，旧 query 继续存在。前端读取队列只能删除未启动工作，已启动的全文搜索必须完成，新查询因此等待过期工作。后端全文搜索遍历所有匹配来源才能计算总命中数，来源发现又同步执行 Claude 保留扫描；当前界面只有扫描文本，没有真实阶段和计数，不能区分等待与停滞。

会话扫描使用独立 WarningNotice 横幅及确认后复查按钮。复查按钮的 unstyled 变体没有重置原生外观，而且独立横幅侵占结果区；这些持续警示应进入现有标题栏 GlobalInformation。

## Decision

搜索使用 start / read / cancel 单一任务契约，桌面和浏览器开发传输相同。后端任务拥有阶段、已处理会话数、实际总会话数及当前消息计数；前端轮询真实状态，环形进度按已完成会话比例绘制。来源发现阶段没有全局总数，只呈现未定量环和阶段文字。任务替换、隐藏和卸载取消旧任务；检查点位于来源、会话和消息处理边界，单次文件/SQLite 操作仍须返回后才能取消。取消不通过清空 busy 伪装为成功。

任务注册表最多持有 16 个活跃请求与尚未领取的终态，轮询维持 60 秒租约；后台回收器主动取消过期任务并清理终态，不依赖下一次用户请求。取消中的任务仍计入并发上限，直到实际执行退出；领取终态即移除。旧 search_sessions IPC 删除，无界面包装仅在测试编译中委托同一执行器，不另建算法。清空非空已提交搜索词立即回到空查询，输入其他草稿仍显式提交。

取消检查进入扫描/索引/保留锁等待、目录遍历、原始与已保留记录读取、附件分块保存和消息索引建设，避免旧任务在这些环节长期占用后续查询。已完成会话和当前消息计数来自后端处理边界；发现与同步总数未知时使用未定量环，索引阶段明确显示正在建立索引，不生成猜测百分比。取消中止当前文件的保留事务，完整文件快照不回滚；根目录可用性只在该目录完整扫描后原子发布，取消不把尚未检查的既有会话误记为不可用。

Claude 恢复包重建同样消费 `visit_records_observed`；恢复操作不属于搜索任务，因此显式传入空检查点，不借用搜索取消状态，也不恢复旧接口。保留库仍是记录和修订校验的唯一读取来源。

GlobalInformation 接受由工作区声明的消息来源；扫描警示、转换操作和转换错误在全局展开面中显示，确认按消息身份记录，已确认内容可在同一全局入口复查。不会进入两条上限的短暂通知队列，也不另存持久历史。删除旧 WarningNotice 横幅、复查按钮及专用 CSS。

会话 Hook 将最近成功扫描的 issues 与可释放的结果正文分开持有，返回的页面快照不再重复保存 issues；查询变更或页面隐藏不抹掉来源诊断，下一次成功扫描替换它。用量页作为旧提示组件的另一个直接消费者，同批接入全局来源。确认由来源 Hook 唯一拥有，外壳只消费来源展示，不维护第二份确认集合。

来源确认集合只保留当前仍存在的消息身份，问题解决后清除对应确认，再次出现时重新提示。全局展示将来源错误排在来源警示之前，已确认内容保留在同一展开面中复查。

转换结果和错误按转换所有者产生的实际尝试序号区分，不使用翻译后的错误文案作为身份；切换语言更新文案但不重置确认，新的转换尝试仍产生新的反馈身份。

## Alternatives considered

- 只在前端超时后清除 busy：实现最小且能恢复控件，但后端仍在执行，重复请求继续堆积，也无法提供真实进度，因此不采用。
- 保留单次 invoke，额外用桌面事件推送：桌面成本低，但浏览器开发接口没有同一事件传输，还需要另一条状态读取路径；统一任务读取覆盖两种传输，因此不采用。
- 只在全文匹配循环检查取消可以少改调用链，但来源保留及首次索引仍会长时间占用扫描门禁；检查点必须进入这些实际耗时环节，单次系统调用仍保持原子边界。
- 警示发送 durationMs=0 的 toast：可直接复用全局入口，但两条队列会挤掉警示或操作结果，确认后也无法复查，因此不采用。

## Consequences

清空已提交关键词退出旧查询，更新的请求不再排在完整旧搜索之后。环形进度来自真实会话处理数，当前消息计数来自逐条访问边界；未知总数不展示百分比。旧消息读取队列继续服务其他读取者，搜索只保留当前任务接口。持续警示可从标题栏确认与复查，不再压缩双栏阅读区，也不挤掉短暂通知。

取消为协作式，单次文件系统或 SQLite 调用不会被强行终止；跨记录、跨分块及门禁等待均执行取消检查。进度按实际会话计数，不是时间估计；大消息会话耗时较长。当前审查未接触真实数据或运行进程，截图不能证明永久死锁。

代价是搜索期间每 150ms 读取一次任务状态，任务状态在内存中有界存放，后台每秒回收过期任务；来源发现及同步仍有实际 I/O 成本。保留格式和数据库模式不变，目录可用性发布改为完成扫描后的原子事务；本轮实现没有运行应用，也没有写真实会话数据。
