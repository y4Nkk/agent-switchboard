# Agent Note: Codex 回填使用档案存储版本，遗留事务按原字节补偿

Status: implemented

## Problem

切走活动 Codex 供应商时，应用先保存切换意图，再将实时配置中归供应商所有的字段回填到原档案。意图里的回填后版本用 SHA-256 计算，档案实际写入返回的却是存储版本指纹。写入成功也被判为失败；同一比较阻止回滚，导致后续写入和启动准备持续受阻。这一步发生在模型目录暂存和客户端执行器之前。

## Decision

Codex 档案存储层拥有落盘编码及档案版本计算：新回填和活动档案保存的预计算与实际写入共用编码和版本规则。回填前像及其版本来自同一次读取。客户端配置、认证文件和网关路由指纹仍有各自的所有者，不更改算法或文件结构。

只有切换事务恢复入口可消费已落盘的 v2 混用意图。自动恢复限定在 Codex 投影尚未进入执行器、客户端与认证快照及写入历史未变、模型目录尚未暂存的阶段。恢复核对之前的路由与档案身份，只有原始档案字节精确匹配记录的回填 SHA-256 才用前像回滚；档案已是前态时不重复写入。前像若不能重建原版本、任何配套状态不符或档案额外更改，停止并保留意图。网关恢复后才清理意图，不重放切换，不生成混用记录。此入口只补偿遗留的在途事务，不是档案或事务的日常双读。

## Related decisions

- [当前客户端配置契约](../feature/2026-10-12-current-client-configuration-contract.md)继续拥有回填字段及验证边界；本篇仅规定落盘版本与中断后的补偿。
- [启动准备](../feature/2026-11-11-automatic-application-data-preparation.md)继续调用事务的原所有者，不接管恢复。

## Alternatives considered

- 只修新写入的算法改动最少，但已卡住的写入仍无法通过恢复。
- 允许日常读取和回滚同时匹配两种哈希能省掉特定中断阶段的校验，但会扩展长久的文件契约，并允许在客户端或历史已变化的阶段误用前像。

## Consequences

新切换使用一致的档案版本。符合已知中断状态的旧事务可在启动或写入前原地结束，客户端配置和认证不重写；与快照不符的记录仍需保留以供核对。隔离回归夹具覆盖预测与实际版本一致、遗留事务回滚与重新进入、冲突拒写。
