# Agent Note: 按调用增量计量与真实刷新进度

Status: implemented

## Problem

整份文件计量状态虽然避免未变化正文的重复解码，但任一来源变化仍解码所有历史调用并四次聚合。统计来源发现同步执行 Claude 保留，等待与写入锁进入页面关键路径。只有计时文字无法说明实际完成量。

## Decision

在同一个读取索引中用来源游标、来源调用观察、去重调用和会话日期小计替换旧整块用量项。来源修订、调用贡献和小计在短事务中原子发布；修改或删除来源仅重新判定受影响调用。保留 Codex 收据身份、上下文模型补全、检查点日期补全和 Claude 最终片段规则，来源关系不能被文件小计替代。

用量来源由会话模块提供轻量清单，Claude 只交付保留库已提交版本，不同步采集原件。保留库在一个读事务中验证来源版本并提供追加字节；原件完整前缀校验仍归保留所有者。Codex 活动原文保留完整旧前缀与读后核验，只处理变化来源。

一个应用级刷新所有者负责短请求启动、重复请求合并、状态读取与最终结果。进度只来自来源完成数量、实际读取字节和已处理调用；未知总量使用不确定动画，不生成假百分比。前端先读已提交汇总，观察当前刷新，隐藏停止观察和调度，已开始工作完成并保存。四范围来自同一快照，日期选择不发起读取。

读取索引使用版本 3，已知版本 1/2 在事务中升级；版本 2 的有效四范围快照转入 usage_snapshot，删除被替代的 usage-file、usage-saved-events、usage-reports 项。版本 1 的旧派生项按既有规则重建，版本 2 的无关索引和所有原始记录保留。不双读、双写或保留旧计算路径。结构未知时保留材料并提供明确错误。报告缓存与增量表同属唯一派生索引。

时区标识和进程 TZ 值参与日期投影版本。变化时只从去重调用重建日期小计，不读取原文；普通刷新从小计生成四范围。计数在 Rust 使用受检的 u64 运算，以 JSON 保存小计，避免 SQLite 有符号整数缩小计数范围。每来源事务同时提交游标、观察、去重调用与小计，失败回滚该来源，上次完整汇总直到新一轮发布成功才替换。

前端以短请求观察任务终态；连续观察失败解除加载并允许重新加入任务，后端异常也有失败终态。模型图表按报告引用记忆，进度与计时不反复重绘图表。部分来源说明在消费页按需展开，诊断日志复用会话模块的去重记录机制。

## Alternatives considered

- 各文件只保存小计最省存储与查询成本，但跨来源副本、压缩检查点、调用补全和来源删除无法正确去重，因此保存来源到调用的关系。
- 只延长刷新周期或新增前端缓存改动最少，但单次刷新仍重做全历史工作，因此采用按调用增量更新。
- 首尾抽样或仅比较长度能减少大文件 I/O，但无法证明既有前缀没有改写，因此保留变化原文的完整核验。
- 新增独立统计数据库可以绕开现有模式校验，但增加派生状态所有者与恢复边界，因此在同一读取索引事务升级。

## Consequences

快照读取不扫描来源；范围选择不调用后端；无变化来源只读小游标，不解码历史调用。追加、改写、截断、删除及日期模型补全只重判受影响调用。来源到调用的关系增加派生存储，用来保证跨文件重放、来源移除及后续补全的正确性，不能压缩成无法追溯的文件小计。任务只保留当前或最后一个结果，不积累任务历史。

首次建立索引仍读取全部受支持来源；变化的大原文仍有完整校验成本。Claude 汇总覆盖已提交保留边界，不能声称覆盖尚未保存的数据。进度显示当前操作，不把重复校验字节包装成全局单调百分比。旧快照升级后可先显，但新调用表仍需首次建设；索引中释放的旧页由 SQLite 复用，不承诺升级立即缩小磁盘文件。

## Verification

隔离夹具覆盖无变化不解码、仅解码追加、重复来源删除、重写与尾行补全、同修订读中改写、模型和日期补全、时区投影、来源事务回滚、版本 1/2 升级和保留无关索引、Claude 已提交追加读取及不持有采集锁、任务合并与失败终态、前端隐藏和失败恢复、实际工作量百分比。按项目要求，本次未运行编译、类型检查或自动化测试，不把这些夹具列为通过。静态调用链、过时引用、差异和笔记结构单独检查；真实桌面和 GB 级历史的耗时仍未验收。
