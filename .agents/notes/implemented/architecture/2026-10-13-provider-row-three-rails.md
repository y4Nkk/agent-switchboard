# Agent Note: 供应商档案行三轨分层（布局整合，不减信息不改样式）

Status: implemented

## Problem

供应商档案行在窄容器（列表 ≤55rem，125% 缩放常见）下动作轨整体换行为右对齐孤行，而模型槽 60px 固定高把主数据轨撑出大片空白，单行行高约 170px，右缘扫描锚点断裂。宽容器下「已应用」标记锚在模型槽尾缘，与连接槽文案相邻跨格连读成「已应用 官方登录」；整行九类信息只有「正文/弱化」两档字重，没有主次链。

## Decision

用户约束：不大改、不改视觉样式、不舍弃任何信息元素。分层整合只通过布局几何与结构落位实现，落点三处：

- **三轨命名入契约**（DESIGN.md §供应商界面）：主数据轨恒为单行，只承载身份、模型与连接地址；状态轨是主数据轨下方的全宽摘要轨；动作轨以右缘为唯一扫描锚点。全部信息元素保留：官方行连接槽仍显示「官方登录」，无模型时仍显示「默认模型」，「上次读数 · 更新失败」标记与独立警示行并存。
- **已应用标记改锚名称尾缘**（`ProviderWorkspaceShell` 结构重定位）：从模型槽尾缘移入身份区，紧随名称之后；消除与连接槽文案的跨格连读。仅一行是激活态，标记不要求跨行对齐，随名浮动无损失。
- **窄容器（≤55rem）动作轨紧贴**（`provider-list.css` 容器查询内）：动作轨整体换行时与主数据轨零行距，主数据轨回落标准控件高度（40px），动作仍右缘对齐——换行动作是同一轨的延续，不是新区块；宽容器下主数据轨保持舒展固定高度不变。

视觉样式（颜色、字体、字重、边框、圆角、背景）零改动；CSS 仅调整布局几何（锚点边距、行距、轨高）。词汇表无增删，`providers.label.defaultModel`、`codex.rows.defaultModel`、`usage.summary.previousFailed` 等既有词条全部原样消费。

操作可见性由[供应商行操作统一按悬浮显示](../bug-fix/2026-10-22-provider-row-hover-actions.md)拥有；该决定保留本篇三轨布局及占位，不改变模型与地址的扫描锚点。

## Alternatives considered

- **信息元素删减与词条收敛**（官方行连接槽去重、「默认模型」占位改「未设置」、「上次读数 · 更新失败」合并为「上次读数」）：最强理由是消除语义重复与占位词歧义，首轮曾按此实现。否决：用户明确要求不舍弃任何信息元素、不修改样式，本轮全部恢复原状。
- **纯 DOM 重排、零 CSS 改动**：最强理由是字面满足「样式不修改」。否决：窄容器孤行与主轨空洞是几何问题（行距、固定轨高），结构重排无法解决，且用户同时要求优化布局；样式与布局分层理解，几何属性不属于视觉样式。

## Consequences

收益：窄容器行高从约 170px 收紧到数据轨加动作轨约 80px 起；「已应用」与名称同组、不再与连接槽文案连读；三层结构有了契约命名，后续行内改动有归属可查。代价（由信息保全约束主动接受）：官方行「官方登录」在名称与连接槽两处重复、无模型时「默认模型」占位词仍像列标题、失败状态在新鲜度标记与警示行两处出现——这三处重复作为既定取舍保留，将来若要收敛需用户明确解除约束。验证：恢复的三个词条与全部消费点经全库 grep 双向核对；本次用户授权的 0.3.3 构建包含前端类型检查并通过；`npm run verify-notes` 通过。独立模拟沙箱对生产前端的 1440px 收起导航与 1100px 展开导航截图进行目检，名称标记、模型、地址与换行动作均在各自轨内；未执行自动化回归测试，原生窗口与系统缩放仍未验收。文案密度与工作区视觉所有权的相邻决定见 [界面文案密度收敛](../simplification/2026-10-13-ui-copy-density-reduction.md) 与 [桌面工作区视觉与交互所有权](2026-10-13-desktop-workspace-uiux.md)。
