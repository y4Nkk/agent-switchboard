# Agent Note: 供应商资料与模型路由共用一个编辑会话

Status: implemented

## Problem

供应商新增后必须保存、返回列表、再打开模型路由工作区才能配置用途。主模型有重复入口，连接和路由分别持有草稿、确认与保存。新建档案尚无 UUID，固定自目标不能在首次保存前表达；把 Claude 固定自目标转为 Primary 会改变故障转移语义。

## Decision

供应商编辑器唯一持有连接、模型和参数草稿，使用「连接设置」「模型与路由」「运行参数」自由分区及一个表单。Codex 与 Claude 各自保持类型化草稿；官方登录只有连接和参数，不暴露第三方路由。配置图与用途检查器消费只含路由字段的 RouteDocument，不再依赖已保存 record 或伪造 fileHash。

模型目录、名称映射、主模型和用途归模型分区，主模型只有一个编辑位置。当前档案使用当前草稿名称与目录，外部目标读取已保存记录；不默认选中目标或按同名模型猜供应商。Claude 保留自动、Primary、固定 Provider、Fable 的 Opus 继承和 1M 标志。恢复用途自动值只清除用途覆盖，不重置主模型、连接、目录或参数。

「模型路由与网关」只读展示已保存方案、活动身份和真实运行观察。选择方案不激活，点击用途进入同一个供应商编辑会话；同档案只切分区并更新返回来源，换档案或显式重读先处理未保存修改。实例身份与持久档案 ID 分开，重读从最新清单重新解析记录并重建实例；确认等待期间发生删除不能被旧导航闭包忽略。

### 创建与保存契约

新建会话分配稳定的最终标准 UUID，仅在内存持有，取消不创建占位文件。转换种子沿用独立新建身份、未知限制与能力确认，不修改源档案或继承外部用途依赖。

通用 prepare_profile_save 接收严格的 ProfileSaveTarget：create 包含 profileId，update 包含 profileId 与 expectedFileHash。Codex create_codex_profile 接收明确 profileId 和专用 draft；两端存储创建函数接收 ID，所有内部导入、发现、转换及直接夹具同步当前签名。删除 nullable 参数组合及自动生成 ID 的旧签名，不保留旧请求重载或临时 self 格式。

创建在现有写闸门与用途锁顺序下校验 UUID、实际三个供应商目录的冲突、完整候选和引用，再原子写入。失效符号链接也算已有目标，不能覆盖。Codex 自身引用对照完整候选，外部引用按真实目标目录及认证校验；创建和编辑复用存储侧引用所有者，不再创建前到磁盘查找不存在的自己。持久文件、备份版本与网关请求路由结构保持原契约，无数据迁移。

新建及无活动依赖的修改一次点击保存；影响活动方案时合并编辑对象、原活动所有者、用途变化与实际文件差异，确认一次后走原事务。保存不隐式启用。网关独立 useRouteDraft、useRouteApply、RouteSavePreview、参数二级页状态及重复 MainModelField 已移除。

### 异步与可见性

唯一保存入口复用 useProfileSavePreparation 的准备、移交、撤销及失败释放队列。供应商会话 setter 的现有同步 generation 与主页面的同步 pageVersion 组成提交上下文，事件开始时捕获；迟到 prepare 即使在下一次 React render 之前返回也须释放，已发出的 commit/create 继续完成但不能关闭新会话、重选旧目标或抢回导航。转换响应同样绑定页面版本。准备上下文还绑定记录修订与活动身份；未确认准备失效时显示原因，已移交的事务不被误报为撤销。

确认期间冻结编辑；模型列表获取同步标记 pending，防重复请求和同事件保存，返回时比较版本及当前连接。模型读取期间不允许保存，避免目录迟到改变已预览草稿。参数种子只在新建缺失时初始化，原始模型列表文本、折叠与分区阅读位置保留。必填错误先揭示所属分区再报告，防止隐藏 input 无法聚焦。

外部档案变化保留草稿，禁用保存并提供显式重读。编辑框架统一拥有标题和可恢复来源焦点，隐藏编辑器不消费快捷请求、不显示放弃弹层。保存后刷新配置，返回网关复用已有可见即刻读取，隐藏网关不增加轮询或冒充已完成刷新。连接提示在原 requiresGateway 所有者中加入模型映射及用途规则，监听就绪和上游调用成功仍是不同事实。

### 视觉与资源

网关页头、状态与已保存用途列表分层，活动档案与查看方案分开。用途行显示目标、模型、1M 和固定/跟随规则，操作复用已有 Button、Tabs、Select、FactList；窄内容区按命名容器查询重排，隐藏装饰，不挤正文。实际拓扑、请求遥测、端口与恢复仍由原运行模块拥有。

内置生图工具生成透明的金属与冰玻璃交换节点装饰，落地 `src/assets/routing-hub.png`，提示词与用途记录在 `src/assets/routing-hub.prompt.md`。它无文字、状态灯或请求关系，仅作 alt 为空的装饰；不在图片内承载产品事实，不添加远程运行时依赖。

## Alternatives considered

- 保存后增加「继续配置路由」动作改动最小，完整复用原工作区；但仍要求提前落盘、两次保存与取消，不能完成一次编辑。
- 在供应商页复制用途表单可保留网关原交互；但两套草稿、主模型与确认仍需维护版本一致，因此复用受控用途组件并移除第二个写入口。
- 把资料、路由和流量全部合到一个主导航页面，入口最少；但全局端口和请求会持续占用单档案编辑空间，因此保留两个查看入口和一个编辑会话。
- 用 self 创建意图由后端分配 UUID，能保持存储内生成身份；但两端都需增加草稿目标归一化，且 Claude 固定自目标与 Primary 不等价。会话提前拥有标准 UUID 可复用已有路由格式，代价是所有创建请求及直接消费者必须一起更新。
- 后端预分配 UUID 或持久预留能独占身份生成；但 ID 不承载权限，当前本机前端已有 crypto.randomUUID，会话内生成与后端冲突校验足够，无需额外命令和清理生命周期。

## Verification

本任务按当前 AGENTS 不运行编译、类型检查、格式化、自动测试或写配置验收。完成代码、契约直接消费者与组合差异阅读，检查旧引用、冲突标记、文件/函数职责边界及 git diff --check；笔记另运行 npm run verify-notes。

新增与更新但未执行的检查代码包括两端创建自目标、UUID 冲突及严格 target 的 Rust 用例，纯路由新建自目标与重置用例，网关需求及 Codex 官方保存摘要回归。原模型路由浏览器夹具改为只读总览与正确入口检查，移除已失效的网关保存模拟，保留隔离网络、合法 ID、双语深浅和窄窗用例。

并行转换聊天拥有其真实副本与浏览器验收脚本，本任务保留其工作并只更新共享业务契约；其独立运行结果不作为本篇当前整合的完整验证证据。

## Consequences

收益是新建与编辑都能在一个流程配置连接、目录和用途，保存只有一个事实所有者，旧独立写路径和请求形状不再保留。代价是创建签名涉及内部导入与直接夹具，并需要同步会话、导航与确认生命周期；开发中的旧页面须重新加载当前请求。

代码与资产已落地，未提交、推送或发布。编译、自动化、原生窗口、真实 Codex/Claude Code 与上游调用验收尚未在本任务执行；源码审查和装饰图检查不能替代这些证据。现有单文件原子替换不等于已验证断电、外部进程并发写入或进程终止的全部行为。
