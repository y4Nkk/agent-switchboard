# Agent Note: 会话读取索引与增量真实用量

Status: implemented

## Problem

会话列表、消息页和单条正文都重新发现全部来源。分页约束传输而没有约束解码；原生时间线先读取全部正文建立临时位置索引，再逐条读取正文。用量的五分钟、单范围 JSON 快照到期后重新解码全部历史，切换范围和重复请求会放大同一工作。

活跃会话持续追加时，文件级和整体汇总的前后版本完全相等检查会把正常写入当成失败；首次打开消耗统计因此可能没有任何结果。读取到不断增长的 EOF 也没有稳定的完成边界。

## Decision

应用的 `state/sessions/read-index.sqlite3` 唯一拥有可重建读取索引，客户端原文和原生历史库仍拥有事实。索引只保存来源修订、元信息、消息位置和计量解析状态；不保存第二份完整消息正文。索引使用当前格式，拒绝未知模式，不读取旧用量 JSON 快照。来源目录标识参与键空间，来源切换不能复用另一目录的结果。

元信息按文件修订复用；筛选客户端和定位会话在正文解析之前完成。消息位置按原始文件修订或原生消息更新序号失效，消息页仅解码当前页，单条正文直接定位并验证摘要。原始消息保持既有前缀身份和续接去重；已变化的原始文件重建自身消息位置，不复用过期锚点。原生消息增量复用未变化条目的位置，不因其他会话更新读取全文。

真实用量按文件保存解码状态及完整记录边界。未变化文件不重读；追加前验证旧字节前缀，验证通过后只解码新增记录，改写、截断或不完整尾行按当前文件重建。全量前缀验证仍有顺序字节读取成本，但避免旧 JSON 解码，不能用抽样摘要猜测前缀未变。调用身份、模型上下文、压缩检查点与 Claude 最终片段共同保留，删除文件后不累计其旧派生事实。所有时间范围从同一份去重调用集合产生。

文件读取固定开始时的字节上限，解码流同时生成完整前缀摘要；发布文件索引前再核实当前文件身份、长度及同一前缀。上限之后的追加进入下次读取，已读取前缀的改写或截断仍拒绝该文件的结果。整体来源修订仅决定能否发布可复用的汇总缓存，不再要求活跃会话停止写入才能返回结果；来源继续变化时交付本次已核实的调用集合，并由后端安排较短的前台重读。半条尾记录与单个不可读来源保留覆盖说明，不能升级为全部汇总失败。

同一前缀读取器由 `read_index/prefix.rs` 拥有，元信息发现和用量解码共同使用其字节上限、摘要及校验，不各自维护另一套容忍追加的规则。身份与元信息通过 `ReadIndex::file_prefix` 索引，避免会话发现先因正常追加而丢掉整条会话；两次发现得到的会话身份必须一致。分页消息和不可变转换材料仍使用要求完整修订一致的 `file` 索引，不能把不同一致性要求混成自动回退。

Claude 保留库也以读取开始时的字节上限解析元信息和保存原始记录，两次读取的完整摘要必须一致，并用同一个前缀校验器核实原文件未替换、截断或改写。正常追加发布本次已核实范围，下次同步补读；附件集合仍独立严格校验。不再要求整个活动文件的修改时间保持不变，也不无限追读新尾部；不改变保留库结构或改回原件读取，不留下第二套用量来源。

后端串行合并同类索引建设，短事务发布派生结果；不同领域的文件解析不持有共同写事务。每个会话只保留最近一次正文搜索的命中位置与摘要，翻页不重读正文；不同搜索和来源修订替换该派生项。用量进入页面和刷新定时器只有一个调度所有者；过期请求不追加独立全量扫描。消耗统计唯一的读取 effect 在启动时直接以 `forceRefresh: true` 排队读取，统一覆盖首次进入、切回消耗页签、窗口恢复可见、切换日期范围和手动刷新；不维护额外的刷新意图标记，也不依赖多个 effect 的执行顺序。强制刷新绕过汇总快照，但仍复用未变化来源的调用索引和同一调用集合。定时读取遵循后端 `refreshAfter`，失败仍按既有间隔重试，两者允许复用后端校验有效的快照。同范围刷新保留上次结果，查询身份变化立即隐藏另一条件的旧结果。

Claude 的应用保留库通过同一读取所有者交付按修订校验的原始字节范围。消息索引保持原始位置与前缀身份；用量验证已保留字节的完整旧前缀后只解码新增范围，不因为原件消失改回原文件读取。保留库中的完整正文属于会话保留事实，本索引仍不保存第二份全文。

## Alternatives considered

- 进入时允许复用有效期内的快照可以减少汇总工作，但无法保证每次进入都完成一次当前汇总；因此进入、范围切换与手动刷新使用同一强制路径，未变化文件仍复用索引。用额外 effect 标记进入可以保留范围切换时的汇总快照，但需要刷新意图与修订号两套状态，并依赖 effect 顺序；统一读取启动策略更直接，因此删除标记与辅助 effect。
- 延长整体快照有效期改动最少且可降低扫描频率，但日期范围、消息页和单条正文仍需重复全量解析，因此不采用。
- 把所有正文复制进全文数据库可以直接查询且便于 SQL 分页，但会复制 GB 级客户端内容并扩大派生存储；位置索引与按需原文读取足以覆盖当前瓶颈，因此不采用。
- 为追加文件只检查大小、时间或首尾样本最省 I/O，但无法排除前缀改写后继续追加，会让旧锚点或用量跨代，因此验证完整旧前缀。
- 修改原始消息身份为偏移量更容易持久化追加游标，但会破坏已有定位语义和收藏回链；保持现行身份，改变的文件只重建自己的消息位置。

## Consequences

- 未变化来源不重复解析正文；客户端筛选不解析其他客户端正文。
- 消息页仅读取该页消息；单条正文不线性遍历同一会话；原生条目更新与追加能使相应索引失效。
- 改写、截断、替换、删除、尾行续写及来源目录变更不复用错误计量或锚点。
- 用量范围切换复用同一调用事实，保持续接、检查点和供应商片段的去重与覆盖诊断。
- 移除旧整体 JSON 缓存、重复定时调度及被替代的生产扫描入口，保留现行有界阅读与原文导出。

首次建立某个来源或大消息索引仍需读取该来源。改变的原始文件重建自身消息位置，追加用量仍需顺序读取旧字节验证前缀；这两项成本不会伪装为常数时间。索引增加位置、最近搜索摘要和计量数据的磁盘占用。

每次重新进入消耗统计或切换日期范围都会重新汇总，频繁进出或切换增加汇总成本；未变化调用仍来自同一索引，不增加并行读取器，也不改变其他用量页签的操作。

## Verification

2026-10-26 按用户明确授权执行 Windows 隔离 CI，51 项前端测试、774 项 Rust 测试、类型检查及生产构建通过。新增回归验证固定字节范围、发现阶段持续追加、Claude 保留层持续追加、旧前缀改写与截断、补读去重，以及变化中的全局来源不写入稳定缓存。所有客户端与应用目录均在隔离路径，不改真实历史、配置或凭据。以下保留此前的浏览器及原生接口验证边界。

独立应用标识的当前原生后端接入两条隔离会话，Codex 与 Claude 同时每 2ms 追加进度记录，连续八次强制汇总均为预期 43 tokens，发现两条会话且无来源问题；实际 React 页面显示 Codex 13、Claude 30、合计 43。额度总览使用同一原生后端与隔离 HTTP 服务，验证两客户端的不同单位、真实零余额、未配置未知、批量刷新、503 失败保留旧读数及逐项重试清除错误。额度错误只由后端缓存拥有，不保留会在逐项恢复后过时的批量失败计数。

隔离目录内的相关回归已执行：Rust 会话 84 项、模型用量 18 项、计量存储 5 项、编译阻塞涉及的检测历史 14 项及前端单元 13 项全部通过，前端类型检查通过。测试专用的线程局部解码计数约束热消息页只解码本页、单条正文只解码一条、追加用量只解码新增记录、搜索翻页不重读正文；没有把测试计数引入生产状态。

实际 React Hook 的 6 个浏览器白盒场景验证单次进入、前台期限、隐藏后重入、连续刷新、快速切换范围、过期响应和失败重试。独立应用标识的原生后端通过 14 个黑盒场景，覆盖四个范围、8 个并发强制刷新、文件追加与重放、前缀改写、截断、半行续写、删除、原件消失、原生消息更新、错误契约及进程重启。完整浏览器页面的 4 个黑盒场景验证原生正文、保留记录、6000 条历史中的搜索定位、范围切换与单次手动刷新；用量页面显示预期的 53 tokens，浏览器没有错误。

6000 条合成消息的单次实际接口测量为：首次建立索引并读取第一页 1170.06 ms，热索引第二页 64.13 ms。这是当前实现的沙箱样本，不代表与旧版本的对比，也不能代替 GB 级真实历史测量。测试使用独立客户端、应用和浏览器目录，原生历史在刻意更新测试夹具之前验证只读。结果和截图位于 `.tmp/session-usage-verification-URtQx3/`。笔记结构门禁、差异空白检查及新增模块路径检查已通过；尚未进行安装后桌面界面或真实用户历史的性能验收。
