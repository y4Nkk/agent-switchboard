# Agent Note: 连续原生玻璃外框与固定圆角工作区

Status: implemented

## Problem

顶栏与侧栏各自绘制网页毛玻璃，交接处呈现不同背景；主窗口不透明，侧栏背后只有纯色，不能显示桌面背景的系统模糊。页面满铺窗口、依靠 padding 预留导航空间，滚动后内容进入顶栏下方。用户明确要求连续的玻璃外框、参考桌面应用的内嵌圆角，以及所有界面始终在固定区域内显示。

## Decision

AppShell 使用两行两列 grid：导航跨两行，顶栏占右上，工作区占右下。224px/56px 导航宽度、64px 顶栏高度及 400ms 动画沿用 tokens.css；只有 grid 列宽负责宽度动画，导航项直接从父级可用宽度扣除横向留白，文字以 flex 接收剩余空间，不再独立过渡宽度或借用行高计算宽度。侧栏和顶栏没有独立底色、模糊、分隔线或覆盖定位，共享 `.asb-shell` 的一层半透明材质。悬停统一使用 chrome-hover 透明叠色，删除旧 sidebar-bg、sidebar-hover 与更新标记的重复表面染色；标题栏信息弹层的高度预算来自 titlebar-height。

主窗口通过现有 Tauri windowEffects 配置启用透明窗口与透明 WebView 背景，Windows 使用 Acrylic，macOS 使用 UnderWindowBackground。系统合成器拥有桌面背景模糊，tokens.css 只拥有深浅模式的表面染色；删除网页 chrome-blur token 及侧栏/顶栏的 backdrop-filter，不引入第二个材质实现或新依赖。

原生主题也由现有 AppSettings.theme 唯一驱动：apply_desktop_settings 在其他可失败的桌面偏好应用成功后，以 Tauri 应用级 set_theme 设置 Light、Dark 或跟随系统的 None。启动、保存、修复与保存失败回滚共用这一入口；应用级主题同时作用于当前窗口及随后创建的托盘窗口，不增加前端 IPC、主题缓存、系统主题监听器或第二个设置字段。

`.asb-workspace` 是全部一级与二级界面的唯一边界：实体背景、28px 圆角、右侧与底部 4px 外框露边及 overflow 裁切。`.asb-main` 只拥有工作区内 16px 留白、滚动和焦点滚动余量，不再计算顶栏或导航占位。编辑器、扩展库和会话保持自己的受限滚动，备份历史按其现行契约随页面滚动；固定头尾始终在工作区内，不改为 sticky，也不新增测量头尾高度的路径。启动画面独立拥有实体底色。

品牌、全局信息、置顶、窗口按钮、拖拽区、导航项和页面保活继续由现有组件拥有；可用更新入口不占标题栏，常驻在侧边栏 footer 设置项上方，复用导航条目几何与共享图标轴线：空闲为中性色、点击发起手动检查（失败走全局错误报告），检查中换旋转图标并禁用，发现新版本时转绿、绿色角标固定叠在图标右上角以在收起轨宽内保持可见，点击进入设置页的发布区；microsoftStore 渠道的检查动作改为仅进入设置页，与商店管理更新的既有契约一致；不增加持久化设置或配置写入。侧边栏列表行的几何由行自己拥有：行内边距承担轨宽留白，`minmax(0, 1fr)` 轨道不随内容生长，共享 Tooltip 锚点按 stretch 拉伸、条目按钮以 100% 宽度填满——百分比宽度不再穿过可收缩的提示锚点解析，收起轨宽下条目收缩到 40px 而非溢出。导航项图标内边距由收起轨宽、条目留白及图标尺寸推导，图标中心在展开和收起时均与顶部收起按钮共用同一轴线。

## Related decisions

- [标题栏信息](../../implemented/feature/2026-10-12-titlebar-information.md)和[图标状态](../../implemented/feature/2026-10-12-sidebar-icon-states.md)继续拥有各自内容；其他命中笔记不涉及外框材质或几何。

## Alternatives considered

- 保留两个网页 backdrop-filter，并匹配颜色：无需透明窗口，能模糊应用内滚动内容；但两个采样区域不能构成同一材质，纵向滚动的侧栏没有背景可模糊，还保留用户明确反对的内容穿越。
- 一个 L 形网页模糊遮罩加满铺画布：能消除接缝并集中模糊所有权；但仍以内容被顶栏覆盖为前提，不满足固定圆角工作区。
- 原生材质加实体圆角工作区：此前被否决的最强原因是窗口透明会改变整窗合成，且无法模糊应用内滚动内容；当前用户明确要求系统毛玻璃并禁止内容从顶栏下方经过，因此桌面背景模糊成为正确对象，实体工作区隔离正文。
- 把全部受限滚动页改成 sticky：可以统一滚动实现；但短内容页底栏不再恒定贴底，补救需要绝对定位与高度测量。本方案保留现有固定头尾和页内滚动。
- 为玻璃单独维护主题状态并逐窗同步：可分别控制每个原生窗；但主题已是应用级设置，Tauri 应用主题支持现有及随后创建的窗口，第二个状态和监听器会重复已有所有权。

## Consequences

- 收益：一个原生材质与一次表面染色拥有整个外框；工作区几何、圆角与裁切由共享壳拥有，全部页面自然处于顶栏下方和导航右侧，滚动无需靠 padding 避让。
- 删除独立 backdrop-filter、chrome-blur token、全窗口工作区覆盖定位、导航占位 padding 及过时的滚动穿越契约；没有保留旧路径或增加持久化字段。
- 代价：原生材质受操作系统版本、透明效果设置及合成器控制；Tauri 在 Linux 不提供相应系统模糊，不新增伪造或兼容路径。旧 Windows 版本的 Acrylic 拖拽/缩放性能由原生实现决定。

## Verification

隔离静态模拟页直接加载当前源 CSS。1280×720 下导航收起为 56px、展开为 224px，工作区左缘与导航右缘一致、上缘与顶栏底缘均为 64px；长页面滚动 1440px 后几何不变，顶栏命中仍为顶栏，圆角缺口不命中工作区。深色与展开导航正常；模拟编辑器模块滚动 1440px、外层 scrollTop 为 0，固定页头与底栏仍在工作区内。125% 缩放下顶栏底缘与工作区上缘同为 80px，固定底栏没有越出边界。

最初沙箱内预览服务无法被浏览器访问；改为仅绑定本机回环地址、只提供模拟页面和项目样式的沙箱外服务后完成上述检查。静态模拟只证明几何、裁切与共享染色，不证明真实业务页交互、系统背景模糊、原生拖拽或窗口控件行为。最新授权构建完成前端类型检查、生产构建、Rust release 编译和 Windows 安装器编译；自动化测试与真实窗口验收没有执行。

五份受影响样式通过 PostCSS 语法解析，主窗口 JSON 可读取，透明窗口、WebView 背景及原生效果名称均存在于已安装 Tauri 配置 schema。辅助配置检索首次误用 anyOf 未完成，改为 schema 实际使用的 oneOf 后重跑通过；这不是应用编译证据。差异空白与残留引用检查通过，verify-notes 校验 34 篇活跃笔记和 3 篇归档通过。归档首次受沙箱写保护阻止，在授权的同一精确目标上重跑归档脚本成功，既有归档摘要保留。

收敛后的模拟预览确认导航图标与顶部收起按钮中心 X 均为 28px；条目计算样式仅过渡 background-color、color、gap，文字仅过渡 opacity。展开过程中导航项宽度始终等于父级轨宽减去 16px 留白，工作区左缘与轨宽同步，随后截图显示完整展开及圆角边界。预览首次连接超时，重新获取同一浏览器的新标签后完成上述检查；后续主题点击因浏览器控制通道的 CDP 输入超时未完成，不能作为新一轮主题行为验收。未改动的深浅染色与固定区域滚动沿用前述有效预览证据。原生主题的 Tauri/tao 接口、启动、保存、修复与回滚调用链经源码核对且通过原生发布编译，实机切换仍未验收。

Windows 0.3.3 x64 安装包来自隔离快照中的 1,203 个构建输入，固定 Node.js 22.23.2；快照核对只发现生成图标与 Cargo 对既有 windows 依赖限定名的等价归一化，没有改变依赖版本或混入后续源码编辑。准备快照时曾误复制历史编译缓存，中止并仅删除快照内副本后重跑成功，原项目缓存与用户改动保留。安装包的版本、品牌图标、背景和内嵌安装引擎核对通过。首次直接比较编译程序与安装内容的哈希不一致，逐字节核对只相差 Tauri NSIS 渠道标记的 3 个字节；仅在校验内存中应用这一已确认标记后，完整文件哈希一致，未修改编译程序或安装包。交付文件为 `.tmp/native-glass-package/Agent Switchboard_0.3.3_x64-setup.exe`，23,414,272 字节，SHA-256 `E3E7795244544B95B5663114D163AFDC5354628D7E2B2A502CDA1AA6FF2D399F`；没有执行安装器或写入真实用户配置。
