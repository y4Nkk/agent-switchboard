# Agent Note: 本地资源的有界读取与显式回收

Status: implemented

## Problem

会话与收藏将完整正文跨 IPC 传入长期挂载的工作区；日志在全量解析后才截取 500 条。WebView 的网页和代码缓存没有应用层回收边界。请求账本、配置历史和可恢复备份的业务含义不同，不能通过统一删除历史来压低磁盘占用。前端字体同时打包三字重的 WOFF 与 WOFF2。

## Decision

会话完整性由[完整本地会话与用量契约](2026-10-16-complete-local-session-usage.md)接管，本篇继续拥有有界传输及显式维护。共享读取器覆盖原生历史与 JSONL；JSONL 解码器拥有原始记录的前缀身份，Codex 原生消息由原生 item 身份及内容摘要拥有。生产读取逐条访问消息，搜索和导出不积累全文。原始 JSONL 消息身份校验完整源前缀；追加不改变旧身份，编辑前缀使旧定位明确失效。单条记录上限为 32 MiB；[会话读取索引](./2026-10-22-incremental-session-read-index.md)接管按来源修订复用位置、消息建设门禁和当前页解码，替代原始 JSONL 的全局解析锁。详情每页 25 条摘要、每条最多 1200 字符，正文每页 16384 个 Unicode 字符。长正文以原文分页阅读，完整导出流式写入用户选定文件；完整复制只在明确操作时临时读取单条正文，不写入 React 长期状态。

隐藏会话页释放正文与列表，保留选择、当前消息页、展开状态、正文页码、滚动位置和编辑状态。正文位置仅保存当前 25 条消息的标量信息。收藏每页 50 条，在后端过滤并返回摘要，正文使用相同的有界内容页契约。搜索匹配流式归一化空白与大小写，再映射回原文字符位置，直接打开命中正文页。收藏库损坏不阻止会话阅读，收藏状态明确为未知并报告错误。

详情、收藏、正文与用量读取共用 `src/hooks/use-read-queue.ts` 的同一有界队列机制，每个读取所有者最多持有一个执行中任务和一个最新待执行任务；新请求直接替换未执行任务，隐藏或卸载移除待执行任务。已经发出的原生读取完成当前操作，迟到结果由当前请求生命周期拒绝，不能写回已失效页面。会话搜索使用[可取消搜索任务](../bug-fix/2026-10-23-session-search-lifecycle.md)，替换、隐藏和卸载取消旧任务，进度由后端实际处理数量拥有，不再经过只能等待旧任务完成的前端队列。消息定位只由详情状态中的 target 拥有，正文展开集合只表达展开状态，不再保存同步维护的 focused 副本。

日志流式读取，按当前级别筛选后再保留最新候选，候选始终最多 500 条，完整匹配数量及跳过行数同时返回。单行最多 16 KiB；超长或无效日志行不进入候选。字体生成脚本唯一维护现有三字重、完整 unicode-range 的 WOFF2 样式，主窗口与托盘共同消费，前端开发和构建入口先同步样式。

存储维护拥有应用数据的容量统计、可重建 WebView 缓存回收和历史归档。Windows 启动时及每 5 分钟检查网页和代码缓存，超过 64 MiB 时通过正式 WebView2 Profile2 磁盘缓存接口回收；手动清理走同一单任务执行器。超时报告后台仍在进行，不启动第二次清理。该数字是维护阈值，不是硬上限，不清除登录与偏好。

历史回收先生成内容摘要计划，再将完整记录流式导出到应用数据目录之外的 `.jsonl.gz`，同步落盘后才回收与计划匹配的历史。配置历史仍使用唯一的现行 JSON 文件契约，以流式读取和原子替换消除日常全量数组。配置写入门禁与 SQLite 写事务分别保护各自持久化所有者；并发变化拒绝过期计划，后续部分失败保留归档并逐项报告。当前 UTC 计费月份、运行中的检测、各客户端最新配置恢复记录及全部文件备份受到保护。SQLite 删除提交后按空闲页比例压缩，压缩失败不会把已成功删除误报为未删除。应用启动和维护均使用同一目录所有者，不访问客户端凭据或会话文件进行清理。

归档内容先同步文件，再发布最终文件名：Windows 使用带 WRITE_THROUGH 的原生移动操作，其他桌面平台在原子改名后同步父目录。持久化未确认时停止历史回收。配置恢复保护的是最新写入事实的位置，同一备份被反复恢复不会让全部旧记录永久受到保护。

相邻决定的原有职责继续成立：[工作区状态与生命周期](../../implemented/architecture/2026-10-13-desktop-workspace-uiux.md) 保留草稿与导航状态，本篇收窄大正文的挂载寿命；[本地构建缓存保留边界](../../implemented/process/2026-09-24-local-build-cache-retention.md) 仍只管理开发产物，本篇管理运行数据。两个旧决定部分重叠，均不归档。

## Alternatives considered

- 只加虚拟滚动能减少 DOM，并保留整篇 Markdown 的格式；但后端向量、IPC 和前端正文仍随全文增长，因此同时替换读取契约。
- Promise 链可以串行请求并在执行前跳过过期任务，接入最少；但慢读取期间仍持有所有排队闭包，因此改为一个待执行槽，直接释放被替换任务的引用。
- 设置默认历史天数并自动删除最容易形成磁盘硬上限；但会丢失用户计费记录或破坏恢复链，因此历史采用显式、先归档后回收的流程。
- 直接删除整个 WebView 资料目录能回收最多空间；但会覆盖浏览器持久状态，因此只回收可重建缓存。
- Chromium 启动标志可以直接请求缓存大小，接入成本低；但 WebView2 将这些标志定位为开发诊断功能，因此生产使用正式缓存维护接口，接受检查间隔内的增长。
- 将配置历史整体改为 SQLite 能直接追加与索引查询；但现有升级、修复和配置快照共同拥有当前 JSON 契约，此次内存问题可以用逐条解析与原子重写解决，无需增加格式迁移和第二个存储所有者。
- 字体改成系统字体最省包体；但会改变既定排版和离线覆盖，因此保留现有家族、字重和字符范围，仅移除重复格式。

## Consequences

- 生产路径删除会话全文数组、收藏全文列表 IPC 及旧入口，不保留别名或双读。搜索、定位、收藏、复制、导出使用同一来源读取器；原始文件按来源修订建立小型位置索引，消息页和单条正文直接读取所需记录；原生历史在只读事务中按条目更新序号复用位置，不积累全文。额度历史的 720 点限制只约束图表传输，完整保留契约由新篇拥有。
- 正文页跨 Markdown 边界时按原文展示，完整复制及导出保留原始内容。每条记录的资源上限会明确拒绝超大记录，不会静默截断或换用旧读取路径。
- 历史采用显式归档，仍会随使用增长；只有可重建缓存自动回收。业务恢复和计费的可用性优先于强制磁盘硬上限。
- 字体只保留一种受当前桌面运行时支持的格式。实际安装包缩减取决于下一次构建与压缩，已有发布产物不会被此次源码修改替换。
- 新增测试覆盖消息页与锚点、Unicode/NUL 正文、深层搜索位置、流式日志、历史变化及数据库空间回收。读取队列覆盖慢任务期间 1000 次请求只执行最新项、过期取消不移除新任务、待执行任务取消与失败后继续处理。按 AGENTS.md，本任务不执行编译、类型检查或自动化测试；结构门禁、差异与引用检查不能替代桌面运行、内存采样或打包验收。
