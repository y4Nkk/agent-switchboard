# Agent Note: 二级工作区按操作用途选择滚动布局

Status: implemented

## Problem

编辑供应商需要在长表单的任意位置切换分区和保存。标题、页签及正文之间的留白重复占用可用高度。导入与导出供应商及检测历史使用同一个固定页头的框架，但主要按页面顺序阅读和操作，无需为页头持续预留空间。

## Decision

`WorkspaceSubpage` 拥有二级页的页头、焦点与滚动视口。供应商编辑、用量查询、MCP 表单与向导、Skill 编辑及扫描已有扩展明确选择 `fixed-actions` 并提供提交栏。标题及页签固定在顶部，操作固定在底部，中间的视口承载各模块。标题与页签之间用 8px 间距，操作区也使用 8px 上留白，所有按钮沿用各自既有尺寸。

导入与导出供应商、检测历史选择 `page`。返回按钮、标题、来源页签或运行状态和正文进入同一个 `ScrollArea`。检测历史关闭时保留业务会话，重新打开时重建页面表面。列表与详情互换时将所属视口复位到页首，并聚焦标题。供应商分区的阅读位置仍归供应商编辑会话管理。

可见的二级页占满工作区，外层视口停止滚动。判定排除 `hidden` 元素及其后代，隐藏的扩展库及市场也释放外层边界。扩展库、会话列表、托盘和应用弹窗继续使用各自的有界视口。

## Related decisions

- [桌面工作区](2026-10-13-desktop-workspace-uiux.md)和[原生外框](2026-10-14-unified-native-glass-shell.md)继续拥有导航、窗口裁切、焦点和草稿的整体契约。本篇限定二级页使用固定头尾的条件。
- [表格滚动所有权](2026-10-16-table-scroll-ownership.md)和[返回顶部](../feature/2026-10-16-global-back-to-top.md)继续拥有各自的滚动实现。表格可随二级页自然展开，二级页统一由现有视口提供返回顶部。
- [供应商编辑会话](2026-11-13-provider-routing-editor-integration.md)接管旧运行参数独立页和返回触发按钮的读位逻辑。视口引用仍由业务会话提供，工作区框架只透传实际滚动元素。复位依据是业务分区或列表与详情的切换，标题文本变化与滚动位置无关。

## Alternatives considered

- 全部整页滚动能给正文留出最多空间，几个分区之间来回编辑时会反复寻找页签和保存入口，扩展扫描也会失去随手可达的批量提交。
- 全部固定页头可以让返回始终可见，浏览型页面会为页头持续预留空间。
- 直接用主工作区视口滚动浏览页可省去二级页视口，但入口列表和历史详情会共用滚动位置，返回顶部和读位复位也会依赖外层导航。

## Consequences

固定操作页释放正文空间，浏览页可以让页头滚出视野，返回时使用视口的返回顶部入口。检测历史从各层页首开始，筛选、页码和详情身份继续由历史会话保留。所有直接消费者使用同一个组件，旧编辑框架、路由样式和隐式的无底栏布局均已移除。

## Verification

在隔离的浏览器模拟页中使用当前源样式和两种二级页结构。固定操作页滚动 720px 时页头、页签和底栏的位置相同，整页滚动的页头、页签和正文同步移动 720px。窄工作区和扩展入口保有固定操作；另一个工作区的隐藏子页未阻止主视口滚动。该预览覆盖布局及裁切，React 业务交互与原生窗口没有在预览中运行。
