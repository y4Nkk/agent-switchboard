# Agent Note: 二级工作区按操作用途选择滚动布局

Status: implemented

## Problem

长表单需要在阅读和编辑过程中持续提供提交入口。供应商编辑在滚动正文时仍为标题与页签保留高度，短窗口留给字段的空间受限。导入与导出供应商及检测历史主要按页面顺序阅读和操作。

## Decision

`WorkspaceSubpage` 拥有二级页的页头、焦点与滚动视口。用量查询、MCP 表单与向导、Skill 编辑及扫描已有扩展选择 `fixed-actions` 并提供提交栏。标题及页签固定在顶部，操作固定在底部，中间的视口承载各模块。标题与页签之间用 8px 间距，操作区也使用 8px 上留白，所有按钮沿用各自既有尺寸。

Codex 与 Claude 的供应商新建和编辑通过 `ProviderEditorFrame` 选择 `floating-actions`。返回按钮、标题、页签与正文共用一个 `ScrollArea`。取消与保存复用客户端配置的悬浮操作布局。胶囊按钮在视口右下与返回顶部并排，空间不足时可换行，操作组的实际高度在内容末尾自然占位。主动选择页签时显示分区顶部，字段校验及用途定位的滚动继续由供应商编辑会话管理。

导入与导出供应商、检测历史选择 `page`。返回按钮、标题、来源页签或运行状态和正文进入同一个 `ScrollArea`。检测历史关闭时保留业务会话，重新打开时重建页面表面。列表与详情互换时将所属视口复位到页首，并聚焦标题。

可见的二级页占满工作区，外层视口停止滚动。判定排除 `hidden` 元素及其后代，隐藏的扩展库及市场也释放外层边界。扩展库、会话列表、托盘和应用弹窗继续使用各自的有界视口。

- [表格滚动所有权](2026-10-16-table-scroll-ownership.md)和[返回顶部](../feature/2026-10-16-global-back-to-top.md)继续拥有各自的滚动实现。表格可随二级页自然展开，二级页统一由现有视口提供返回顶部。

## Alternatives considered

- 全部整页滚动能给正文留出最多空间，几个分区之间来回编辑时会反复寻找页签和保存入口，扩展扫描也会失去随手可达的批量提交。
- 全部固定页头可以让返回始终可见，浏览型页面会为页头持续预留空间。
- 在视口外保留独立底栏可以始终隔开字段与操作，代价是持续占用正文高度。直接绝对定位按钮能腾出这部分空间，但会盖住滚到底部时的字段。视口内粘附的操作组在滚动时悬浮，末尾按实际高度留出完整空间。
- 直接用主工作区视口滚动浏览页可省去二级页视口，但入口列表和历史详情会共用滚动位置，返回顶部和读位复位也会依赖外层导航。

## Consequences

供应商编辑向下滚动后获得完整的表单视口高度，底部操作始终可达。改变分区或返回时先通过所属视口的返回顶部入口到达页头。检测历史从各层页首开始，筛选、页码和详情身份继续由历史会话保留。所有直接消费者使用同一个组件，旧编辑框架、路由样式和隐式的无底栏布局均已移除。

## Verification

共享框架初次落地时，隔离预览显示固定操作页滚动 720px 时页头、页签和底栏的位置相同，整页布局的页头、页签和正文同步移动 720px。窄工作区和扩展入口保有固定操作，隐藏子页释放主视口。

供应商悬浮布局使用项目样式和示例字段预览。滚动中和滚动到底时操作按钮与返回顶部底边对齐，最后一个字段可以完整显示。React 业务交互和原生窗口待验收。
