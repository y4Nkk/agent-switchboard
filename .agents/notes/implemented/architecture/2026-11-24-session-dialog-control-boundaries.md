# Agent Note: 会话弹窗控件与状态的归属

Status: implemented

## Problem

会话弹窗的下拉列表和日历各自寻找挂载容器。下拉框的非受控打开回调可能晚于首次弹层挂载，也缺少与外层弹窗的关闭协调。日期筛选保存未生效的日期输入，按日期处理会读到它。批量勾选由删除状态维护，翻页期间列表结果退场时分页控件也随之卸载。

## Decision

AppDialog 通过上下文提供字段弹层的挂载位置和暂停状态。Select 以受控打开状态同时提交容器与可见性。Radix 的外部指针按下早于 React Aria 的外部点击完成，所以下拉打开期间暂缓外层关闭，关闭或卸载时释放。DatePicker 使用同一挂载位置，沿用 React Aria 的弹层顺序。

会话搜索持有已生效的日期条件。反向日期只作为筛选弹窗内的草稿，关闭或切换预设时丢弃。会话筛选和按日期处理共用起止字段与 Checkbox，范围操作从已生效条件取初始日期。

批量勾选状态由 useSessionSelection 按会话身份管理，删除执行器只持有待确认的目标快照和结果。批量弹窗统一承载当前子弹窗，确认取消后保留批量勾选，成功删除的会话移出勾选。列表只显示当前页结果，分页和总数在同一查询内保持可见。

## Related decisions

- [会话批量操作弹窗](../feature/2026-11-24-session-batch-dialog.md)拥有入口、布局和批量行为，本篇明确选择、确认和分页的状态归属。
- [会话即时搜索](../feature/2026-11-24-live-session-search.md)拥有查询触发和筛选入口，本篇隔离无效日期草稿。
- [共享 DatePicker](2026-10-15-global-date-picker-primitive.md)拥有日历交互，本篇明确共享的弹层容器。

## Alternatives considered

- 让各控件继续从触发器查找最近的对话框，可以省去组件间的显式接线。下拉首次挂载和外层关闭仍缺少统一时序。
- 把所有弹层迁成同一个库，可以直接复用关闭顺序。共享 Select 已有多处消费者，此次可以沿着现有 API 完成挂载与关闭协调。
- 翻页时保留整页旧结果，可以保持布局完整。旧会话行会继续出现在新页码下，批量操作应只取当前页的真实结果。

## Consequences

- 字段弹层在首次打开时进入当前 AppDialog 的焦点边界。普通页面上的字段弹层使用库默认容器。
- 翻页加载时保持导航，当前页会话仍随新结果到达后显示。关闭筛选弹窗会放弃未生效的日期输入。
- 结构、旧引用和语法可通过静态检查。真实桌面的键盘焦点、遮罩手势和弹层定位仍需运行验收。
