# Agent Note: 更新完成后确认重启

Status: implemented

## Problem

应用内更新成功后立即重启，Windows 更新安装器也会在引擎完成后自动打开应用并关闭窗口。用户没有机会先完成正在处理的内容；只修改前端不能覆盖 Windows，因为 Tauri updater 2.11.0 在启动安装器后直接退出应用。

## Decision

安装完成只进入等待确认状态。macOS/Linux 的应用级更新所有者打开共享 ConfirmSheet，支持「稍后」「立即重启」，稍后不清除已安装结果；关于页的重启入口重新打开同一确认。确认后才调用原生重启命令，失败保留弹窗与完整诊断并允许重试，执行中禁止重复确认和关闭。

是否安装成功只认原生任务的 installed 阶段，删除独立的 restartRequired 布尔值；快照、检查与下载门禁、重启按钮及夹具都消费同一事实。请求打开确认命名为 requestRestart / onRequestRestart，实际重启只从 confirmRestart 进入，不保留旧动作别名。弹窗暂停既隐藏界面，也禁止 Escape、外部点击及关闭回调，嵌套暂停继承祖先状态。

Windows 由现有安装器完成窗口承载同一确认语义：首次安装提供「打开应用」「稍后」，更新提供「立即重启」「稍后」，默认焦点停在稍后；引擎只执行安装，确认按钮才用原调用参数启动应用。每次安装或更新成功都等待本次选择，不保存跳过确认的标记。完成面消费本次已验证 InstallationRequest 的 Update 字段，应用内更新与手动覆盖安装共用确认。删除引擎的自动启动、LaunchError 返回值、自动关窗、StartsImmediately 与 RestartAfterInstall 派生属性，并删除默认勾选启动的复选框、完成按钮间接启动分支和对应样式，保留当前 /P /UPDATE /R /ARGS 调用协议。

安装器的单一视图状态明确区分等待启动、启动中和启动失败。主动作按状态分派：安装失败重试安装，启动失败只重试打开；启动期间禁止关闭和重复执行。失败保留原始异常、内部原因和引擎返回代码，并在原安装器诊断区展示和复制，不通过取消复选框改变下一次按钮含义。

安装执行与位置查询分别位于 InstallerEngine.cs 和同一 partial 类的 InstallerInstallationLookup.cs，每个源文件均不超过 500 行，不增加运行层级或改变查询行为。

## Alternatives considered

- 仅去掉前端的自动 relaunch，代码最少且覆盖 macOS/Linux；但 Windows 已退出前端，实际仍由安装器自动启动，无法完整实现。
- 在 Windows 完成窗口上再叠系统 MessageBox，能直接复用系统确认框；但会出现两个完成表面，失败重试和关闭焦点也需要额外协调。直接让现有完成窗口成为确认面，复用其动作和诊断。
- 首次安装保留默认勾选打开应用并用完成按钮提交，符合常见安装器习惯；但启动失败后复选框变化会使同一按钮变成仅关闭，且与更新完成页形成两套启动规则，因此统一为显式的打开与稍后选择。

## Consequences

- 安装成功不会直接调用重启或启动应用；取消确认保留真实安装结果。
- 两端确认入口都支持延后、显式确认和失败重试，保留原始诊断与重启参数。
- 中英文说明、README、DESIGN 与更新日志同步，不再承诺自动重启。
- 确认状态由应用级更新 hook 唯一拥有，关闭确认不释放更新任务；已有业务弹窗通过共享 AppDialogSuspension 保持状态但暂停交互，嵌套暂停继承祖先状态，局部解除不能恢复被全局暂停的弹窗。
- 收益是由用户决定启动时机；代价是安装结束后多一次确认，Windows 无法继续使用已经退出的旧应用。
