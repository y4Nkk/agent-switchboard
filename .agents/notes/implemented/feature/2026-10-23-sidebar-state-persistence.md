# Agent Note: 侧栏展开状态独立持久化

Status: implemented

## Problem

侧栏展开与收起只保存在 AppShell 的组件状态，重启后始终展开。用户要求恢复上次状态，同时删除相关旧契约和兼容路径。应用偏好采用完整快照保存，直接混入频繁变化的工作区位置会让陈旧偏好快照覆盖新的界面状态。

## Decision

LocalState 唯一拥有 `state/sidebar-collapsed.json`，内容只接受 JSON 布尔值；文件不存在表示首次使用，默认展开且读取不创建文件。命令只暴露布尔读取和写入，原生及浏览器开发桥调用同一实现。文件写入同步临时文件后原子替换，不接受对象、字符串或旧设置字段。

应用级 useSidebarState 唯一拥有读取结果和保存中的状态，AppShell/SideNav 只渲染受控值。启动读取完成后才显示外框，成功保存才改变展开状态；同步防重入并在保存期间禁用按钮。读取失败保留原文件并报告具体错误，按钮改为重新读取，不把未知状态当作可写默认值。保存失败保留已确认的状态并报告错误，不排队延迟写入或退出时补存。

删除 AppShell 的窗口内 useState 和 SidebarEraSettings 的旧字段读取、丢弃与自动改写分支。AppSettings 不增加侧栏字段，不改变既有偏好快照；其他语言偏好的升级不属于本决定。

## Alternatives considered

- 在 AppSettings 重新添加 sidebarCollapsed：可以复用现有整份设置读写和启动屏障；但侧栏切换会触发桌面偏好应用，已打开的偏好草稿也可能覆盖较新的侧栏状态，还需要改变所有既有偏好文件的严格契约。
- 使用浏览器 localStorage：实现少、读取同步；但原生 WebView 与浏览器开发环境会产生不同存储来源，无法复用应用本地状态的文件与错误边界。
- 合并到新的完整工作区文件：可一次读取导航位置与侧栏状态；但需要替换现有 last-workspace-page.json 契约并处理多字段更新竞争，扩大本次范围。单一布尔文件沿用现有工作区位置与偏好分离的机制。

## Verification

- 新增隔离临时目录用例覆盖首次默认且不创建状态、两种状态在重建 LocalState 后恢复、偏好与页面写入不覆盖状态、非法记录保留、目录占位导致替换失败后清理临时文件，以及 Windows 文件锁导致保存失败后保留原状态。
- 旧偏好字段拒绝用例覆盖有、无 language 两种输入，要求读取和启动升级均失败且不改写原字节，不生成新侧栏状态记录。
- 已核查 App → AppShell → SideNav 的唯一受控链、启动等待、异步卸载防护、同步防重入、失败重读分支、原生命令注册、开发桥分派与中英文错误词条。
- 笔记树、格式与归档封印校验通过（63 篇活跃笔记、8 篇归档）；差异格式检查通过。使用仓库已有 Rolldown 仅解析 9 个相关 TS/TSX 文件并核查本地导入、函数行数，15 个相关源文件未发现文件行数超限或冲突标记；没有执行转换或类型检查。这些结果仅证明静态范围。
- Windows 本地隔离 CI 的 723 项 Rust 测试全部通过，包含上述侧栏持久化、旧字段拒绝与文件锁用例；44 项前端测试、类型检查和生产构建通过。全部写入使用隔离临时目录；真实桌面退出重启和浏览器刷新尚未实测。

## Consequences

每次切换增加一次本地文件写入，布局切换需等待该次写入；只保留一个在途操作，保证界面所示已完成状态与落盘一致。损坏或不可读记录不会被默认值覆盖，重新读取前保持中性展开几何和明确的重读入口。旧偏好文件若携带已废弃 sidebarCollapsed 字段会被严格拒绝，保留原文件并沿用应用已有显式偏好修复入口，不迁移其值。
