# Agent Note: 标题栏统一全局信息

Status: implemented

## Problem

操作结果在左上角浮层显示，持续错误占用工作区顶部，处理中状态位于右下角。用户需要在不同位置寻找同一类全局反馈，并希望信息集中到窗口动作所在的标题栏。

## Decision

`GlobalInformation` 在标题栏的软件名后方统一消费既有通知队列、持续错误与 busy 状态。软件名「Agent Switchboard」位于左上应用标记右侧，由外壳拥有；消息槽可收缩，软件名与右侧窗口控件不收缩。标题栏保持固定高度，摘要右侧显示数量；点击摘要通过已有 React Aria Popover 展开完整信息与修复、关闭动作。持续错误优先，其次错误通知、忙碌状态、其他通知；未展示的通知暂停倒计时，展开、悬停、聚焦和窗口隐藏期间暂停倒计时。

通知队列和错误状态仍由各自当前所有者持有，组件只派生展示数据，不建立消息副本或持久历史。删除独立 Toaster 挂载、工作区 OperationNotices、右下角 busy 及其废弃样式。通知内容翻译辅助函数保留在独立模块并更新全部直接消费者。

会话与用量来源由[静默来源恢复](../bug-fix/2026-10-29-silent-session-source-recovery.md)接管，不再通过全局信息发布。`GlobalInformation` 继续拥有操作通知、持续设置错误和真实 busy 状态，通知计时与软件更新反馈保持原所有者；已删除无人使用的来源 Provider、确认状态与全局转换入口。

全局短暂通知支持逐条删除和「清空通知」，同步更新摘要及计数；持续设置错误、操作恢复错误与 busy 不纳入清空。通知删除复用原队列和计时器，清空后入口及键盘焦点保持稳定，不保存第二份历史。

[雷达后台检测通知](2026-10-23-probe-background-notifications.md)复用本篇的唯一信息入口与队列，并由任务全局所有者负责结束判定。通知生产者取得当前消息的关闭回调，使待保存错误在成功保存后从同一队列撤下。

软件更新反馈由 `useUpdateCheck` 统一产生：侧栏和设置页手动检查成功且 `checkUpdate()` 返回 `null` 时，发布一条 success 通知，标题复用 `backup.update.upToDate` 的结构化词条。成功结果先经过卸载判断并更新检查状态，再发布通知；失败沿用全局错误报告，不产生成功消息。内部检查来源只接受 `"manual" | "startup"`，手动入口固定传入 `"manual"`，启动入口固定传入 `"startup"`；成功和失败反馈都按同一来源判定，启动自动检查保持静默，删除布尔控制参数。`inFlight` 由检查所有者同步设置，同一时刻只发起一次检查；卸载后不发布检查结果或错误，迟到的新版本资源由同一所有者释放。提示直接由请求结果产生，不监听检查时间或更新状态，不在两个按钮中分别发送。通知沿用共享队列的默认计时、优先级和渲染时翻译。

检索命中的[桌面工作区笔记](../architecture/2026-10-13-desktop-workspace-uiux.md)只拥有外壳和侧栏，两篇互链；[导入导出文案笔记](../bug-fix/2026-09-24-provider-import-export-copy.md)仍拥有业务反馈含义，与本次展示位置无冲突。

## Alternatives considered

- 仅移动浮动通知到标题栏：改动最少且保留全部展示结构，但持续错误和忙碌状态仍分散，不满足统一集成。
- 在标题栏堆叠完整消息：无需展开即可阅读，但长诊断和多条反馈会改变标题栏高度，挤占内容和窗口动作区域。
- 分别在侧栏与设置页按钮发送更新结果：入口可直接控制反馈，但同一检查逻辑会分散到两个消费者；统一在 `useUpdateCheck` 的成功分支发送，保持结果语义只有一个所有者。
- 监听检查完成状态发送通知：可复用已有检查时间和结果状态，但启动检查也会更新这些状态，重新挂载还可能重复提示；直接按手动请求的成功结果发送，无需额外状态或去重机制。
- 仅用「已知晓」降低优先级：保留全部诊断方便复查，但无法让用户移除截图中的历史提示；删除与确认分别表示隐藏和保留复查，状态由同一个应用级来源所有者持有。

## Consequences

- 收益：全局反馈只有一个挂载点；修复回调、通知关闭与原队列上限保持有效。长消息在展开区域完整换行，列表有边界滚动；窗口动作不因消息出现而移动。翻译辅助模块的所有直接消费者同步迁移。
- 代价：完整详情增加一次展开操作；持续错误会暂停后排通知的倒计时，原通知队列仍只保留最多两条，不扩展为通知历史。
- 手动检查无更新时从任意页面都能得到完成反馈；启动检查不打扰用户。软件更新消息接受共享队列的两条上限和优先级，持续错误存在时需展开查看排后的成功提示。
- 短暂通知可逐条删除或一次清空；持续恢复错误与真实处理状态保留。删除和清空前通过引用把焦点交给收起按钮，清空后保留空态、入口和键盘焦点，沿用双语提示与可访问名称。
- 摘要与展开区通过原按钮和 React Aria 弹出层提供键盘操作；交互内容不标记为窗口拖拽目标，空白信息槽仍可拖动窗口。
- 验证范围为笔记结构、差异格式与直接引用检查；按项目要求不运行编译和自动化测试。原生窗口拖拽、窄窗布局、消息计时和焦点恢复仍需实际运行人工验收。

## Verification

`npm run verify-notes` 通过笔记树、格式和归档三项结构校验。差异格式、冲突标记与直接引用检查通过：侧栏和设置页共享手动检查入口，启动检查明确传入 `"startup"`；`reportFailure` 和布尔来源参数已移除，成功消息只在手动请求成功且返回 `null` 时发送，成功和失败反馈均受卸载判断保护。已沿本地安装的 Tauri updater 实现核查 `Update | null` 返回契约和异常传播，并核查两处按钮、API 包装、并发保护、资源释放、中英文词条、全局通知队列消费与计时路径。按项目规则未运行编译、类型检查或自动化测试，软件更新提示的实际桌面展示与计时仍需运行时验收。
