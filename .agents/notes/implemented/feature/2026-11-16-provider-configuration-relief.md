# Agent Note: 以预设和模型目录减轻供应商配置负担

Status: implemented

## Problem

供应商表单让用户重复选择客户端、声明供应商和模型两层能力，并为每个模型操作八档推理复选框。未知模型会被填入通用窗口和输出上限，掩盖缺失信息。完整显示高级设置的既有决定仍成立，减负必须减少人工判断而不是增加折叠。

## Decision

应用内置可追溯、生成的供应商与模型目录快照。准确匹配端点才补全该供应商的模型信息，不按同名模型跨中转站猜测。预设带入名称、官网、协议及已知参数；用户明确填写的配置保持优先。目录是新建时的输入建议，保存后的具体档案继续是运行时事实，不增加持久化第二来源或兼容格式。

移除表单内重复的客户端选择。新建保留明确的官方登录入口。模型目录使用结果表与直接编辑，选择主模型即建立目录条目。删除无依据的通用限制和全推理档位默认值。模型能力只有一处编辑，供应商同名总能力从模型条目汇总；独立协议操作和 Chat 转换配置保留真实含义，以值编辑取代复选矩阵。用途以表格展示现有去向，保留原生默认、Primary、固定供应商及 Fable 继承语义。运行参数完整显示当前值、来源及修改入口，不要求逐项选择模式。

共享一个草稿、一个保存入口，保存不启用。转换种子保留未知限制、能力审核及来源快照，不把新建目录建议自动套到转换或已有显式值上。模型目录读取、准备和保存的过期响应保护继续有效。

精准检索的其他协议、诊断、布局和资源笔记没有被本决定完全取代，不归档。

## Alternatives considered

- 只调整布局和默认值能保留全部已有契约且成本最低，但用户仍需维护两层能力与模型矩阵，不能满足减负目标。
- 实时拉取目录并自动探测可覆盖更多未知服务，但增加打开编辑器的联网依赖和可能计费的请求，普通请求成功也不能证明全部能力，因此使用内置目录及明确的手动联网入口。
- 为表单增加基础和专家模式能减少首屏控件，但引入另一轮选择和并行编辑表面，因此保持全部信息可见，只在主动修改时呈现值控件。

## Verification

内置快照从公开 models.dev API 生成，包含 11 家服务商和 601 个文本输出模型。生成脚本拒绝缺失服务商、模型身份及无效目录形状；数值只保留正的安全整数。目录缺少推理档位或当前 Chat 适配器没有明确方言时，不自动启用推理控制。

新增未执行的回归覆盖完整地址、协议隔离、未知同名模型不借用限制、非法限制不能序列化、已知模型建立主模型、已有条目和明确值保留、能力汇总、独立操作保留及预设切换清除不适用的 Chat 控制。转换界面夹具同步审核按钮和原有必填字段名称。按仓库要求不运行编译、类型检查或自动化测试；执行笔记校验、差异检查与相关源码及直接消费者审查，不据此宣称原生或真实上游验收。

## Consequences

已知端点和模型无需逐项勾选即可完成新建；未知端点不借用同名模型能力；缺失的必需限制明确阻止提交。已保存值和转换待核对状态保持。Codex、Claude、官方表单、模型用途、运行参数、直接消费者和双语文案同步，旧图形编辑模块、原始模型文本、复选矩阵、通用限制及其样式和失效文案移除。没有新增兼容或过渡格式，不修改真实档案或凭据。

目录快照随版本维护，可能滞后；界面标明日期和当前值是否与目录建议一致，不把数值相同冒充可追溯的历史来源。模型声明不等于上游或账号验收，只有明确支持的档位和适配器可自动带入；未知配置仍需集中补齐实际限制，并保留完整直接修正入口。公开目录读取不发送凭据；打开编辑器不联网，不引入后台探测或外部运行时依赖。
