# Agent Note: 再次点击侧栏当前页回到页面主界面

Status: implemented

## Problem

侧栏项只切换页面。停在二级页（供应商编辑、导入、用量查询、扩展编辑与扫描、检测历史、会话详情）时，再次点击当前页没有任何变化，只能用二级页自己的返回控件退出。未保存保护分散在各编辑器内部，12 处 `useUnsavedChanges` 各自持有确认单；二级界面的状态又分属导航钩子、领域模型和页面组件。侧栏既不知道当前打开了什么，也不能绕过确认直接丢弃草稿。

## Decision

侧栏选择走 `useWorkspaceNavigation` 的 `selectPage`。选中当前页时它发布一个新的页根请求对象，其余 `setPage` 调用方保持只切换页面的含义。`AppWorkspace` 用 `PageRoot` 包住每个页面子树；子树收到属于本页的请求后，交给页根注册表（`src/app/page-root.ts`）的 `returnToRoot`。

拥有二级界面的组件用 `useOnReturnToRoot` 登记打开状态、关闭动作和忙碌状态。只有随二级页关闭而卸载的编辑器向 `useUnsavedChanges` 声明侧栏返回守卫。没有打开的二级页时请求立即结束。任一打开的视图或守卫忙碌时保留当前界面。否则由第一个有未保存更改的守卫经它自己的确认单放行，确认后执行打开视图的关闭动作。

请求必须是每次点击新建的对象：同一页连续点击都要各自触发。子视图的登记 effect 先于父级 `PageRoot` 的请求 effect 运行，所以即使两者落在同一次提交里，关闭动作也已登记。

各页登记的范围：

- 供应商页关闭导入页、两端用量查询和编辑器。`closeEditorAtList` 不跟随「返回网关」，也不把焦点移回列表行，因为用户点的是侧栏项。
- 扩展页关闭编辑器和扫描视图；扫描视图忙碌时让路。
- 用量页关闭检测历史。
- 会话页复用 `clearSelection`，与切换页签、切换筛选时离开会话详情走同一个动作。

页签、客户端选择、筛选和扩展库／市场视图属于一级内容，不登记。网关、客户端配置和设置没有二级界面，再次点击没有变化。弹窗的遮罩覆盖整个窗口，侧栏点不到，因此不处理弹窗。

## Alternatives considered

- **让 `setPage` 本身在重复选中当前页时触发。** 只需改一处，所有导航入口行为一致。但页面内的入口也用 `setPage("providers")` 显示已打开的编辑器（例如从模型路由进入），返回会把它刚要显示的编辑器关掉。触发因此只挂在侧栏的处理上。
- **把全部二级界面状态提升到导航钩子，由它直接重置。** 可以在点击处理里同步完成，不需要上下文和 effect。但未保存确认仍在各编辑器内部，同步重置等于绕过确认丢草稿；还要搬动扩展、会话、用量的页面局部状态，其中扩展页当时正被并发改动重构。
- **再点一次等同于点击当前二级页的返回控件，逐层退出。** 与返回控件完全一致，不必定义「主界面」。但扩展页的编辑器可以叠在另一个二级视图上，要点多次才回到主界面，不符合需求；而且需要按挂载先后推断「最里层」，父子守卫同批挂载时顺序并不可靠。按「任一忙碌则不动、第一个有更改的守卫确认」判定不依赖顺序。
- **自动登记所有未保存守卫。** 新编辑器可直接继承保护，但市场仓库表单同样挂在页面下，返回时会要求放弃仍然可见的草稿。由关闭时会卸载的编辑器选择登记。

## Consequences

收益：侧栏复用二级编辑器的放弃确认，保存或扫描期间保持界面。一级表单保留草稿。程序化跳转继续由原导航入口处理。

代价：返回经 effect 执行，比点击晚一个提交。从网关打开的供应商编辑器经侧栏返回时落在供应商列表而不是网关，焦点留在侧栏项上。确认单是通用文案，不指明将关闭哪些界面。会话页的返回动作由 `clearSelection` 同时关闭详情和[批量操作弹窗](2026-11-24-session-batch-dialog.md)。

在完整应用的模拟入口验证供应商编辑中的继续编辑、确认放弃后回到当前客户端列表，以及导入子页回到列表。`tests/page-root.test.ts` 补充在一级页面不触发守卫的回归用例，自动化用例按项目约定留待显式授权后执行。
