# Agent Note: 托盘切换的两步确认

Status: implemented

## Problem

托盘供应商行整行是一个按钮，点击一次就直接预览并执行切换，`confirm_write` 由后端 `tray_switch` 固定传入 `true`。托盘是贴着任务栏弹出的快速面板，无读数的行只有约 40px 高，点错一行就换掉了正在使用的供应商，事后只能去主界面撤销。主界面的切换会在目标供应商行内展开确认，托盘没有任何中间步骤。

## Decision

切换需要两次点击同一个供应商行。第一次点击只把该行标记为待切换目标（`armedId`，由 `useTrayActions` 拥有），不发出 `tray_switch`；行的状态槽改为显示「再次点击切换到 {名称}」并常显，按钮的可访问名称同步改为同一句。再次点击同一行才调用 `tray_switch`。

- `tray-switch.ts` 的 `switchClickOutcome` 同时检查目标和单调时钟截止时间。点击其他行或超过 5 秒的标记只会重新标记。计时器负责清除提示，点击判定也校验截止时间。
- 原生 `popup::hide` 成功后向托盘窗口发出 `tray-hidden`，托盘收到后清除标记。页面失焦与 Esc 同样清除标记，卸载时释放订阅和计时器。面板闲置时保留 WebView 的理由见[托盘浮层的闲置销毁与按需重建](../architecture/2026-10-28-tray-idle-teardown.md)。
- `tray_switch` 沿用已有切换执行器和互斥控制。待确认文案通过持久的状态区域向辅助技术播报。
- 标记是 `TrayPanelContent` 内的 React 状态，用量刷新和 `tray-changed` 轮询带来的快照更新只重渲染，不清除标记。首层布局（名称—状态槽）不变：状态槽随文字变宽，用量行横跨名称列与状态槽两列，宽度不受影响。

## Alternatives considered

- 确认弹窗或行内展开的确认区（主界面的做法）：能展示完整变更，防误触最强。但托盘的定位是快速切换的面板，为一次切换再加一层确认区会把常用路径拉长，透明材质浮层上的第二层还需要新的样式与焦点管理。用户要的是同一个按钮点两次。
- 状态槽只显示「切换到 {名称}」或「确认切换到 {名称}」：更短，长名称下对名称列的挤压更少。但两句话都不提还要再点一次，容易让人以为已经切换。用户在三个文案里选定「再次点击切换到 {名称}」。
- 标记期间隐藏名称、让整行变成确认提示：超长名称下更干净，不会出现左侧省略的名称与右侧完整名称并存。但它改变了首层「名称—状态槽」的结构，需要额外的网格重排；现状只在长名称下才把名称列挤到省略，且只持续到标记取消。保留现有结构。
- 只用 5 秒计时器取消，不监听失焦：实现更少。但隐藏的 WebView 会把状态保留到下一次打开，计时器在后台还可能被节流，关掉再打开后的第一次点击可能就是确认。
- 只依赖网页 `blur` 同样可以处理浏览器里的焦点变化，接线更少。原生隐藏可能复用网页且没有对应的 DOM 失焦，因此由实际隐藏边界通知托盘。

## Consequences

- 托盘误触一行不再切换，必须再点一次同一行。快速连点两下仍会直接切换，这是「同一行第二次点击即确认」的固有结果；要防连点需要再加最小间隔，目前没有这个需求。
- 标记期间该行的名称列变窄：名称越长挤得越多，超长名称会被省略显示；用量读数不受影响。
- `tests/tray-switch.test.ts` 覆盖首次标记、点击另一行移动标记、再次点击切换和截止时间判定。
- DESIGN.md 托盘段落写入两步点击规则；README 没有描述托盘切换的句子，不改。首层布局与刷新按钮仍由[托盘原生玻璃与两层读数布局](2026-10-16-tray-glass-and-reading-layout.md)和[托盘警示图标与行内用量刷新](2026-10-14-tray-usage-alert-refresh.md)拥有。

## Verification

在模拟 IPC 的托盘入口核对首次激活只更新状态区域、同一行再次激活只调用一次切换、选择另一行移动待确认目标、Esc 清除并请求隐藏。模拟原生 `tray-hidden` 事件后，再次激活同一行会重新标记。等到五秒确认期限后，仍需重新标记。

原生窗口实际派发事件和真实供应商切换仍缺实机验证。
