# Agent Note: 云端备份的配置指南与初始化 SQL 合并为一个 AppDialog

Status: implemented

## Problem

「设置 → 备份恢复 → 加密云端备份」页签里，首次配置 Supabase 要用的两样东西都是页面内的展开收起，各有问题：

- 六步「从零配置 Supabase」指南是一个 `CollapsibleSection`。它夹在主图和「项目连接」「备份或恢复」两组表单之间，展开后把两组表单推到页面下方。它是配置完成后就用不到的引导，却常驻在表单上方，和表单争同一个页面滚动面。
- 「显示初始化 SQL」是表单组里手写的显隐切换：普通按钮加 `aria-expanded`，点开后在「测试连接」「保存连接」下方挂出一个只读 `Textarea` 和一个复制按钮。它没有经过 `Collapsible` 原语，没有箭头也没有过渡，与 DESIGN.md 把 `Collapsible` 定为全部展开收起唯一原语的规则不一致；只读文本框也没有接入 `CodePreview`。

两者还互相指路：指南第 3 步写着「再点击下方『显示初始化 SQL』」，而那个按钮在指南下方的另一个分组里。只把指南单独搬走，这句话就会指向一个被模态弹窗挡住的按钮。

## Decision

指南和初始化 SQL 属于同一个「进入—阅读或复制—离开」任务，由一个 `AppDialog` 承载（`CloudBackupPanel.tsx`）。

- 入口是云端主图上的次要按钮，文字与弹窗标题同用 `backup.cloud.guideTitle`。入口只有名称，不带 `aria-expanded` / `aria-controls`，也不随弹窗开合切换文案；Escape 关闭和焦点回到入口由 AppDialog 拥有。
- 弹窗取标准宽度，主体是六步有序列表。第 1–4 步都在 Supabase Dashboard 里完成，弹窗可以一直开着对照浏览器；第 5 步的文案以「关闭本指南后，在页面填写…」开头。
- 初始化 SQL 紧跟第 3 步的段落，用 `CodePreview` 渲染，行号、行数、复制按钮和超过 12 行时的「展开查看」都来自该组件。SQL 在弹窗挂载时读取一次（`getCloudBackupSetupSql`，后端常量），卸载即丢弃，下次打开重读；读取失败只弹错误提示，该位置不渲染内容。第 3 步文案指向这个复制按钮（「再点击下方『复制』」）。
- 到达初始化 SQL 的入口只有这一个：表单组里的显隐按钮、只读文本框和独立复制按钮全部删除。
- 弹窗随页签可见性关闭。三个备份页签为保留状态常驻挂载，残留在隐藏页里的 ModalOverlay 会让页面之外的整个应用保持 inert，所以 `CloudBackupPanel` 以 `active && guideOpen` 决定是否渲染，并在 `active` 变为 false 时复位 `guideOpen`。[客户端配置入口弹窗](2026-11-23-client-configuration-entry-dialogs.md)对路由不可见做同样的处理。

改弹窗还是留折叠，沿用客户端配置四入口定下的边界：独立的进入—离开任务用 AppDialog，挂在行上的审阅证据继续用 Collapsible。按这条边界，本地备份的「查看差异」保持折叠，其滚动归属见[备份历史改随页面滚动](2026-10-14-backup-history-page-scroll.md)。云端主图的构成由[设置维护页的设备图与差异列表](../architecture/2026-11-24-settings-device-layouts.md)拥有，折叠原语的范围见[全局折叠原语](../architecture/2026-10-14-unified-collapsible-primitive.md)。

## Alternatives considered

- **保留内联折叠，只把 SQL 的显隐切换换成 `Collapsible` 加 `CodePreview`。** 最强的理由是页面没有模态阻断：指南展开着就能直接点到下方的 SQL 按钮，也能一边读第 5 步一边填表单，两处互相指路正是靠这个布局成立的。否决：要解决的恰恰是形态本身——引导和常驻表单争同一个滚动面、表单被推离首屏，修掉显隐切换后原样保留。
- **指南和 SQL 各开一个弹窗。** 最强的理由是职责清楚：需要重跑 SQL 的老用户不必翻进一份名为「从零配置」的指南，第 3、5 步的文案也不用改。否决：两者在同一步里先后使用，而两个都是模态弹窗——读到这里必须先关掉指南，到表单组点开 SQL，再回来接着读第 4 步。
- **指南弹窗用 `wide` 档。** 最强的理由是初始化 SQL 最长的一行有 94 个字符，标准宽度下较长的行会折行，`wide` 下不会。否决：`overlays.css` 把 `wide` 定位给并排浏览或前后对照列，这份弹窗的主体是指南正文；SQL 在这里的用途是被复制，`CodePreview` 的长行折行不影响复制结果。
- **「查看差异」也改成弹窗。** 最强的理由是同一份 `BackupDiff` 已经在恢复确认弹窗里渲染，复用没有成本，长差异也不再撑开时间轴。否决：差异是单条备份的审阅证据而非独立任务；弹窗一次只能看一条，逐条比较备份时每条都要开关一次，还与恢复确认弹窗里的同一份差异重复。

## Consequences

- 收益：云端页签的主画面只有主图和两组表单；备份恢复页面上剩下的展开收起（「查看差异」）全部经 `Collapsible` 族实现；初始化 SQL 的行号、复制反馈和展开查看与其他代码预览同源。
- 代价：读指南时看不到表单，第 5 步填表单必须先关闭弹窗，漏看一项要重新打开。初始化 SQL 只有一个入口，名称对需要重跑 SQL 的老用户不贴切；界面文案里没有错误提示指向这个入口，所以没有断链。
- 重访条件：后端开始要求用户重跑 SQL 并需要在提示里给出直达动作时，给 SQL 单独开入口。
- 文案词典删除 7 个只服务于显隐切换的键（显示、收起、复制、标签、无障碍名称、已复制、复制失败），新增 1 个代码块标题键 `backup.cloud.setupSqlTitle`；`.asb-cloud-backup-sql` 样式随之删除。

## Verification

这几个组件没有单元测试，`scripts/backup-recovery-ui.fixture.tsx` 只覆盖本地备份的恢复确认。按项目约束未运行类型检查、构建和自动化测试。静态核对：被删的文案键和类名在 `src/`、`tests/`、`scripts/` 零引用，`CloudBackupPanel.tsx` 的每个导入都有使用点；`npm run verify-notes` 通过。弹窗的实际表现（SQL 折行、矮窗口下的主体滚动、关闭后焦点回到入口）没有在运行中的应用里看过。
