# Agent Note: 当前客户端配置的类型与模型偏好契约

Status: implemented

## Problem

Codex 终端屏幕和恢复目录被错误建模为布尔值，通知事件列表无法读取，审批策略仍接受已经失效的 untrusted。Claude 顶层 effortLevel 不能表达新模型的持久化偏好，却允许保存仅适用于会话的 max。常用语言、压缩窗口、速度档位和请求限制没有类型化入口。

## Decision

沿用 ownership 目录作为字段、值域、控件和校验的唯一所有者，增加文本、目录、整数、字符串整数及通知联合类型控件，所有输入通过既有预览与确认执行器写入。Automatic 只删除对应字段，不伪造默认值。旧布尔类型与失效审批值不兼容读取，不自动猜测转换；有效顶层 effortLevel 的保留与新增结构由关联的双客户端配置笔记拥有。

Claude 推理强度使用现有 JSON 片段及其逐叶所有权清单承载 modelSettings.<model>.effortLevel，按模型编辑，只接受 low、medium、high、xhigh。不增加另一份模型偏好存储。网关投影将显式模型键同步映射到实际客户端角色标识，JSON Pointer 保留模型名中的点、斜杠和波浪号；其他模型字段保持原样。有效顶层 effortLevel 保留，仍可显式进入片段；新模型的默认强度继续按模型保存。

通用额外配置始终使用客户端字面键，只有供应商片段随网关路由投影；客户端单独应用不能覆盖活动供应商声明的叶子。供应商切换先清理原供应商片段，再应用通用和新供应商片段；预览使用最终文档差异，删除独立叠加两份片段差异的旧路径。退出网关时恢复接管前路由声明的 modelSettings 叶子，保留当前其他片段字段、通用偏好与未声明模型偏好。

Codex 通知数组的读取、预览和值比较共用无歧义 JSON 表达；供应商数值读取和切换回填复用同一个 TOML 解码器及目录校验。界面控件仅消费目录的控件和值域，按模型编辑复用全局 Input、Select 和 Button；恢复参数默认值移除界面管理的默认强度、上限和窗口叶子，保留其他模型偏好。

Claude 网关模型角色的来源由核心适配器唯一解析，配置投影与请求派发共用。删除内部角色缺少配置时硬编码到指定 Claude 型号的路径，改为具体错误；不改变原生模型名称的既有路由语义。

## Alternatives considered

- 继续写顶层 effortLevel，改动最少，也适用于部分旧模型；但不能兑现新模型的持久化选择，拒绝。
- 给模型偏好增加独立存储，类型易于表达；但现有片段已经拥有逐叶校验、预览、交换和恢复机制，会产生第二份事实来源，拒绝。
- 读取时自动将旧布尔或 max 转成新值，可以减少报错；但不能证明用户意图，且会留下双契约，拒绝。

## Consequences

目录、前后端类型、校验、读取、序列化、预览、导入和文档使用当前契约。新增纯文本变换测试覆盖失效值拒绝、通知数组无损读写与歧义、数值边界、按模型偏好投影和恢复、所有权冲突与交接。当时契约的历史验证在获准后执行 `cargo test --locked -p asb-core current_contract_tests`，8 项全部通过；前端生产构建与桌面编译通过。供应商存储修复的真实后端副本验证及桌面单测编译阻塞记录在关联笔记中，这些检查不代表真实客户端请求验收。

笔记检查的首次 npm 入口因缺少本地 tsx 且 registry.npmjs.org DNS 解析失败退出；使用本机 Node 24 直接执行同一组三个脚本，目录与相对链接、格式、归档封存检查均通过（17 篇活跃笔记，0 篇归档）。未安装依赖或改变工具链。

存有显式失效值的配置与档案会明确报错，必须由用户修正；退役且无值的 Claude 自动强度项由现有智能修复入口处理。配置契约改动本身不修改真实客户端配置或应用存储。模型与账户的实际能力由客户端和上游决定，保存配置不等于功能已启用。网关最小请求模式按现有契约省略 service_tier，界面直接说明此边界。
