# Agent Note: 题库限时与真实检测进度

Status: implemented

## Problem

只按整数或视觉格式设置 4/15 分钟，不能区分已知短题与内容未知的自定义题。现有记录仅有计数题三次成功（约 16–25 秒）及 max 推理 HTML 题一次 240 秒超时，没有行程、圆桌和成功视觉题样本，无法推导统计完成时间。界面只显示批次完成次数，没有单次剩余时间和当前阶段，大幅参考画面还会把运行状态推到模块下方。

## Decision

- questions.rs 唯一拥有时限：计数、行程、圆桌各 180 秒；鹈鹕完整 HTML 动画 900 秒。前三题只需短推导并输出整数，采用相同保守等待预算，不因题名制造无依据的耗时差别。自定义题的工作量未知，整数给 300 秒、SVG 给 600 秒、HTML 给 900 秒。预算是应用等待上限，不是统计预测或模型能力判据；保留当前模型、推理强度与题干，不自动重试。
- 题目目录统一返回内置题、自定义格式预算与自定义次数上限；不从内置题反推自定义次数。选题处显示单次限时，目录或当前状态尚未同步时不可开始调用；删除旧的列表命令与 runner 内独立的 4/15 分钟分支，所有直接调用方同时迁移到目录契约。
- progress.rs 拥有每次实际执行的单调时钟，登记在唯一活动检测槽，runner 用同一个起点和截止时刻终止进程，视图返回已用时与本次限时。刷新页面重新读取该时钟，不按批次开始时间或历史耗时猜测单次起点，不建立前端截止时间。
- 运行槽用互斥状态表达正在执行和等待保存；每个批次从准备第 1 次开始，只有当前结果提交成功后才能准备下一次。创建运行记录和登记时钟在同一个运行槽锁内完成，重复、跳号或跨批次启动明确报错，不覆盖已有时钟。执行阶段为启动 CLI、执行中（CLI 报告会话 ID）、整理结果、保存结果；迟到会话事件不能倒退阶段。取消只由同一个原子信号拥有，状态读取将它投影为取消中，不另存一份取消阶段。
- 批次及其运行记录在一个 SQLite 读取事务内取得；读取、创建运行、结果提交、批次结束和保存重试共享运行槽锁，避免跨瞬间拼接进度。运行中视图必须有明确的准备或执行状态，匹配不到所属批次、轮次或记录时报告具体契约错误，不过滤成空进度或无限显示正在读取。结束或等待重试保存时不保留活动时钟。活动计时不作为结果的第二份持久化来源。
- 当前读取优先选择运行槽持有的批次，只有没有活动或待保存结果时才按历史时间选最新记录；系统时间调整不能让活动任务让位于旧历史。数据库读取拒绝未知状态和越界的无符号计数，不将错误状态改判失败或把负数归零。读取失败的重试只重新读取，待保存结果才提供保存重试，避免把查询与写入混为一个补救动作。
- 活动计时只存在于进程内，网页刷新可重连，应用退出后按既有规则中断并清理子进程，不恢复倒计时或生成任务。不为临时计时增加历史字段、数据库迁移或第二份持久化缓存。
- 运行块置于雷达模块顶部、题目参考画面之前，并复用于历史中的当前任务；显示本次序号、真实阶段、剩余/已用/上限和已完成次数。次数进度条只按已完成次数推进，不将已耗时间伪装成生成百分比。计时读数复用每秒状态轮询，隐藏时暂停读取，重新显示时同步；读取失败标明是上次读数，归零只表示执行截止、等待后端结束，不由前端判定成功或发起新调用。

## Related decisions

检索活动笔记的运行预算、倒计时、进度、雷达与 codex_probe。本篇完全吸收原按格式限定运行时间笔记：超时终止整个进程树、保留同会话用量和已有回答、失败保持未判定、不自动修改配置或重试、历史不补猜答案的理由继续有效，旧篇删除。[HTML 动画与隔离预览](../../implemented/feature/2026-10-13-linuxdo-pelican-animation.md)继续拥有题干与作品展示，双方互链；[安装器进度](../../implemented/feature/2026-10-14-installer-ring-progress.md)提供不按耗时伪造完成度的相邻约束，执行器独立。

## Alternatives considered

- **统一 15 分钟或各题随意给不同分钟数**：规则少或看似针对每道题；但前者让短题挂起过久，后者缺乏样本与任务量依据，因此已知短题共用预算、未知自定义题按输出量留余量。
- **用前端开始时间计时并按耗时推进百分比**：无需后端改造、看起来连续；但刷新重置、时钟调整和多次调用切换都会使截止时间漂移，也无法知道模型生成了多少，因此从实际执行时钟读取剩余预算，只显示真实完成次数。
- **为临时阶段与起点迁移历史数据库**：可持久化每个阶段；但异常退出后任务本就不续跑，旧记录也没有可信起点，迁移会扩大数据契约却不能恢复生成，因此保留数据库唯一结果来源，活动进度归进程所有。
- **分别读取批次、结果与运行槽，再过滤不匹配的进度**：锁的范围小，实现直接；但结果提交与连续调用切换会暴露不一致的组合，空值还掩盖丢失运行槽，因此采用单次读取事务与统一生命周期锁，准备阶段成为显式契约。锁只覆盖本地记录操作，不覆盖模型执行、进程等待和用量整理。
- **取消上限、自动降低推理或自动重试**：可避免截断或更快返回；但会无限占槽、改变被测配置或增加真实消耗，因此保留有界等待和用户主动取消、重测。

## Consequences

- 目录、解析后的题目、runner 实际截止与界面限时使用同一预算来源；旧题目列表命令和旧预算函数没有直接消费者。
- 刷新、隐藏再进入和连续多次检测不重置本次计时；旧批次、已完成批次和待保存结果不展示活动倒计时。取消和迟到回调不使阶段倒退。
- 当前任务在题目画面之前显示，历史可见同一活动数据；次数进度、时间预算和生成阶段语义分开，读取失败明确标示。
- 回归覆盖预算、时钟、重复和跳号启动、迟到回调、槽归属、准备/执行状态、当前与历史视图重连、终态清理及待保存重试。用户授权的 Windows 本地 CI 已通过：Rust 工作区 696 项、前端 27 项、类型检查、生产构建及笔记校验均通过；两个子进程辅助入口由其上层测试调用。沙箱禁止回环连接导致的失败经错误 10013 复现，保持配置目录隔离并扩大进程权限后通过同一门禁。未调用真实模型，原生界面中的倒计时、取消和页面恢复尚未实测。
- 只有少量历史数据，所选等待上限需要在更多真实使用后再评估，不能保证所有上游请求或自定义题都按时完成。
- 状态按秒轮询，数字可能因读取延迟跳秒；生成内部完成比例不可知。退出后活动时钟消失，不给旧历史虚构当时限时。
