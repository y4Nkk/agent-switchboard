# Agent Note: 扩展库与市场的操作布局

Status: implemented

## Problem

扩展库的创建入口埋在更多菜单里，首次添加与批量维护使用同一个入口。Skills 与 MCP 市场需要一致的查找和结果动作位置。编辑与部署收纳了文件、配置、目标和诊断等长内容，独立组织时容易出现重复标题、分散的更新入口和层叠滚动面。

## Decision

扩展库和市场共用工作区及 Skills、MCP 分类导航。扩展库保留宽表格，搜索行直接提供更新检查与当前分类的创建入口。「更多」承载扫描、导入、登记项目、批量启停和历史，批量条目明确全分类范围及已启用数量。空库可直接打开对应市场。

市场共用搜索表单、结果行与有界滚动面。来源选择紧邻本模式的输入，搜索、扫描和浏览只由用户提交触发。每个分类首次打开时挂载，保留查询、结果、来源和视口读位，进入编辑与返回时使用原位置。结果行的来源、简介及状态与当前条目相邻，安装、配置和来源链接归同一操作区。仓库进度、错误及恢复动作留在结果之前。

Skill 编辑、MCP 新建编辑及配置向导复用设置正文与分组。Skill 文件、版本和依赖在独立页签里展现，草稿继续由编辑会话拥有。MCP 的基本信息、连接和可选启用客户端顺序排列，JSON、参数和凭据列表有完整行宽。新建默认只保存定义，用户勾选后随保存启用所选客户端。配置向导来回切换时保留原发起按钮，以便返回市场后恢复焦点。「部署与诊断」按已部署、部署目标、连接检测、版本来源和资源详情排列，删除位于管理面末尾。管理弹窗主体负责纵向滚动，绑定与检测表格只在需要时横向滚动。目标级启停在对应行显示进度和异常，成功后以刷新结果呈现启停状态。写入继续走现有事务，预览在相应确认弹窗展示。

## Alternatives considered

保留两个全页市场可沿用返回栈和编辑页骨架，切换分类时需要换一套导航，搜索输入和提交分处页面两端。

批量按钮常驻可直接启停并展示范围，占用库内搜索行。将明确的全分类范围和数量放进菜单项，为更新检查腾出位置。

市场卡片网格能并排展示更多结果。条目描述、注册版本与操作文案长度不同时，跨列比较需要来回移动视线。统一结果行让标题和动作保持稳定位置，长内容可借助整行宽度换行。

## Consequences

市场内容在扩展工作区存续期间驻留，返回时使用同一视口的读位。单列结果减少并排条目数，长名称、路径和安装状态可完整阅读。执行批量启停多一步打开菜单，具体范围在选择前可见。窄工作区优先重排搜索和表单行，保留表格的列语义。
