# Agent Note: 会话批量操作弹窗

Status: implemented

## Problem

会话列表的批量选择入口与普通文字难以区分。进入选择模式后，操作栏占据列表与详情上方的一整行，选中状态和可用动作分散在主页面。

## Decision

会话与已归档从[页头「更多操作」](2026-11-24-session-workspace-controls.md)进入「批量操作」，使用 AppDialog。弹窗复用当前客户端、搜索、项目筛选和分页，列表按会话身份合并同页的多条命中，Checkbox 支持勾选单条或本页。选择跨页累积，固定底部显示已选数量、分页及操作。弹窗关闭时清空本次选择。

标签编辑和筛选复用 AppDialog，删除使用现有 ConfirmSheet。切换到这些对话框时通过 AppDialogSuspension 保持批量弹窗及其选择，取消删除确认时仅清除待删除目标。删除结果及逐项失败原因在批量弹窗内也可阅读。[会话弹窗控件](../architecture/2026-11-24-session-dialog-control-boundaries.md)定义字段弹层、批量勾选与删除快照的归属，并让同一查询的分页在加载期间保持可见。

## Related decisions

- [会话操作层级](../bug-fix/2026-09-24-session-operations-layout.md)继续拥有会话详情和双栏布局，原页内批量栏由本篇接管。
- [会话项目与结果布局](../bug-fix/2026-09-24-session-layout.md)继续拥有项目身份和双栏浏览。批量入口的位置由会话工作区操作布局定义。
- [会话即时搜索](2026-11-24-live-session-search.md)继续拥有搜索与筛选行为，批量弹窗使用同一查询。
- [原生会话删除](2026-11-10-session-context-actions-and-native-delete.md)继续拥有删除目标核验及执行，批量弹窗消费同一确认和执行结果。

## Alternatives considered

- 给页内工具栏增加背景和分组，可以直接从现有结果中连续选择。它仍占用会话阅读区的整行，选择与操作仍在不同位置。
- 在主列表勾选完会话才打开操作弹窗，可以减少弹窗内容。完整流程仍依赖页内选择模式，打开入口后无法直接在弹窗内完成操作。

## Consequences

- 主页面恢复双栏阅读空间。弹窗共用查询状态，在其中调整的关键词、筛选和页码同步到主列表。
- 批量标签在独立弹窗中编辑。标签草稿随该弹窗关闭，所选会话保留到批量弹窗关闭。
- 按仓库约定检查差异、旧入口引用与笔记结构。桌面上的跨页勾选、关闭焦点和嵌套对话框仍待运行验收。
