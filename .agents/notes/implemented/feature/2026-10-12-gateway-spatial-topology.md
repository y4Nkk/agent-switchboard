# Agent Note: 本机网关的 2.5D 拓扑与客户端聚焦

Status: implemented

## Problem

本机网关的平面文字节点与长协议芯片挤在同一条连线上，用户需要逐项阅读才能分辨客户端、监听器和上游供应商。未配置网关路由的客户端仍有接入连线，且最近请求无法按客户端查看，容易把未接入或历史流量理解为当前连接。

## Decision

本篇只拥有实际网关连接、状态与流量聚焦。模型配置图与保存应用流程由[图形化模型路由](../architecture/2026-10-26-graphical-model-routing.md)拥有；运行拓扑和遥测位于其下方的共享折叠区，监听状态与恢复仍保持可见，不将未应用草稿作为运行连接。

拓扑采用固定阅读方向的开放 2.5D 设备场景，文字、地址和操作保持正视排版。设备、位置与留白建立层级，模块间没有横竖分割线，节点没有常驻卡片边框，底面没有装饰网格；只保留表达请求路径的曲线箭头。复用全局语义色、字体、按钮和 ClientFilter，不引入三维运行时、画布交互或新增依赖。客户端、中央监听器、供应商仍由同一份 gateway_status 快照拥有；协议标签沿用现有本地化函数。

路径端点由设备实际 DOM 边界拥有，ResizeObserver 在节点或场景尺寸变化时重新测量，合并到一个动画帧更新 SVG 坐标；换行、窗口宽度与应用缩放不使用固定端点猜测。观察器及待执行帧随组件卸载或路由变化清理。竖向母线、伪元素直线与按线计数的旧布局全部移除，请求计数附在所属节点旁。

页面只持有一个临时客户端筛选值。共享筛选器与节点点击共同更新它：聚焦路径同步筛选最近请求，整体仪表保持网关全局统计并明确说明范围。不持久化筛选，不修改任何路由或客户端配置。未接入的客户端不绘制网关连线；节点计数仅纳入近 60 分钟能匹配当前路由的样本。端口预览、确认、监听重试与恢复入口沿用原执行路径。

面向用户的文案由 `gateway` 双语目录拥有，先说明请求去向、网关是否启动以及下一步操作。界面使用「应用」「模型服务」「本机地址」「当前使用端口」「连接配置版本」等日常说法；请求格式保留共享协议精确名称，并添加格式标签。配置连接、网关就绪和上游请求成功是不同事实：空连接状态说明暂无应用连接，运行状态只说明网关已启动，不承诺模型服务可用；请求结果用成功、失败或未完成配合原状态码显示。错误先呈现可执行指引，原始原因另标「详细原因」，不丢弃诊断信息。更换端口与结束恢复的确认仍说明具体影响及删除范围。

最近请求继续复用共享 Table；网关样式为表格设置 56rem 最小宽度，使用已有容器横向滚动，应用名与结果单元格不换行。较长说明与协议可在所属列换行，避免窄窗口把品牌名和成功、失败结果拆成碎字，不添加模块分割线。

历史决策检索仅命中[协议标签本地化](2026-10-12-gateway-localized-protocol-labels.md)，属于部分重叠：该篇继续拥有协议文案决策，本篇拥有拓扑呈现与聚焦语义，不替换旧篇。

## Alternatives considered

- 可旋转的 WebGL 三维拓扑能够呈现真实景深与自由视角；本页需要快速读取地址、状态和表格，自由相机增加操作与文字遮挡，且引入无必要的运行时和依赖，因此采用 SVG 设备插图与 CSS 层次。
- 只给现有平面卡片加阴影，改动最小且保留全部布局；但无法区分未接入客户端和当前路由，也不能减少按客户端查请求的步骤，因此同时提供一个共享聚焦状态并移除无路由连线。
- 竖向母线配合卡片框线能稳定对齐多条路径，纯 CSS 的连接也不需要测量；但母线、网格与模块分割线形成过多区域边界，无法满足开放场景的阅读方式，因此使用直接连接设备的 SVG 曲线，并承担尺寸观察与清理责任。
- 把网关运行状态写成「服务可用」、同协议路径写成「原样转发」最简短，读者无需理解技术细节；但本机已启动不能证明上游服务可用，同协议请求也可能经过参数处理，因此只写「已启动」和「保持原格式」，原始状态码与诊断原因仍可读。

## Consequences

- 收益：设备类型、连接方向与监听事实分别有图形及文字承载；聚焦共享 ClientFilter 与页面内唯一状态，用户可从节点直接缩小最近请求范围；没有当前路由的客户端不再伪装接入。
- 代价：SVG 设备占用更多图面高度；曲线增加尺寸观察和帧调度，窄窗口顺序堆叠并隐藏连线。视图不支持自由相机或平移缩放，因为所有状态文字与地址须始终可读。
- 所有权：GatewayPage 拥有快照读取、临时聚焦与端口弹层；GatewayTopology 拥有路由和样本归属；GatewayTopologyWires 独占设备端点测量与曲线；GatewayHub 拥有设置页监听事实轨（asb-gateway-hub，样式独存于 gateway.css），拓扑中央节点由 GatewayTopology 以 asb-gateway-node is-hub 自有渲染与持有样式，两者不互借类；GatewayDeviceArt 只输出装饰性 SVG；GatewayTelemetry 的仪表仍用全量 metrics，最近请求先筛选再截取 20 条。
- 删除旧 GatewayMap、平面卡片节点、线中协议芯片、竖向母线、伪元素连线、底面网格与模块分割线及对应样式，没有并存的旧渲染路径；保留现有协议本地化、配置执行器与端口事务。DESIGN.md 更新为同一事实。
- 布局静态目检覆盖 1080 / 820 / 440 像素内容宽度、浅深主题、监听失败、空路由与聚焦反馈，使用当前源样式与设备 SVG、隔离示例数据，不访问真实配置。宽、中曲线路径未遮挡状态和地址，窄布局没有模块分割线；深色标记底面与中性空设备依据目检修正。文案静态预览覆盖 820 像素监听失败指引和 440 像素请求统计、表格横向滚动，应用品牌名与成功、失败状态可完整读取。静态服务只暴露隔离目录内的示例 HTML、CSS、字体与品牌图标。
- 按项目约定不运行编译、类型检查或自动化测试。静态预览不证明 React 运行时、真实轮询、端口提交或筛选事件正确；这些仍未执行验收。
- 笔记树、格式和归档校验均通过；默认 `npm run verify-notes` 入口因沙盒内 npm 注册表解析失败（ENOTFOUND）未完成，使用本机 Node 离线执行其三个相同脚本通过。差异检查通过，旧拓扑符号与样式无残留源消费者。
