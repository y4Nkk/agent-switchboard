# Agent Note: 开机自启的窗口显示方式

Status: implemented

## Problem

「启动时最小化到托盘」同时影响登录自启和手动打开。用户选择后台自启后，从桌面打开应用也会隐藏主窗口。旧系统自启项使用与手动打开相同的启动参数。

## Decision

「开机自动启动」开启时，下方用单选项显示「启动方式」。「显示主界面」与「最小化到托盘」复用 `startMinimized`。系统自启项传入 `--asb-login-launch`，主窗口只在带有该参数且已启用托盘自启时保持隐藏。Tauri 重启使用的参数移除这次启动的来源标记。手动启动通过正常入口或单实例唤起打开主窗口，macOS 的应用重开事件也打开主窗口。自启请求遇到已经运行的实例时保留当前窗口状态。

每个进程首次应用开启自启的桌面设置时，通过现有插件重新登记并补齐来源参数。插件只报告自启项是否启用，无法验证旧项的参数。应用偏好保存和回滚继续使用同一套注册逻辑。

## Alternatives considered

- 给两种显示方式分别登记命令行参数，启动时可以直接判断。这样每次切换方式都需要写系统自启项，且偏好保存失败时还需要恢复模式参数。固定来源参数让显示方式始终以应用偏好为准。
- 将布尔值升级为双值枚举能让存储名直接表达登录用途。两种选项与现有布尔值一一对应，维持现有存储可保留已选偏好，也避免为设置文件与恢复记录引入迁移。

## Consequences

- 已保存的窗口偏好直接用于自启，手动打开仍可进入主窗口。应用准备失败仍通过[现有恢复界面](2026-11-11-automatic-application-data-preparation.md)显示处理入口。
- 现有自启项在每个进程首次应用开启自启的设置时刷新一次。升级后的首次运行若由旧自启项触发，会显示主界面，刷新后由新的自启命令应用已选方式。
