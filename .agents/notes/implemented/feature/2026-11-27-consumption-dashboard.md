# Agent Note: 消耗统计概览与模型趋势

Status: implemented

## Problem

消耗统计把来源覆盖文字、Token 明细和并排图表放在同一面板。页面缺少日历活动视图和模型日趋势，无法顺着概览、日期、模型的顺序查看用量。

## Decision

使用累计指标条、52 周活动图、时间范围、每日模型趋势和模型用量环图。活动图独立于趋势范围，每周模式按周汇总，累计模式按可见周范围累加。当前连续天数允许连续记录截至昨天。现有四个日期范围共用快照，精确的客户端用量明细按需展开。页面显示刷新进度、快照时间和实际读取错误。

模型日用量来自现有会话日桶。趋势与分布按原始模型名合并客户端、共享排序和色序，表格保留客户端分组。最长会话跨度取同一客户端会话首末两条带有效日期的正用量记录的间隔。日趋势、活动图和连续天数使用有日期的用量。未记录日期的用量计入全部范围的合计和明细。

## Related decisions

[用量工作区的读取性能](../architecture/2026-11-25-usage-workspace-read-performance.md)与[消耗统计快照](../bug-fix/2026-10-29-usage-snapshot-first-refresh.md)拥有刷新和四范围快照读取。消耗概览使用同一批快照，沿用已验证的用量及会话身份。

## Alternatives considered

- 只用现有 Token 类型日趋势，能保留原报表字段和查询成本。按模型查看时会失去每天的来源和一致的图例颜色。
- 单独保存会话时长索引能避免逐次读取调用数据。其增量更新必须处理端点撤销、重归属和既有索引重建，现阶段可直接使用已去重的调用数据。

## Consequences

趋势、分布和详情使用同一个选中范围。旧快照可以先展示日合计及原有明细，首次更新后提供按模型的趋势。没有成对日期的会话跨度显示未知。模型日数据以日期和模型小计传输，刷新期需要额外流式遍历当前范围的去重调用以计算会话跨度。
