# Agent Note: 客户端工具页的删除确认与两处写入预览由内联面板改为弹窗

Status: implemented

## Problem

「设置 → 客户端工具」里有三块「进入—查看或确认—离开」的面板长在页面内，而项目其余破坏性或写入操作（档案删除与撤回、会话删除、客户端配置恢复、同页的「确认客户端更新」）都在 `ConfirmSheet` / `AppDialog` 里预览后确认；只有主供应商切换确认是明文例外，在请求它的档案行内展开。

- Codex 工作场景的「删除场景」把所选场景的操作行原地换成一段确认块（说明与「保留 / 确认删除」）。`deleting` 状态从 `ProjectPlansPane` 传进 `ScenarioPanel`，删除完成后的收尾再经 `onDelete` 回传；这段回传在 0.3.34 漏接过一次（"fix scenario delete callback"）。确认块没有焦点圈定，删除失败的原因显示在模块上方。
- 工作场景的恢复预览（将写入的步骤、先自动保存到哪份场景的说明、警告、「返回 / 确认恢复」）作为面板追加在模块最底部，排在所选场景的操作面板之后；卡片多时点完「预览并恢复场景」要滚动才看得到待确认的内容。
- Claude 客户端集成的标记写入预览展开在标记卡片内。预览打开期间，刷新、自动同步开关和两张卡片的动作全部被 `!!preview` 禁用，带预览的卡片还要 `grid-column: 1 / -1` 拉通整行才放得下差异列表：行为上已经是模态，却没有模态的焦点圈定、Escape 与焦点恢复。

## Decision

三块面板改为弹窗，模态、焦点圈定、Escape、忙碌关闭与滚动全部交给既有的 `AppDialog`。

- 删除场景打开 `ConfirmSheet`。确认框展示删除目标及后果，使用共享取消文案。对话框状态保存删除对象及发起时的版本。删除成功后清空选择，将焦点移到已保存场景标题。打开前清除前一次操作的错误。
- 恢复预览打开 `AppDialog`，默认聚焦「返回场景」。预览请求由面板发起，`ScenarioPanel` 上报触发按钮。恢复结果与警告作为同一份结果留在页面上。请求载荷与写入、备份语义沿用原契约。
- 标记写入预览打开 `AppDialog`，使用标准宽度和 `DiffView` 列表版式，默认聚焦「取消」。存在变更时提供「确认写入」。模态负责阻断页面交互，移除由 `!!preview` 控制的禁用状态、`is-previewing` 和相关专用样式。
- 两个面板接收 `active`（页面可见且所属页签是当前页签）。`useClientToolDialog` 统一管理打开状态、预览请求身份和关闭后的焦点。面板隐藏时立即移除弹窗，并在当次提交中使预览请求失效。已失效请求的结果和错误都不再进入界面。访问过的设置分区会隐藏并保留挂载，关闭弹窗才能解除其余界面的 inert 状态。见[客户端配置四入口由互斥内联展开改为 AppDialog](2026-11-23-client-configuration-entry-dialogs.md)。

预览请求期间，触发按钮禁用并失焦。预览在读取结束后挂载，返回或取消按钮在首次渲染时即可聚焦。面板提供明确的返回控件，共享生命周期等弹窗关闭、操作结束且焦点仍停在页面主体时恢复焦点。Claude 标记卡直接引用写入和清除按钮，选择当前可用的一项。删除场景时，原按钮仍存在便返回原按钮，删除成功后改用场景列表标题。`AppDialog` 负责模态焦点圈定、Escape 和常规焦点恢复。

文案随容器收口：区域的 aria-label 上移为弹窗标题（`codex.plans.deleteTitle`、`codex.plans.previewGroup`、`clientConfig.integration.previewTitle`），只服务内联确认块的 `deleteConfirm`、`keep`、`deleteConfirmAria`、`previewAria`、`integration.previewAria` 删除。

安装卡片的「详情」、更新任务的「操作输出」和「识别诊断」三处折叠不在本次范围：前两者是 [DESIGN.md 与客户端软件版本契约](2026-11-04-client-software-version-management.md) 明文规定的形态，后者是贴着对象的小证据。

同主题审计：

- [客户端配置四入口由互斥内联展开改为 AppDialog](2026-11-23-client-configuration-entry-dialogs.md) 拥有配置页四入口及其 `active` 关闭约定。本篇沿用该约定。
- [桌面工作区 UI/UX](../architecture/2026-10-13-desktop-workspace-uiux.md)：拥有「AppDialog 是全部应用模态的唯一所有者、短确认复用 AppDialog」。本篇是该规则在客户端工具页的落地；其中「Codex 场景恢复与只更改记录的维护动作分组」的事实不变。
- [全局折叠原语](../architecture/2026-10-14-unified-collapsible-primitive.md)：三块面板此前不是 Collapsible 的消费者，本篇不改变它的边界。
- `2026-10-13-ui-copy-density-reduction` 只记录场景文案键的删减，与本篇无关。

## Alternatives considered

- 保留内联形态，只修排版。它最强的理由是零模态阻断，用户可以一边看恢复预览一边对照页面上的场景卡与当前状态。否：要解决的正是形态本身——删除确认没有焦点圈定、逐层回传出过缺陷，恢复预览落在模块底部，标记预览已经禁用整块面板并拉通整行，承担了模态的代价却没有模态的收益。
- 连安装卡片的「详情」一起改成弹窗。它最强的理由是长路径在小卡片内展开会把同一行的相邻卡片撑高，改成弹窗后「同时只展开一张」的状态也不再需要。否：详情是设计文档明文规定由 Collapsible 承载的只读查看，读它时常要对照上方的版本轨道；用户确认的范围是其余三处。
- 把「确认恢复场景」放在弹窗主体末尾、紧跟步骤列表，即配置页恢复弹窗的做法。它最强的理由是动作贴近它确认的内容。否：步骤列表随场景长短变化，固定 footer 让确认始终可达；两处预览没有配置页那种按阶段切换动作的状态机，不需要逐阶段条件渲染的 footer。删除则直接沿用 `ConfirmSheet` 的固定 footer。
- 关闭后的焦点完全交给 react-aria 自动恢复，不手工聚焦。它最强的理由是零代码，焦点恢复本来就在 `AppDialog` 的契约里。否：实测关闭恢复预览后焦点落到页面主体，键盘用户要从头 Tab；根因是触发按钮在请求期间被禁用，恢复目标只剩 `body`。
- 收到预览时立即挂载弹窗，可以尽早展示结果。浏览器中此时读取操作还在收尾，返回或取消按钮仍禁用，错过原生自动聚焦。等待读取操作结束，使首次挂载直接获得正确焦点。
- 失败原因只显示在页面上，弹窗内不重复。它最强的理由是同一事实只有一处。否：模态下页面被遮罩且 inert，在弹窗内点「确认」后看不到任何反馈；同页的「确认客户端更新」已经把错误传进弹窗。

## Consequences

- 收益：三块面板得到统一的模态、焦点圈定、Escape、忙碌关闭与滚动契约；删除确认的逐层回传、`onDelete` 的删除回调、`!!preview` 的四处禁用，以及 `.asb-plan-confirm`、`.asb-marker-preview`、`.asb-marker-card.is-previewing` 三组专用样式删除；页面不再因预览而增高，标记卡片不再被拉通整行。
- 代价：调用方需要提供返回控件。恢复预览打开期间，页面交互由模态阻断。错误状态由操作钩子持有，在当前可交互的模态或页面中呈现。
- 删除确认使用共享的「取消」。删除成功后清空选择，焦点回到已保存场景标题。

## Verification

在关闭热更新的开发服务上挂载真实的 `ClientManagementPage`：`window.__TAURI_INTERNALS__` 桩按命令返回夹具并记录每次调用，界面语言设为中文，`requestAnimationFrame` 改由定时器驱动，点击以「控件先取得焦点再触发 click」模拟。

- 删除确认：标题、两行说明与按钮正确，焦点默认在「取消」；Escape 和取消都关闭且不发出请求，焦点回到「删除场景」；确认的载荷为 `delete_codex_project_plan { planId, expectedRevision }`，选择清空、提示更新；失败时原因显示在框内，重试成功；此前的改名失败不会被带进确认框。
- 恢复预览：标题、自动保存说明、三步变更与警告齐全；返回不发出请求，焦点回到「预览并恢复场景」；确认的载荷为 `apply_codex_project_plan { planId, expectedRevision, confirmWrite: true }`，结果与提示留在页面，焦点回到触发按钮；失败时留在弹窗内显示原因。
- 标记预览：标题、备份说明与两行差异齐全，无横向溢出；取消不发出请求，焦点回到「写入」；确认的载荷为 `apply_claude_integration { preview, confirmWrite: true }`，写入后焦点落到「清除」；无变更时只有「取消」。
- 页面可见性变为 false 时三种弹窗关闭，恢复可见后不重新出现，`#root` 的 inert 随之解除。
- 模拟 IPC 检查页无未捕获错误。原生 WebView 和真实配置写入未参与验收。
- 使用内存夹具将两个预览命令各延迟 2.5 秒。请求中隐藏并立即重新显示面板，两个响应返回后均无弹窗，焦点停在切换可见性的控件。英文深色预览宽 619px，Claude 集成卡和差异弹窗均无横向溢出，取消后焦点回到写入按钮。
- 在 Edge 中手动复核三种弹窗的打开、Esc 和焦点返回。恢复默认聚焦「返回场景」，确认恢复后页面显示结果并回到触发按钮。标记预览默认聚焦「取消」，模拟写入后焦点移到「清除」。模拟删除移除对应场景后，焦点落到「已保存场景」标题。
- 延迟 3.6 秒后返回的 Codex 预览结果和 Claude 预览错误在面板隐藏后均被丢弃，焦点留在可见性控件。活动面板的 Claude 预览失败显示错误并返回「写入」。
