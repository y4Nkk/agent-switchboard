# Agent Note: 用量监控的网关请求性能与来源边界

Status: implemented

## Problem

会话消费统计只有真实调用 Token，不能证明请求耗时、完成或首输出。两端网关账本已有独立请求事实，尚未进入用量工作区；直接把会话 Token 除以会话时间，或混合吞吐量、生成速度及推理 Token，会产生无法解释的结果。

## Decision

消费页保留原有会话统计，增加独立的网关性能区域。新的只读请求查询由 request_usage 拥有，复用 Codex 与 Claude 现行账本，不创建第二份事实库或改变持久化格式。后端统一过滤、聚合、精确分位数、趋势桶及分页，渲染层只消费有界报告；前台可见时轮询，隐藏停止。查询失败保留同筛选结果；部分来源失败时保留同筛选已有完整汇总及其旧时间，并显示本次来源错误，首次只有部分事实时明确标记不完整，不能覆盖成貌似完整的零值。

平均输出速度使用成功请求的输出 Token 除以总耗时，输出可能包含推理 Token；显示 P50 与慢端 P10。首输出为已有流解码器观察到的文本、推理或工具内容，排除元数据与结束事件，显示 P50/P95 和各自样本数。缓存命中率使用同时报告完整输入和缓存读取的成功请求，按 Token 加权；网关输入已包含缓存，不重复相加。完成率分母为已完成及失败请求；确定的客户端断连使用 499 并单列，不能推断主动取消，历史未分类中断仍为未知原因失败。失败不混入速度和首输出样本。

报告包括按客户端、供应商、实际/映射/请求模型来源分组的数据，时间和模型筛选，速度/首输出/失败率趋势，有界请求明细，Token 分项、参考费用及其覆盖数、重试与恢复数、来源保留边界。缺失指标保留 null。会话来源记录、WebSocket 握手和非模型操作不进入性能统计。参考费用只汇总账本中的本地估算，不能冒充供应商扣费。没有尝试记录时重试保持未知，统计同时说明尝试记录覆盖数。旧账本不能证明的协议细节或取消意图不补造。

Claude 现行账本保存完成时间，报告以完成时间减去已记录耗时投影为开始时间；Codex 已保存开始时间，不改变两端持久化格式。Codex SQLite 的滚动时间条件直接使用现有时间索引与有序游标，Claude 使用原有最多 10000 条的有界快照，合并后只保留请求页和末页尾部；IPC 请求明细每页 25 条，分组每页 20 条，趋势最多 96 桶。来源覆盖计数和跨度对应当前时间范围，早于供应商与模型筛选；选择全部可读取当前完整保留跨度。单请求样本仍在后端参与精确分位数，不把完整请求载荷交给渲染层。

最终记账状态由现行记录的 status 承载：部分输出为 206，失败为 502 或实际错误状态，确定的客户端写入断连为 499。206 保持现有路由健康判断中的有效 2xx 语义，但性能统计不将其视为已完整生成。原生响应对象的失败/部分状态由 transform/response 的同一函数解释，WebSocket 和 HTTP 使用同一结果；原生 SSE 仍保留原始事件字节，只修正失败与部分输出的观测。非空内容识别覆盖正文、推理、工具增量及带初始内容的块，心跳、空工具占位与终止事件不补造首输出。替换并删除 WebSocket 私有的重复 response_is_failure 判断。

## Presentation

请求性能按「筛选与新鲜度 → 核心指标 → 当前分析视图 → 按需证据」组织。ModuleHeader 拥有标题、相对更新时间与刷新，筛选字段按内容长度约束宽度，不把模型搜索扩成整行长条。四个核心指标仅在存在已核实请求时展示；没有请求、首次加载、读取失败和部分来源无可核实数据各有一个紧凑状态，不再铺开未知卡片、零值辅助行和大面积图表占位。空状态复用共享的图标、标题、动作形态；存在筛选时提供查看全部保留记录的明确动作，清空客户端、供应商和模型限制并切到全部时间，不在读取失败时暗示没有发生过请求。

趋势、供应商比较与请求明细通过共享 Tabs 切换，趋势一次展示一个明确单位的指标，释放非当前图表和表格。当前分析视图与趋势选择由面板持有，筛选更新后继续保留。Token、耗时费用、失败分类与重试分为有标题的 FactList 组，收敛到默认关闭的辅助统计；来源摘要常显，准确日期、来源跨度、保留上限和完整口径在同一个 CollapsibleSection 中按需阅读。读取错误与不完整提示保持在折叠区域之外：读取器按筛选范围保留错误直至成功，分页不清除同范围错误；恢复部分缓存时仍从其来源事实投影诊断，不能依赖已隐藏的详情才能发现问题。没有改变请求事实、聚合公式、分页或查询调度。

## Alternatives considered

- 将新指标直接并入会话消费报告，能复用全部过滤与刷新，但会把来源覆盖和计时范围混为一体，甚至重复计算同一次调用；因此采用同页独立性能区域和查询契约。
- 用总耗时减去首输出时间更接近流式生成阶段，但分子可能包含首输出前已消耗的推理 Token，且非流式请求没有该区间；因此使用可解释的完整耗时，不制造第二个模糊速度。
- 在前端读取全部请求并计算分位数最直接，但 IPC 和页面内存随历史增长；因此由账本所有者提供逐条读取，后端计算后只返回分页与趋势汇总。
- 新增持久化性能快照能减少查询成本，但会产生另一个失效和迁移边界；当前请求事实已经足够，采用只读派生报告。
- 将全部来源说明、辅助数字、三个图表和两张表同时展开，可以免去切换与展开操作，但核心数据会被长说明和横向事实串淹没，空数据也呈现大量无意义占位；因此采用明确的分析视图与按需证据，保留全部字段与诊断入口。

## Consequences

两个账本进入同一当前查询；会话记录及非模型操作被排除。有效速度、首输出、缓存、耗时、尝试和费用各有独立覆盖数；分位数基于逐请求样本，分页不改变汇总。来源失败可见，保留范围明确，缺失值不变成零。界面有中英文、筛选、分组、趋势、明细与口径说明；确定断连和流式失败不能计为完成。没有增加依赖、事实数据库、旧契约别名或双读双写。

代价是可见时重新查询账本，并在后端短暂保留分位数所需的数字样本；不是持久化缓存。极大历史的查询耗时需要实际运行后再判断，当前没有为了假定性能问题引入第二份索引。Claude 账本仅保留最近 10000 条，缺失旧记录不能恢复；历史请求只按当时已保存的计时和状态解释，不伪造回溯校正。已有账本没有推理强度、服务档位及统一流式模式，比较结果是实测请求体验，不是严格模型基准。

## Verification

隔离临时目录回归用例覆盖两端账本、时间投影、合并排序、分页不改变聚合、会话收据排除、来源损坏及原件保留；纯统计用例覆盖成功样本分位数、Token 加权缓存、缺失值、成本精度、重试恢复与原始样本合并。流测试覆盖元数据不计首输出、有效文本/推理/工具内容、原生失败帧保持字节与部分输出。按当前项目指令不执行编译、类型检查或自动化测试，不读取或写入真实用户配置；笔记结构、静态引用与组合差异另行检查，运行与桌面验收仍未验证。

界面静态审阅覆盖无数据时不挂载指标、图表和表格，辅助统计按组保留全部原字段，Tab 与面板的可访问性接线，完整来源错误保持常显，以及清空筛选后查看全部记录的动作。没有运行程序内视觉验收，浅深主题、窗口缩放与实际布局效果仍需运行确认。
