# Agent Note: 关于页可取消的更新下载

Status: implemented

## Problem

关于页的下载并安装只有文字进度，下载、签名验证和安装共用一次不可取消的前端插件调用。关闭显示或忽略回调不能终止网络传输，下载完成与安装提交之间也没有可核实的取消边界。

## Decision

原生 app_update 模块统一拥有更新候选和唯一下载任务，复用当前钉死的 Tauri updater Rust API 检查发布、下载、验证和安装。前端只接收候选身份、实际字节和任务阶段；旧 JS updater 资源、downloadAndInstall 路径、依赖和权限已移除。桌面与浏览器开发分发使用同一份 JSON 契约，界面不提交下载 URL、签名或安装数据。

Windows x64 的更新目标固定为发布所有者已有的 `windows-x86_64-nsis`，不依赖运行程序的安装器标记推断。公开 v0.3.21 清单只含此精确平台键；无安装器标记的程序默认只查 `windows-x86_64`，插件在判断版本相同之前也会解析平台，因而会把“已是最新版本”变成检查失败。客户端明确选用现行目标，不给清单增加通用别名或第二条回退路径。其他平台继续由其实际包类型选择已有发布资产，Store 更新渠道继续由系统管理。

全局错误展示仅在原始诊断尚未包含在翻译文本内时追加第二行，保留有信息差的诊断，消除 `{detail}` 和同一原始消息的重复输出。

取消由原生任务状态及 watch 信号驱动；取消等待网络的 future 会释放响应流与部分字节。签名验证完成后，取消和进入安装使用同一把锁裁决：已接受取消的任务不得安装；进入 installing 后取消返回实际状态，不伪报已取消。任务只保存当前一个状态，不写新的持久化格式；取消和失败后可从头重试，已安装结果继续使用既有重启流程。检查与下载共享原生互斥门禁，检查 guard 在离开时释放；安装完成后直到重启前拒绝再次安装。

DownloadState 包含任务 id、单调 revision、版本、阶段、downloadedBytes、可空 totalBytes 和结构化错误。下载与取消确认共用修订，前端丢弃旧任务和较早或未变化的读数。totalBytes 为零按未知处理；百分比只由有效总量和已收到字节推导，不作为安装进度。取消中仍占用任务槽，只有下载 future 和部分数据已释放后才发布 cancelled；失败保留阶段错误和签名失败的独立代码。

界面沿用现有色彩、字体、按钮与间距。任务区位于更新摘要下方、发布说明之前，显示阶段、进度条、实际下载字节和取消动作。总量未知时不显示百分比；验证和安装各有文字状态，安装阶段不伪造完成百分比。取消完成后提供重新下载入口，切换页面保留应用级任务；普通配置操作的 busy 不阻止下载取消。未知总量动效遵循系统和应用的减少动态效果设置。

侧栏消费同一个应用级更新快照，显示真实下载圆环、字节、验证、安装、取消、失败和重启状态。已知总量的百分比由既有字节算法产生；未知总量和不可量化阶段显示不定量圆弧。读取失败标明上次进度，取消请求不覆盖原生安装或终态。检查和开始下载失败由原操作所有者保留实际错误，不虚构原生任务。

侧栏没有独立计时、轮询或任务状态，与关于页共用下载阶段和字节规则。检查中禁用重复检查，进行中及终态入口打开关于页；Store 渠道仅显示系统管理状态。圆环保持原图标尺寸，展开显示阶段、百分比和读数，收起显示完整提示。按钮与锚点保持挂载，提供可访问状态，减少动态效果时停止旋转和弧长过渡。

检查失败也进入关于页展示完整结构化诊断，重试使用已有检查按钮；这样启动静默检查失败也可从侧栏查看原因，展开状态不依赖 tooltip 或通知历史。关于页读取共享快照中的真实检查阶段，业务 busy 只影响动作可用性，不能冒充检查阶段。

应用更新使用一个类型化快照和动作契约，侧栏与关于页通过同一个纯函数解释阶段、忙碌、可取消边界、旧读数和动作可用性；删除分散的更新属性传递和用 installing 表示所有忙碌的别名。读取失败保留原生阶段并单独标明读数过期，取消阶段也遵循同一规则。渠道尚未读取时禁止检查和下载；渠道读取失败明确展示原因并允许重读，不能把未知渠道当作 GitHub。

读取、取消和重启错误保留原始结构化对象，详情与提示共享诊断渲染；取消失败仍展示实际任务，重启失败仍保留已安装结果，分别允许重试对应动作。成功状态与新一轮操作清除所属旧错误，终态不再展示过期的读取或取消错误。重新检查开始时清除已结束的下载展示，避免新检查失败与旧下载失败混为一个状态。渲染回归进入现有 Node 测试发现机制；预览脚本与自动化测试共用断言，并使用互不冲突的隔离产物目录。

useApplicationUpdate 统一拥有快照、动作和检查反馈；useUpdateEnvironment 读取渠道并支持失败重读，useUpdateDownload 持有当前应用任务，useUpdateRestart 只拥有安装成功后的重启重试。一个轻量读取器在前次请求完成后再调度，读取失败保留身份和最近进度并重试，退出则使迟到响应失效。开始命令确认前发生的取消会在取得任务身份后提交；取消失败可再次操作，不能当成下载已停止。组件卸载时申请取消，安装已提交则保持实际安装状态。

## Alternatives considered

- 继续只传检查中和新版本号，接线最少，但无法反映下载或安装；改为消费已有应用级快照。
- 侧栏独立轮询或按时间补足圆环，可独立更新动画，但会产生第二份任务事实和假进度；复用既有读取器与真实字节。
- 继续逐项传递更新属性并保留 installing 忙碌别名，可以少改调用方，但会在两个工作面重复解释阶段和动作边界；取消期间读取失败的显示差异已经证明这种分散会偏离同一任务事实，因此直接替换为一个快照、动作契约和共享投影，不保留旧接口。

- 给发布清单增加 `windows-x86_64` 别名可以让旧程序自行恢复检查，但会为唯一的 NSIS 载荷留下两个平台事实来源；当前选择修正客户端的精确目标，不新增兼容清单键。

- 保留前端 downloadAndInstall 并在取消时关闭资源：改动最少，原进度回调可以复用；但插件的资源关闭并不取消已克隆的下载 future，会继续传输甚至安装，无法满足真实取消。
- 保留 JS 检查资源，只用自定义原生命令执行取消下载：可以减少检查代码迁移；但候选身份依赖 WebView 资源表，桌面与浏览器开发入口必须分别接入，释放与任务状态分属两处。统一原生所有者能直接移除这层资源生命周期与第二条下载入口。
- 自行用 reqwest 下载并另写验签和安装：可以精确控制响应头及分块落盘；但会复制插件已有的签名与跨平台安装规则，当前公开 Rust API 已提供可丢弃的下载 future，选择继续复用它。

## Consequences

已知大小显示真实字节和有界百分比，未知大小仅显示实际字节与不定量进度；取消中、已取消、验证、安装、失败及重启状态均有双语反馈。前后端、开发分发、权限、依赖锁文件、README、DESIGN 和 CHANGELOG 使用同一当前契约，没有旧 JS 资源或合并下载安装的内部入口。

插件在内存中下载并同步验签，验签时不能抢占其 CPU 代码，但原生取消裁决保证已接受取消不得进入安装。没有持久化下载、断点续传或安装过程的撤销，取消后重试会重新下载全部数据。活动任务的轻量状态每次读取完成后约 200 ms 再读，读取失败约 1 秒重试，不把读取失败当成下载已经停止；终态停止调度。

## Verification

更新状态展示在用户已授权的隔离验证范围内，使用 Node 22.23.2 运行 27 项状态、读取与渲染测试，通过前端类型检查；`scripts/test-sidebar-update.mjs` 验证中英文、展开与收起的 140 次侧栏渲染、70 次关于页任务渲染及 76 次更新摘要渲染，并编译真实样式生成 `.tmp/sidebar-update/preview.html`。覆盖零字节、已知与未知总量、下载 100% 未安装、取消与安装裁决、取消阶段读取失败、渠道未知和失败重读、取消及重启失败、终态丢弃旧错误与 Store 管理。重试主动作只有一个，完整错误只显示一次。渲染回归由现有 CI 的 Node 测试发现机制直接执行，测试临时目录独立且验证边界后清理；渲染与预览期间禁止网络请求。此验证没有调用原生更新、访问窗口或更改真实安装和配置，也不构成原生界面与实际网络下载验收。

平台目标修复后，Windows x64 隔离开发程序对公开 v0.3.21 更新清单的真实检查成功返回当前无更新，没有下载或安装。更新模块九项聚焦 Rust 测试、六项中英文错误详情渲染断言、前端类型检查和隔离开发编译通过。没有给远程发布清单增加别名，也没有更改远程资产；此证据不覆盖下载、验签和安装流程。

新增隔离原生夹具覆盖无响应头取消、停滞 future 的载荷释放、成功与失败透传、签名错误、验签取消与安装提交裁决、晚到进度失效、检查门禁释放及安装后阻止重复提交。前端夹具覆盖已知和未知大小、迟到和未变化修订、慢读取不重叠、终态停读、读取失败重试及停止后抑制迟到结果。

取消下载最初实现时按项目约束未执行编译、类型检查、自动化测试或安装器调用；当时仅检查笔记结构、JSON/锁文件一致性、差异、旧接口及直接引用，并按 React 清单人工检查 hook 生命周期和可访问性。后续平台目标修复的实际执行结果见上文；真实下载取消、签名验证、跨平台安装重启、键盘交互及实际窄窗/主题展示仍未运行验收，不能以源码或夹具存在代替通过。
