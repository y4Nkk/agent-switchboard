# Agent Note: 全局来源消息的应用级删除生命周期

Status: implemented

## Problem

来源 Hook 中的确认和删除集合随页面卸载销毁，用量页切换页签、隐藏窗口或切换页面会让相同来源重新提示。转换入口使用固定身份，新的来源集合会继承旧提示的删除状态。删除最后一条消息同时移除弹层触发器，键盘焦点没有稳定恢复目标。

## Decision

InformationSources 在应用外壳生命周期内唯一拥有来源消息、确认和删除状态；来源以 sessions / usage 稳定命名发布，Hook 不再拥有消息状态或使用挂载生成身份。纯状态转换由 information-source-state.ts 拥有，Provider 只负责派发与派生可展示消息；消息身份去重同样在状态所有者执行，生产者不重复维护去重路径。卸载或报告暂不可用时发布 null，仅撤销可展示内容与动作闭包，保留有界状态；重新发布按当前消息身份裁剪状态，成功空快照清除旧状态。新问题重新提示、同一问题重新发布和切换语言不恢复已删除消息；已删除状态不能被迟到的确认降级。按用户选择，退出应用清除全部状态，不增加持久化存储。

转换入口以排序去重后的真实 conversionId 集合作为身份，新的集合与旧删除状态隔离。全局信息入口保持稳定，清空后展示双语空状态；列表行与清空操作通过面板收起按钮的引用恢复焦点，不沿 DOM 查找相邻行或用选择器推断组件关系。关闭后由共享弹层回到仍然挂载的入口。

## Alternatives considered

- 保留每个来源 Hook 的本地状态：离消息生产者最近且实现较短，但状态寿命由界面挂载决定，无法兑现切换页面不恢复的要求；不保留这条路径。
- 保活页面以保存删除状态：可沿用当前 Hook，但将全局交互状态绑在昂贵页面的保活策略，且不解决消息身份冲突；只保留来源状态与当前展示声明。
- 持久化通知历史或删除名单：可以跨重启恢复，但用户明确选择仅本次运行有效，新增落盘契约没有必要。

## Consequences

- 删除或确认后的消息在来源卸载、重新挂载、语言切换后仍维持对应状态；只保留两个明确来源最近快照中仍存在的状态，不扩展为消息历史。
- 来源解决后的成功快照移除旧状态，复发与新的转换集合正常提示。未发布新扫描结果前保留最近已知状态，不以加载或页面释放推断问题消失。
- 状态不跨来源串用，卸载不保留 React 内容或动作闭包，空快照不会无限积累删除身份。
- 清空移除可删除消息，持续修复错误与真实处理状态保持；删除最后一条后入口与焦点稳定。代价是标题栏无通知时也保留一个中性入口与零计数。
