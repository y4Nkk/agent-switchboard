# Agent Note: 工作区复用分组设置布局

Status: implemented

## Problem

客户端配置用多行堆叠呈现设置名、说明、当前值、控件和待应用内容。字段较多时，编辑和审阅竞争同一滚动空间，提交操作离正在编辑的字段很远。偏好设置、关于、备份恢复、客户端工具和供应商编辑页各自排布正文，视图间的标题、表单和操作位置缺少共同基准。

## Decision

共享组件提供限宽正文、分组标题与内容面、设置行。普通控件横排，长编辑器、图形预览和窄工作区纵排。设备图、应用标记、偏好选项插画和模型图形由调用页面提供。配置、设置分类和供应商编辑器的页签仍由各自页头渲染。

Codex 与 Claude 的页头和表单共用一个纵向视口。「保存并预览应用」、草稿操作和提交反馈在视口右下角悬浮，与「返回顶部」并排。悬浮组在内容末尾按自身高度占位，滚到末尾时可完整查看最后一个设置项。恢复入口沿用共享危险按钮样式。偏好设置、关于、备份恢复、客户端工具及供应商新建和编辑的各页签接入共享正文结构，继续使用各自的写入、滚动和确认流程。

待应用数量由预览准备的变更集合得出，结构化额外配置算作一个编辑项。字段的代码入口按需显示已读取的文件值。表单的差异由确认弹窗使用后端生成的候选呈现。目录、来源、原文、指令和恢复入口各自继续使用现有操作流程。

## Alternatives considered

- 组跳转条可直达长表单中的偏远字段。已确认的设计偏好是从页头直接进入分组，整张表单使用连续的阅读顺序。
- 行内实时差异能指出单字段变化，方便核对当前编辑。用户在提交前集中审阅改动，行内保留只读文件证据便于查询已有值。
- 统一完整工作区外壳能同时收编页签和页尾。客户端配置、维护和供应商编辑的滚动、导航与动作归属不同，共用正文结构可让各页独立安排这些入口和图形。
- 独立底栏能分隔正文与操作。它持续占用整行视口高度，页面改用只有控件自身宽度的悬浮操作。视口为焦点滚动保留底边空间，内容末尾容纳整组控件。

## Consequences

编辑行聚焦当前操作，提交前可在一个弹窗完整核对影响。行内代码入口提供文件原值，维护档案级参数时仍可看到档案已保存值。从页头切换客户端后，进入端的视口回到页头，便于继续切换及保持键盘焦点可见。

集中审阅需要多一次打开确认窗口。限宽布局会让长英文和复杂编辑器在部分窗口中更早换行。悬浮按钮可随可用宽度换行。页面决定各自的图形、预览卡、滚动和确认动作，便于大图或时间轴使用合适的布局。窄工作区的实际换行和键盘焦点待桌面验收。

## Verification

静态核对两个配置分支、四个设置分区和两端供应商的共用入口。备份设备、客户端工具图形、偏好 SVG、关于标记和供应商模型图仍由相应文件渲染。检查客户端表单只读代码与提交弹窗的数据来源，并验证旧的行内差异入口和样式引用。

在隔离 Chromium 中用当前源码和示例配置验证了两端的滚动效果。滚动后页头退出视口，悬浮按钮纵向位置一致，并与返回顶部对齐。滚至末尾时最后一个设置项完整可见，悬浮保存按钮可打开差异确认。原生桌面窗口待实测。
