# Agent Note: 请求性能以趋势与比例建立信息层级

Status: implemented

## Problem

性能页的留白调整后仍以四张文字卡、单张趋势图与五组细分事实平铺信息。成功、缓存、失败和重试需要逐条阅读，缺少可直接比较的形状；只增加间距不能解决信息杂乱。

## Decision

概览的速度与首 Token 使用报告现有时间桶绘制迷你趋势，成功率与缓存使用固定 0–100% 比例环。网络范围的典型耗时使用迷你趋势，最慢 5% 和记录数保留后端事实，不虚构其时间序列。

分析区继续使用唯一主图与共享页签。细分保留 Token 和耗时的独立横向比较，将失败与重试合并为请求质量组：失败原因用互斥构成条，重试记录/含尝试次数的记录和重试成功/重试记录各用独立比例条，重试次数保留计数。没有失败直接说明零失败，没有尝试字段不推断重试。

数据来源保留共享表格与模型筛选前的语义，在记录数列内增加同尺度条形；时间仍为文本。全部指标保持常显，不改变采集、筛选、分页和切换动画。

`request-trend.ts` 唯一投影性能趋势：保留报告中的空值，对后端省略的无记录时间桶插入空值断点，主图与迷你图消费相同的点序列，不补零或补算指标。共享 `UsageTrendPoint.value` 接受明确的 `number | null`，归一化保留缺口并排除没有有效值的整条序列；图形断开空值，读数、坐标范围与样本数只消费真实数值，孤立点可见。Token 和耗时组在全缺样本时保持标题、破折号与空缺轨道，来源时间未知时明确显示未记录。移除旧 `moreStats` 消息标识和被取代的排版选择器，不保留第二套性能图表路径。

## Alternatives considered

- 继续增大间距最容易落地，也不会改变图表含义；但文字密度和多组信息同权重的问题仍然存在。
- 把全部指标换成环图可统一外观，但 Token 含缓存/推理子集，耗时分位数也不是可相加的组成，环图会制造错误的占比语义。
- 用折叠或更多页签减少首屏内容能明显缩短页面，但会重新隐藏已有常显事实。保留全部事实，通过主图、概览图形和按主题分组建立层级。

## Consequences

概览只绘制后端真实趋势与比例；缺失时间桶断开，未知比例使用虚线环而不补零。失败构成、重试比例与来源记录数均保留数值及标签，读图不依赖颜色。零失败显示文字，尝试字段未报告时显示未知和具体原因；已知没有重试时不绘制无分母的恢复比例。相比原五块平铺，细分归为 Token、耗时、请求质量三组与末尾来源表，全部事实仍常显。

迷你趋势没有交互坐标，只作为有标注的概览补充，精确时间与数值仍由主分析图提供。实际桌面布局与交互效果需要另行运行验收。

## Verification

`tests/request-trend.test.ts` 包含稀疏历史断开、显式未知值、真实零值、长空档有界投影、共享序列保留缺口和全空序列排除的回归用例。已执行验证限于组合差异、直接消费者与过时引用审阅、冲突标记检查和 `npm run verify-notes` 笔记结构校验。遵守项目当前约束，新用例与编译、类型检查、自动化测试均未运行；没有声称实际桌面布局、键盘交互或真实数据渲染已验收。
