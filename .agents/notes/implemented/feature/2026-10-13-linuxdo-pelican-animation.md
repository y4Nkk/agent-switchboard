# Agent Note: Linux.do 鹈鹕动画题与完整 HTML 预览

Status: implemented

## Problem

Linux.do 的[共建实验帖](https://linux.do/t/topic/2702004)与[鹈鹕跑分帖](https://linux.do/t/topic/2716797)反复采用「生成html，内容是svg绘制鹈鹕骑自行车2D动画，不用进行测试。」。经典英文题只要求 SVG；从 HTML 中抽取 SVG 再用图片显示，会丢掉文档外层 CSS 和脚本，不能完整观察动画。

## Decision

- 题库只保留一道 `pelican-riding-bicycle` 鹈鹕题，以 Linux.do 的 HTML/SVG 2D 动画题为标准，不提供经典英文题或独立动画题入口。题干显示并保存社区原文和「直接在最终回答中输出完整 HTML 源码，不要只返回文件路径或完成说明。」这条输出要求，避免用户误以为与社区调用条件完全相同。
- 鹈鹕题排在后端题库首位，是降智雷达的默认选中题（前端默认取目录第一项，下拉框同步把鹈鹕题排第一）。题目目录与其 DTO 不携带来源字段，界面不再提供「查看题目来源」链接；社区出处的归属只保留在 README 文档中。
- 题干下方直接内嵌显示「参考画面」：后端题库以 `include_str!` 内嵌一份人工制作的完整 HTML 参考渲染（`pelican-reference.html`），经题目 DTO 下发；前端用与运行结果同一条预览管线派生 srcdoc 并注入 CSP，策略单一归属 `probe-html.ts`，参考画面自身不携带副本。参考画面只演示一种可行的输出，不是期望答案，不参与判分，也不是评分基准；视觉题结果仍由人工观察。雷达模块不做展开/收起交互：回答只有内联预览加复制，原文不设折叠或弹层查看。
- 参考作品是独立、无外部依赖的 16:9 HTML/SVG 海边骑行场景。车轮与木板路位移共用滚动距离；曲柄按前后齿盘半径比驱动，双踏板相差半周，腿部按固定骨长向前屈膝、脚底保持贴合踏板，翼尖固定在车把上。云、海浪与远景按层缓慢流动，区别于地面速度；所有运动由单一动画时钟拥有，暂停时一起停下，恢复时接续相位。内置暂停/播放按钮可键盘操作；减少动态效果时默认静止，隐藏或离开可见区域暂停调度，重新可见时不补跳时间。HTML 本身锁定视口与溢出，不给参考画面增加内部滚动。
- 题库每题携带 `max_runs` 上限，鹈鹕题为 1：一道动画足以人工观察，多代对比交由自定义题完成。上限由题目目录唯一拥有，start 命令对超限次数明确报错，前端把预设 3/5 次改为自由输入（1..=10）并在上限为 1 时锁定输入。HTML 预览以 16:9 比例随宽度完整显示，固定像素高度与内部滚动移除。
- 已有 `grading_version` 增加 `html-visual-v1`，唯一决定完整 HTML 输出与人工观察；整数、SVG、HTML 三种显式格式共用已有开始、历史回填、保存和删除链路。视觉格式没有期望整数，也不产生自动通过或失败。
- 原始最终回答继续只保存在 `probe_runs.final_answer`。从回答中的单个 HTML 代码块或完整 HTML 文档派生 `srcdoc`，不把预览文档另存为文件或浏览器缓存。
- HTML 以独立来源的 iframe 预览，只开放脚本执行以支持动画；禁止同源访问、顶层导航、弹窗、表单和下载。文档最前面加入 CSP，禁止外部子资源与连接，允许内联 CSS/脚本和内嵌图片。SVG 仍使用图片上下文，HTML 不走 SVG 截取路径。
- 预览是原始输出的展示，不修复模型的图形或动画，不把成功解析当成通过。缺失可预览内容时保留原文并提示，生成耗时及配置快照规则不变。

## Related decisions

检索活跃笔记中的 `pelican`、`鹈鹕`、`codex_probe`、`降智雷达`。[SVG 回答与缓存](../../implemented/feature/2026-10-13-pelican-probe.md)部分重叠，其 SVG 自定义回答、已保存的格式契约、原文缓存和人工观察决定仍然有效，双方互链；本篇拥有单一鹈鹕题的现行题干与 HTML 动画展示。[会话操作布局](../../implemented/bug-fix/2026-09-24-session-operations-layout.md)不涉及输出格式，保留。其余诊断和用量笔记无关，无需归档。

[题库限时与真实检测进度](2026-10-20-probe-deadline-progress.md)拥有题目执行预算和单次计时，题干、预览和人工观察规则仍由本篇拥有。

## Alternatives considered

- **保留经典 SVG 与社区动画两道题**：能比较两个不同输出任务；用户明确要求只实现一道题并以 Linux.do 为标准，因此题库只保留社区题，不建立别名或第二个入口。自定义 SVG 回答是通用输出方式，不是另一道鹈鹕题。
- **只改题干，继续抽取 SVG 图片**：可复用全部展示代码；但会丢失外层样式和 JavaScript 动画，让显示缺陷被误认为模型能力问题，所以 HTML 使用独立文档预览。
- **用互相独立的 CSS 循环驱动车轮、曲柄和腿部**：标记短、无需逐帧求解；但各部件相位与速度容易脱节，暂停也会留下第二套时钟，因此参考作品统一按距离推导运动，只用原生脚本更新 SVG，不引入动画依赖。
- **完全复用社区题干并收集工作目录里的生成文件**：与社区 agent 调用的提示更接近；但文件发现、主入口选择与关联资源归档引入另一种输出契约。用户要求直接输出显示，因此明确要求完整源码作为最终回答，且这条要求随题干保存和展示。
- **在应用文档中直接注入 HTML**：尺寸和交互最容易复用；但模型脚本会与应用共享页面权限，所以只在不开放同源权限的 iframe 执行。
- **引入社区自动评分**：可批量比较；但跑分帖作者明确指出基线偏向 Grok 样本且其他模型可能测不准，也不符合用户要求的人为直接观察，因此不接入自动判定。

## Consequences

- 鹈鹕题只有一个 ID 与标签，排在题库首位并作为雷达默认题；完整实际题干在当前页与历史中可见，复用历史不改变原文。经典英文题、第二个动画题 ID、目录来源字段与「查看题目来源」入口移除。
- 参考画面随二进制内嵌，随题目目录实时下发，不进批次快照与历史；自定义题与整数题没有参考画面。「首项即默认题」契约由题库测试固定；README 与 DESIGN 的产品/设计事实随本批改动同步。
- 参考作品的静态 SVG 也保留完整场景与骑行姿态；脚本负责连续运动与暂停交互。维护时需要保持骨长、踏板圆周、齿盘与车轮半径的关系，不能只调整单个循环速度。源文件仍由 Rust 编译时内嵌，更新 HTML 后须重新构建桌面应用才会进入已安装版本。
- HTML 的样式、SVG 与内联脚本共同交给 iframe；原始回答经现有本地历史持久化，重开详情不发起模型调用。没有新增文件收集、数据库迁移或第二份文档缓存。
- 自定义 HTML 题、运行结果、汇总和历史均为人工观察；整数题规则不变，未知规则仍拒绝。HTML 不再落入只抽取 SVG 的展示路径。
- 回归用例覆盖完整题干与历史复用、视觉输出不判分、原文存取及历史删除、HTML 代码块与文档提取、CSS/脚本保留和 CSP 前置。依赖整数判分的 runner 用例显式引用计数题 ID，不依赖目录顺序。用例新增或更新，遵照项目指令不执行编译、类型检查或自动化测试。
- 验证范围为项目要求的笔记结构校验、差异审查与参考作品的静态 SVG 渲染检查。浏览器策略禁止直接打开本地 HTML，动画播放、暂停和减少动态效果仅做源码审查，未通过浏览器或原生 WebView 实测；真实 CLI 调用与重启恢复未实测。
- iframe 依赖系统 WebView 的 CSP、sandbox 和动画能力；外部依赖被阻止，预览不等同于完整浏览器网站托管。
- 直接输出的要求会影响生成条件；工具、技能和推理强度不同的社区作品不能当作受控的同条件对照。
