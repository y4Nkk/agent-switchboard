# Agent Note: 会话即时搜索与筛选弹窗

Status: implemented

## Problem

会话全文搜索需要单独提交。时间、标签和置顶筛选平铺在搜索框旁，占用输入区域，选择自定义日期时还会拉长工具栏。

## Decision

会话和已归档页签在停止输入 300ms 后查询文本，输入法组合结束后开始计时。多行文本和粘贴内容走同一入口，清空时立即查询当前筛选下的列表，关键词变化回到第一页。工作区隐藏时取消待执行的计时，重新可见后用保留的输入计算查询。搜索的取消、进度和结果身份沿用[会话搜索生命周期](../bug-fix/2026-10-23-session-search-lifecycle.md)。

搜索框右侧使用一个标准尺寸筛选图标按钮，复用 AppDialog 承载最近活动时间、标签和仅看置顶。筛选沿用即时生效逻辑，按钮用圆点和可访问名称提示已启用的条件。自定义日期在弹窗内展开。日期字段、有效范围提交及无效草稿边界由[会话弹窗控件](../architecture/2026-11-24-session-dialog-control-boundaries.md)统一。

## Related decisions

- [会话操作与长内容布局](../bug-fix/2026-09-24-session-operations-layout.md)继续拥有工作区和详情布局，搜索行的筛选位置由本篇接管。
- [共享按钮尺寸](../bug-fix/2026-10-23-session-search-button-geometry.md)继续拥有全局按钮尺寸和样式优先级，原搜索提交按钮及其行内间距已移除。
- [共享日期选择器](../architecture/2026-10-15-global-date-picker-primitive.md)继续拥有日期控件行为，筛选容器改为弹窗。

## Alternatives considered

- 每次编辑都查询，输入与结果的延迟最低。全文搜索需要读取本地索引和会话，在连续按键及输入法选字时反复启动和取消任务会增加读取开销。
- 在弹窗内暂存所有条件，集中点击应用可合并连续操作。筛选现有即时生效契约足以支持本次工具栏收拢，独立草稿会增加确认动作和状态。

## Consequences

- 输入停顿期间保留当前结果，新关键词触发查询时取消旧请求。筛选入口少占一部分行宽，查看条件需要打开弹窗。
- 项目限制本次验证为静态差异、引用和笔记结构检查。桌面上的输入法、弹窗焦点与日期选择仍待运行验收。
