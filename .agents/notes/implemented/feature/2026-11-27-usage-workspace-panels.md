# Agent Note: 用量监控的独立工作面板

Status: implemented

## Problem

用量工作区的多类操作集中在分类导航行。用户需要回到页首刷新某个额度来源、配置检测，或者切换性能范围。资源占用把软件概览和进程明细夹在同一张表内。扫描、口径和作用范围的常驻文字占据读数空间。

## Decision

共享工作区页头和单一纵向滚动区。请求性能依次展示采集状态、筛选、概览、分析、细分和来源。采集设置按钮打开共享弹窗，每个客户端使用共享 Switch 表达配置文件中的采集状态。切换打开配置差异预览，取消时开关保留原值，确认后根据重新读取的配置更新开关并提示重启客户端。本机接收的地址和计数使用带图标的 FactList。「重置与额度」将公开重置信号放在首位，供应商额度和官方账号额度顺序排列，各自提供刷新。资源用三张软件概览卡配全宽进程明细。雷达按检测配置、进度、题目和结果组织，历史从分类导航行进入。沿用共享控件、可见性、原生读取和写入预览。

性能失败原因使用与网关相同的分段环形图，保留实际有分母的比例、独立样本数和计量缺口。平台采样口径按需展开，公开信号的出处及时间放在所属页签。雷达样本覆盖放在用量指标下，运行成本放在开始动作旁。状态和错误靠近受影响的操作或读数。

## Alternatives considered

- 将四页套入同一布局模板能快速统一外观。计量报表、资源对比和可写配置的主操作位置不同，共享视觉原语即可。
- 一律使用环图能让图表更统一。性能用量中的子集和耗时分位数没有可相加的分母，继续使用同尺度比较。
- 页内展开设置可以直接看到报表。启停配置需要独立的焦点和确认步骤，设置弹窗也让报表在打开配置时保持原滚动位置。

## Consequences

额度刷新位置随来源分开。资源卡在窄容器换行，选择软件后把其全宽进程明细带入视区。性能各细分维持常显，保留原有请求、模型分页及统计区间。雷达开始和取消分别沿用当前任务动作，按需读取结果并复用历史回填。桌面显示、窄窗滚动和键盘焦点由运行验收确认。
