# Agent Note: 扩展市场与联网更新

Status: implemented

## Problem

Skill 已能检查 GitHub 来源，但入口隐藏在来源选择中。skills.sh 公开搜索的 `count` 是返回条数，改变 `offset` 不会获得新结果。历史恢复可改变内容而保留来源 commit，只比较 commit 会漏掉更新；摘要命中历史内容也无法判定这次用户选择的是上游更新还是恢复。MCP 定义缺少在线目录及后续更新所需的来源身份，手动迁移连接后需要能够继续追踪新版本。

仓库目录为每个仓库的三个请求持续绘制轨道。仓库较多时，当前读数和失败原因容易淹没在已完成与未请求的轨道中。

GitHub 归档开头的提交元数据被当成特殊条目拒绝。两个默认来源另有仓库迁移和整仓 Skill 数超限的问题。管理页只给出失败状态，用户需要返回市场查看原因，再手动修改和重试。

## Decision

仓库目录扫描按配置顺序解析仓库，共享 45 秒的 GitHub 请求截止时间。每次请求最多使用截止前的剩余时间，包含响应体读取。截止后跳过剩余 GitHub 请求，已完成的候选照常返回。每轮扫描持有一份按请求标识读取的进度快照，原调用结束时带回最终快照。Rust 在发起读取、收到 HTTP 响应头、读到响应字节和完成仓库校验时更新它。桌面和浏览器开发模式每 300 毫秒读取一次当前轮的快照。记录在这轮调用结束时释放，最后一次的请求证据随界面结果显示。

整批扫描使用一个按已处理仓库数推进的进度环。仓库行显示当前请求阶段及实际字节数，结束后显示候选数或具体失败原因。提交引用、目录树和压缩包的 HTTP 与读取明细收在对应仓库下，默认折叠。

仓库管理和扫描结果从同一份扫描终态读取失败原因及一键解决动作。临时网络错误可以重试。旧 `cexll/myclaude` 地址被重定向时提示改为 `stellarlinkco/myclaude`，Composio 默认整仓超限时提示改扫 `document-skills`。默认目录直接使用这两个可扫描的配置。点击前显示目标地址或子目录。恢复复用目录刷新，并在共享时间预算内优先请求失败项。地址及范围改动在新位置找到候选且原记录仍匹配时一起保存，重扫失败的记录保留原配置。归档读取接受开头与所请求提交一致的 Git 提交注释，文件和目录仍参加原有校验。 [Git 归档格式](https://git-scm.com/docs/git-archive)

仓库扫描遇到 GitHub API 限流后结束本轮剩余的网络请求，应用进程内共享最早可重试时间。使用响应中的 `Retry-After` 和配额归零时的 `X-RateLimit-Reset`，两者都有时遵守更晚的时间。确认限流但缺少可用时间时，按 GitHub 指引等待至少一分钟。两个入口都显示恢复时间，到期后由用户触发刷新。 [GitHub REST API 限流](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api#exceeding-the-rate-limit)

扫描以 GitHub 的提交 SHA 媒体类型重新确认仓库与引用，已有结果用上次 SHA 作条件请求。提交不变时复用该仓库、子路径、引用对应的已验证候选。提交变化时读取钉住的新目录树和归档，网络失败由当前扫描反馈。市场与安装共用一份进程内候选库，保留最多 512 个候选、256 MiB 文件内容和 64 份仓库定位记录，整批发布本次扫描的可用候选。[GitHub 提交接口](https://docs.github.com/en/rest/commits/commits#get-a-commit)

扩展市场沿用本机扩展工作区与来源解析。Skills 搜索一次最多请求 200 条，结果由后端校验、去重，界面按本次实际返回的可用条目本地分页。Skill 的市场详情解析为固定 GitHub 提交，安装在下一步明确提交。候选标识同时绑定来源、子目录、引用、提交和内容摘要；摘要继续标识版本库中的文件。版本变更显式选择上游候选或历史摘要。上游更新校验来源、候选和定义修订，并记录本次选中的上游提交，即使已保存相同内容；恢复历史只读取版本库并保留上次同步的来源。两种操作都从实际内容同步 manifest 和兼容性信息。

MCP Registry 读取使用固定 HTTPS 主机、最新版本过滤和游标。扩展元信息拥有可选的来源全名、已保存版本和端点，普通元信息编辑保留这份来源。具备唯一、具体、无额外必填请求头的 HTTPS Streamable HTTP 端点时可预填。更新预览确认后，后端重新读取候选并校验动作、定义修订、版本和端点。同源更新可以替换仍等于记录值的 HTTP 端点，按现有扩展计划部署。手动迁移提示发布的 HTTPS 端点、传输和必填请求头。保存连接后，检查更新比对这些字段，匹配时经单独确认，仅在扩展库记录对应的目录版本。

## Alternatives considered

直接跟随迁移重定向可以省掉用户操作。安装候选的身份包含仓库地址，已知迁移先显示要切换的地址，再按目标仓库固定提交并验证候选。

提高候选上限可以保留 Composio 整仓目录。整仓当前有 864 项，扩大共享上限会增加每轮保留和传输的内容。这个默认来源使用仓库已发布的文档子目录，用户可以编辑为所需的其他子目录。

收到限流后继续扫描可以收集更多仓库的失败细节。目录请求共用 GitHub API 配额，后续同类请求要服从响应给出的等待时间。扫描保留已完成结果，未发出的请求以限流原因结束。

按显示名匹配可省去持久化来源字段，并覆盖已有的手动定义；本地名称可改且服务名可能跨命名空间重复，因此记录用户选中的目录身份。

按 commit 快速跳过可少下载一次文件；历史恢复保留来源 commit 时会产生误报，因此检查以内容摘要为准。

延长 HTTP 缓存的有效期可省去仓库查询。重复扫描需要确认用户配置的引用是否前移，因此只复用验证为相同提交的不可变内容。

沿用 `offset` 可以把每次响应限制为一页，但线上接口重复返回同一批结果。请求经实测支持的结果上限，把翻页交给一次搜索的本地快照。

普通编辑时自动更新 MCP 的目录记录可以少一次确认，但用户可为其他目的修改 URL 或认证配置，不能由这些编辑推断已迁移到新版本。显式关联以最新目录的连接声明和当前配置为凭据。

界面单独计时可以及时恢复按钮。后端仍在读取，界面会丢失本轮已成功的候选。

并发请求可以缩短扫描时间。多个仓库的压缩包和候选内容会同时占用内存，整批等待仍需要截止时间。

Tauri IPC 通道可以推送字节进度，省去轮询。仓库扫描也通过只有命令响应的本机浏览器开发桥调用。按扫描标识读取轻量快照，可以让两种入口共享真实进度和终态。

每阶段独立轨道可以直接比较请求的传输比例。已完成和未发起的请求也会占据同样的空间，当前请求难以快速定位。

将全部请求和仓库状态收在一个详情区，可以给候选列表留出更多空间。实际传输读数和失败原因都需要展开查找，扫描期间难以直接判断卡在哪一步。

## Consequences

隔离黑盒读取开发机的 21 个实际 Skill 和 21 条绑定，旧目录用发布版的四条默认配置构造。用无窗口 Chromium 经浏览器开发通道调用真实 Rust 后端与 GitHub，旧仓库地址和扫描范围一次修复后得到 58 个候选，重启再次读回并刷新成功。旧快照与外部编辑冲突或新归档下载失败时，目录文件逐字节保留。受控 HTTPS 响应给出 429 和两种恢复时间，界面和后端在较晚时限前停止请求，时限后重新开放。此验收覆盖目录行为和写盘，Windows 原生窗口未纳入。

仓库较多或网络较慢时，本轮可能只返回部分结果。扫描已完成的数据仍可用，后续扫描可通过缩小启用范围减少请求。

当前请求的 HTTP 状态在响应头到达时即可查看。响应体下载失败、仓库被拒绝和截止后跳过的阶段各有可辨认的状态。下载总量缺失时展示实际收到的字节数。排查先前请求需要展开所属仓库，失败原因直接保留在仓库行。

手动录入的 MCP 没有目录更新身份。新域名、传输、必填配置由用户在编辑器中配置，具体 HTTPS Streamable HTTP 或 SSE 连接可在配置后关联版本；发布包和模板地址继续由文档指引。Registry 确认会额外执行一次目录读取，避免过期预览写入。Skill 市场搜索使用项目既有的 skills.sh 公开搜索端点，翻页只在一次查询返回的结果范围内进行。
