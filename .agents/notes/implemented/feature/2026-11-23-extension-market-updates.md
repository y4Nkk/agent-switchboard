# Agent Note: 扩展市场与联网更新

Status: implemented

## Problem

Skill 已能检查 GitHub 来源，但入口隐藏在来源选择中。skills.sh 公开搜索的 `count` 是返回条数，改变 `offset` 不会获得新结果。历史恢复可改变内容而保留来源 commit，只比较 commit 会漏掉更新；摘要命中历史内容也无法判定这次用户选择的是上游更新还是恢复。MCP 定义缺少在线目录及后续更新所需的来源身份，手动迁移连接后需要能够继续追踪新版本。

## Decision

仓库目录扫描按配置顺序解析仓库，共享 45 秒的 GitHub 请求截止时间。每次请求最多使用截止前的剩余时间，包含响应体读取。截止后跳过剩余 GitHub 请求，已完成的候选照常返回。每轮扫描持有一份按请求标识读取的进度快照，原调用结束时带回最终快照。Rust 在发起读取、收到 HTTP 响应头、读到响应字节和完成仓库校验时更新它。桌面和浏览器开发模式每 300 毫秒读取一次当前轮的快照，进度条按已处理仓库数计算。记录在这轮调用结束时释放，最后一次的请求证据随界面结果显示。

扩展市场沿用本机扩展工作区与来源解析。Skills 搜索一次最多请求 200 条，结果由后端校验、去重，界面按本次实际返回的可用条目本地分页。Skill 的市场详情解析为固定 GitHub 提交，安装在下一步明确提交。候选标识同时绑定来源、子目录、引用、提交和内容摘要；摘要继续标识版本库中的文件。版本变更显式选择上游候选或历史摘要。上游更新校验来源、候选和定义修订，并记录本次选中的上游提交，即使已保存相同内容；恢复历史只读取版本库并保留上次同步的来源。两种操作都从实际内容同步 manifest 和兼容性信息。

MCP Registry 读取使用固定 HTTPS 主机、最新版本过滤和游标。扩展元信息拥有可选的来源全名、已保存版本和端点，普通元信息编辑保留这份来源。具备唯一、具体、无额外必填请求头的 HTTPS Streamable HTTP 端点时可预填。更新预览确认后，后端重新读取候选并校验动作、定义修订、版本和端点。同源更新可以替换仍等于记录值的 HTTP 端点，按现有扩展计划部署。手动迁移提示发布的 HTTPS 端点、传输和必填请求头。保存连接后，检查更新比对这些字段，匹配时经单独确认，仅在扩展库记录对应的目录版本。

## Alternatives considered

按显示名匹配可省去持久化来源字段，并覆盖已有的手动定义；本地名称可改且服务名可能跨命名空间重复，因此记录用户选中的目录身份。

按 commit 快速跳过可少下载一次文件；历史恢复保留来源 commit 时会产生误报，因此检查以内容摘要为准。

沿用 `offset` 可以把每次响应限制为一页，但线上接口重复返回同一批结果。请求经实测支持的结果上限，把翻页交给一次搜索的本地快照。

普通编辑时自动更新 MCP 的目录记录可以少一次确认，但用户可为其他目的修改 URL 或认证配置，不能由这些编辑推断已迁移到新版本。显式关联以最新目录的连接声明和当前配置为凭据。

界面单独计时可以及时恢复按钮。后端仍在读取，界面会丢失本轮已成功的候选。

并发请求可以缩短扫描时间。多个仓库的压缩包和候选内容会同时占用内存，整批等待仍需要截止时间。

Tauri IPC 通道可以推送字节进度，省去轮询。仓库扫描也通过只有命令响应的本机浏览器开发桥调用。按扫描标识读取轻量快照，可以让两种入口共享真实进度和终态。

## Consequences

仓库较多或网络较慢时，本轮可能只返回部分结果。扫描已完成的数据仍可用，后续扫描可通过缩小启用范围减少请求。

HTTP 状态在响应头到达时即可查看。响应体下载失败、仓库被拒绝和截止后跳过的阶段各有可辨认的状态。下载总量缺失时展示实际收到的字节数。

手动录入的 MCP 没有目录更新身份。新域名、传输、必填配置由用户在编辑器中配置，具体 HTTPS Streamable HTTP 或 SSE 连接可在配置后关联版本；发布包和模板地址继续由文档指引。Registry 确认会额外执行一次目录读取，避免过期预览写入。Skill 市场搜索使用项目既有的 skills.sh 公开搜索端点，翻页只在一次查询返回的结果范围内进行。
