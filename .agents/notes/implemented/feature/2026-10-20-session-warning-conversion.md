# Agent Note: 会话来源提示确认与 workflow 完整转换

Status: implemented

## Problem

Claude workflow 的 journal.jsonl 保存执行事件而非带 sessionId 的会话消息。递归发现将它交给普通会话身份解析器，使会话和用量页面持续报告缺失身份。两个页面没有确认关闭入口，长路径挤占阅读区域。直接跳过文件会遗漏仍可阅读的事件；往原文件补会话字段则会改变客户端自己的执行数据。

## Decision

来源发现明确识别 Claude 项目下的主会话/subagents/workflows/workflow/journal.jsonl。会话页面将其报告为可转换的事件来源，转换标识绑定后端解析的文件身份和完整内容摘要；前端只提交这些标识，不能提交路径。用量汇总只消费真实会话来源及调用收据，workflow 事件与转换记录不进入会话覆盖数量或 token 计量。

来源键只哈希按本机 Path 组件重新组成的路径，使 Windows 的正反斜线及冗余分隔符不会给同一来源生成不同身份；发现、转换请求与副本重读共用这一入口。不使用依赖原件仍然存在的文件系统 canonicalize，也不双读旧路径哈希。原始来源位置仍按原样保存。

用户点击一键完整转换后，后端逐文件流式读取全部有界 JSON 记录，在应用 state/sessions/converted 生成当前唯一格式的消息快照。每条消息保留该事件的完整 JSON 字段、原始事件时间及稳定标识；缺失时间保留未知。快照拥有确定的独立记录身份、原始来源位置、所属主会话和真实项目目录，恢复操作回到主会话。源文件不被写入。单文件存在损坏、超限或尚未写完的记录时，该文件不发布部分快照；原文件扫描前后的内容摘要必须一致。发布复用既有同步与原子替换边界，发布前失败保留上次完整快照；移动后持久化尚未确认时保留完整的新材料并返回原发布诊断。每个提交的来源都有独立结果。

转换快照是显式保存的可读记录，搜索、正文、复制、收藏、导出与整理共用 SessionSource 和 SessionMessage。相同来源的新快照原子替换旧快照，不维护第二份拼接正文、迁移格式或双读回退。来源内容改变后重新出现可转换提示。删除转换记录只删除应用副本，原始 journal 仍由 Claude 管理。

会话及用量的来源提示通过 `useInformationSource` 接入标题栏 GlobalInformation，确认按当前提示身份生效；新问题仍可见，已确认提示在同一全局入口复查。确认和删除状态由[应用级来源生命周期](2026-10-23-information-source-lifecycle.md)拥有，不写浏览器或用户配置；转换入口的提示身份包含排序去重后的 conversionId 集合，新集合不继承旧集合的删除状态。提示正文与转换操作在全局面板的共享 ScrollArea 内完整阅读，警示不再挤占结果区。缓存重建提示继续保留其现有确认入口，确认均不改变统计事实或后端错误结果。[搜索生命周期与全局警示](../bug-fix/2026-10-23-session-search-lifecycle.md)拥有展示迁移和真实进度。

## Alternatives considered

- 直接给原 journal 补 sessionId 可以立即复用普通会话解析器，且无需应用副本；但事件日志不属于会话协议，改写会改变 Claude 的持久数据契约，因此不采用。
- 为 workflow 永久加入自动读取分支可以实时展示最新事件且无需显式转换；但用户要求一键完整转换，显式快照能确认保存的是哪一份完整材料，也能在原日志消失后继续阅读，因此选择独立且原子发布的应用记录。
- 隐藏全部缺失身份提示最省界面空间；但会同时掩盖真正不可读来源，因此只对明确识别的 workflow 建立转换入口，其余故障仍按原契约呈现。

## Consequences

- 两个页面可确认当前提示并重新查看，新提示不会被旧确认吞掉；缓存重建提示以本次重建时间区分新事件。
- 一次操作转换全部提交的 workflow 来源；相同源内容重复操作不重复产生记录，更新内容仍使用同一个记录身份。
- 每个成功来源保存全部 JSON 事件、顺序、原始时间及主会话关系；任一坏记录阻止该文件发布，失败逐项可见。
- 搜索、详情、复制、收藏、导出及删除解析同一转换记录；结果事件以助手消息支持既有收藏契约，其余事件作为工具记录。原始文件保持不变，用量不新增虚构调用。
- 用量直接消费同一原生来源扫描结果，不读取与它无关的应用转换副本；原生发现、来源身份和真实用量仍各有唯一所有者。
- 直接 API、命令注册、浏览器开发入口、夹具、README 和 DESIGN 随实现同步。回归夹具覆盖全部字段与重复事件、稳定消息身份、过期标识、写入变化、批量逐项结果、损坏副本、用量排除和仅删除副本。构建与自动化测试分别遵守用户授权；0.3.7 补修版已获得本地编译授权，回归测试仍需单独执行。

完整事件副本占用额外磁盘；转换时仍按既有单记录 32 MiB 边界处理，不以内存容纳整个来源。活跃 journal 可能持续变化，此时明确要求稍后重试而不发布部分内容。源码与静态检查不能替代桌面点击和真实运行验收。

## Verification

笔记结构与相对链接、git diff --check、受影响源文件行数检查通过。0.3.7 Windows 补修版通过前端类型检查、生产资源构建、Rust release 编译及 NSIS/WPF 安装器封装。安装器为 x64，产品版本 0.3.7、文件版本 0.3.7.0；内嵌安装引擎匹配本次构建，包内程序与编译结果只有 Tauri 正式 NSIS 类型标记的三个字节差异，包内更新日志与当前主文件一致。构建前后 1260 个输入文件哈希一致。

发布 CI 的 Linux 源码检查已通过 27 项前端测试与 656 项 Rust 测试。Windows 回归暴露直接哈希路径文本会因分隔符变化而无法匹配来源；路径身份归一化与原件移除后的副本重读由聚焦用例约束，最终跨平台结果以修复提交的发布 CI 为准。未进行安装或真实桌面交互验收，也未对用户现有日志执行转换。
