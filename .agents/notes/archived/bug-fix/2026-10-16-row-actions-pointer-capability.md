# Agent Note: 供应商行操作按输入能力保持可达

Status: implemented
Archived: 2026-10-22

## Problem

无条件隐藏空闲行的动作并禁用指针命中，依赖触摸浏览器模拟 hover 才能操作，违背触摸设备按钮常显的需求。已有三轨布局和 `.asb-row-action` 标记仍是正确的结构所有者。

## Decision

仅在主指针支持精确悬浮且没有粗指针时隐藏空闲行操作；触摸设备及带触摸屏的混合设备保持常显。继续复用同一套动作标记、占位、Tab 顺序、220ms 透明度过渡及减少动态效果规则，不引入设备状态或事件监听。

`ProviderRowShell` 的排序手柄和动作轨、`UsageSummaryView` 的刷新按钮仍声明 `.asb-row-action`；显隐只归 `base/provider-list.css`，不匹配摘要内部 DOM 或客户端专属结构。默认过渡以零特异度 `:where` 声明，排序手柄自有按压过渡保留 opacity 项。名称、模型、地址、已应用和错误始终可见，详情面板内操作不受影响。保留原三轨布局与占位，不增加 React 状态、事件监听或重复按钮。

相关笔记审计：[三轨布局](../architecture/2026-10-13-provider-row-three-rails.md)继续拥有几何，与本决定部分重叠并互链；[扩展操作显性化](2026-09-24-extension-visibility-and-focus.md)属于扩展领域，不改变。旧供应商悬浮笔记的无条件触摸决定被本篇完全取代，保留历史快照供复盘。

## Alternatives considered

- 无条件 hover/focus 规则最简，也能让部分触摸浏览器在点按后显形；但模拟悬浮并非触摸操作契约，首次操作不可发现，不能满足常显要求。
- 只检测主指针精度可让混合设备的鼠标使用者减少噪声；但切换到触摸屏时仍隐藏操作，因此有粗指针的机器整体采用常显。

## Verification

共享动作轨、排序手柄和刷新按钮只在精确悬浮且无粗指针环境收起；触摸常显、键盘聚焦显形、占位及减少动态效果保持。

## Consequences

混合输入设备使用鼠标时也常显，是保证触摸可发现性的明确取舍。按项目规则不运行编译和自动化测试，桌面输入行为未验收。
